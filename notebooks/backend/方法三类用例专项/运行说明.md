# 测试报告运行说明

## 1. 报告与测试范围

打开 [测试报告.ipynb](测试报告.ipynb) 可查看已保存的代码、实际结果和解析；[测试报告.html](测试报告.html) 可下载后直接用浏览器阅读。原始数据默认折叠，可点击展开。运行前可先阅读报告，无需连接服务器。

重新运行时，唯一被测地址为 `https://8.141.96.122:6644/api/v1`。报告选取17个核心Service方法，设计126个用例；每个方法都有正常、合法边界和异常输入，用等价类划分与边界值分析设计。通过HTTP验证后端，不启动本地后端或数据库。

## 2. 安装依赖

准备 Python 3.11 或以上版本；本次验证环境为 Python 3.14.6。克隆仓库的 `test` 分支后，进入报告目录：

```sh
git clone --branch test --single-branch https://github.com/AStar678/software_test_practice.git
cd software_test_practice/notebooks/backend/方法三类用例专项
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

Windows PowerShell 创建环境后，使用下面的命令激活，再安装相同依赖：

```powershell
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

截图默认使用 macOS 上已安装的 Microsoft Edge。其他环境需在当前虚拟环境中安装用于静态报告截图的 Chromium：

```sh
python -m playwright install chromium
```

截图只打开本次生成的本地HTML报告。

## 3. 在 Jupyter 中运行

在报告目录执行：

```sh
python -m jupyterlab --notebook-dir=. 测试报告.ipynb
```

macOS/Linux也可在此目录运行 `bash 启动Jupyter.sh`，脚本会创建 `.venv`、安装依赖并打开报告。

打开报告后，选择 **重启内核并运行全部单元格**。不要仅运行中间章节：各章依赖准备阶段的共享会话和设计清单。修改用例后同样从新内核完整运行，每次生成独立目录，已有同名目录会拒绝覆盖。

按隐藏输入提示提供：

1. 六个员工账号（`13800000001`–`13800000006`）的共同应用密码。
2. 独立管理员应用密码；留空时沿用员工密码，管理员账号名默认 `admin`。
3. 可选的覆盖率采集用SSH密码；留空时执行全部接口用例，本次Java覆盖率明确显示“未采集”，不会沿用已保存的覆盖率数值。

密码不写入Notebook代码格，也不保存到仓库。服务器SSH密码与应用密码属于不同凭据。若账号或权限发生变化，应按实际用例失败信息核对，不在脚本中重置真实账号。

自动执行可通过进程环境提供 `PANDORA_CLOUD_PASSWORD`、`PANDORA_CLOUD_ADMIN_PASSWORD` 和可选的 `PANDORA_SSH_PASSWORD`；管理员账号名可用 `PANDORA_CLOUD_ADMIN_NAME` 设置。不要提交包含这些变量实际值的文件。

## 4. 在 VS Code 中运行

安装 Python 和 Jupyter 扩展，打开本报告目录。打开 `测试报告.ipynb`，在“选择内核”中选此目录 `.venv/bin/python`（Windows为 `.venv\Scripts\python.exe`），然后重启内核并全部运行。看到密码框时按上一节输入。

每章依次显示功能与输入约束、设计表、测试代码、实际数据对照和结论解析；运行配置与原始输出可展开查看。

## 5. 可选：重新采集Java代码覆盖率

JaCoCo采集需有当前服务器的SSH管理权限，并在本机 `~/.ssh/known_hosts` 中已验证服务器主机密钥。首次连接应通过正常SSH流程核实指纹；脚本拒绝未知主机密钥。

提供SSH隐藏输入后，脚本会临时为 `pandora-web-version.service` 加载 JaCoCo 0.8.13，短暂重启6644实例；agent只监听 `127.0.0.1:6300`。服务就绪后重置启动阶段数据，测试结束后导出执行数据，再使用同一个部署JAR的类文件生成报告。采集结束会移除本次临时启动配置、重启恢复服务并检查健康状态。

JaCoCo agent/CLI已随 `tools/jacoco/` 提供，生成报告使用服务器上的Java，无需本机JDK。当前采集器校验固定服务名、Java路径及部署包位置；环境不符时会停止，应先核对服务器配置。

指标分为全部 `cn.pandora` 应用类的覆盖率与17个指定入口方法的精确签名统计。采集窗口在共享服务器上，可能含后台任务或其他请求，不能把每个探针都严格归因于pytest。126项断言通过不等于全部代码已覆盖。

## 6. 结果和故障处理

每次结果写入 `runs/matrix6644-时间-随机值/`：

- `M01`–`M17`：对应方法的 `test_method.py`、`pytest.log`、`pytest.xml`、`cases.jsonl`、`requests.jsonl`、三类覆盖、实际数据分析和清理清单。
- `auth/`：本次共享会话的准备和退出请求，认证信息已脱敏。
- `结论.json`：本次总体状态。只有全部用例通过、每个方法三类均达标、事项清理完成且共享会话退出成功才为PASS。
- `coverage/`：采集时生成的 `cloud.exec`、JaCoCo HTML/XML/CSV、部署包校验值、恢复记录和截图。HTML入口为 `coverage/html/index.html`。

仓库保存的证据目录为 `runs/matrix6644-20261120-001908-614fac/`，其结果为126通过、0失败、0跳过；行覆盖率27.65%、分支覆盖率23.48%。这些数值属于该轮记录，重新运行后以新目录中的实际结果为准。

无SSH凭据时依然能执行全部接口用例，覆盖率显示未采集是预期行为。无Chromium/Edge时最后的截图步骤会报浏览器缺失；安装浏览器后从新内核完整运行。

写入仅涉及本次个人事项，按创建ID清理；审计和幂等历史可能保留。若手动中断或网络中断，按对应方法的 `created-items.json` 与 `write-intents.json` 核查，不按日期或通配符删除现有数据。若覆盖采集被意外中断，应核对本次 `coverage/provenance.json` 的恢复状态及服务器临时配置路径，恢复正常后再继续。
