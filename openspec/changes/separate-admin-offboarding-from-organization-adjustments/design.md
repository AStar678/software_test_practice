## Context

现有 `admin.html` 同时提供员工离职弹窗和顶层责任盘点页；前者调用员工离职接口，后者写入 `planDraft`。后端 `EmployeeOffboardings` 构造受限计划，但仍经由可接受生命周期字段的 `OrganizationPlans.save`。当前责任清单只查申请人或审核人关联，并把内部类型和 ID 交给界面；停用校验会在仍挂着未完成任务时一律拒绝。变更动机见 `proposal.md`，可验收行为见增量规范。

## Goals / Non-Goals

**Goals:** 把生命周期指令从组织调整的公开契约移出，复用公司锁、组织不变量、版本校验和历史机制；让管理员在真正提交前看清交接与待审的处理结果；身份证搜索不能把敏感值带入地址栏、日志或普通目录。

**Non-Goals:** 不新增可恢复的临时停职、不改固定创始人身份、不授予管理员普通交接/审批权、不扩大普通员工的候选范围，不修改历史数据或正式库演示内容。

## Decisions

1. **分开公开命令，共用组织校验。** 组织调整写接口只接受结构字段，未知的旧生命周期字段整单拒绝；下线独立接管写入口，保留离职专用清单和历史读取。独立入职、离职可调用内部共享的组织写入基础，不通过公开的组织调整命令互相模拟。单位负责人离职仍由向导选择合法继任；涉及调岗或单位组合变更时，先单独保存组织调整，再回到员工页办理离职。仅隐藏旧页面会留下绕过流程的写入口，因此不选。

2. **单员工导向页负责确认，不保存到结构草稿。** 员工列表点击办理离职后，清单返回已绑定员工的任务、岗位和申请及版本。无事项时直接确认，有事项时在离职交接页按执行交接、管理权、必要岗位继任、待审处理组织表单；可取消或返回，不落结构草稿。选人复用管理端目录的最小投影，按姓名筛选，结果带部门、团队且保留当前选择；不携带证件字段，也不把两个任务角色的选项合成一个。旧的两个入口和步骤文案不再保留。

3. **为离职增加受限的执行指派更新。** 清单及提交按现有有效版本和有序负责人核对，接手选项表达「移除本人」或「选接手人」，后端复验至少一位剩余有效员工。替换时在原位置接入未在列表的接手人，其余有效负责人相对顺序不变；若选人已经是负责人，只移除离职人且不重复添加。使用既有任务版本、历史和通知机制写入，只变指派，无权夹带任务内容或替代普通员工的申请审批。已完成任务留历史指派，软删除任务不进入活跃交接。继续要求管理员先让员工在另一端完成全部普通交接，会让离职页无法履行已确认的单一流程，因此不选。

4. **按关联角色处理申请，而不是按任务接管人处理。** 清单以任务名称和中文类型投影申请，区分本人提交、本人审批、他人提案中的拟任负责人，重复关联用明确结果而非重复处理。最终确认绑定本人待撤销申请的 ID 与版本集合，服务端不扩大确认范围；集合、申请状态、截止或任务版本变化时刷新重试。公司锁内先核对快照和最终组织，终结经确认的本人有效申请并释放其冻结，再应用任务执行安排、管理权、必要继任及账号停用，按最终组织改派和重验他人申请。仍有效但无法改派、拟任负责人失效或因执行交接与有效任务版本冲突的他人申请提示原业务方处理，不替换提案、隐式撤销或跳过冻结。撤销用现有终态并记录「因离职撤销」来源，不用自然过期或通过状态。所有结果、历史、通知及会话撤销同事务提交。

5. **员工搜索和演示数据分别控制证件边界。** 使用管理员专用、请求体传输的目录搜索路径承载身份证号，不将号码置入 URL；服务端按公司与规范化完整号码精确查找，与既有筛选取交集，返回相同的脱敏列表与总数。请求体及判定值不记入日志、审计或错误。普通搜索保留原有姓名、部门、手机号匹配，不增加证件尾号模糊搜索。演示种子用可复现、唯一、非真实地区号段且满足现行校验的合成数据，仅在显式新建或受控重建时写入管理员专用证件存储；不使用业务库迁移回填或普通启动覆盖。展示职位只改种子名称，保留稳定标识。

6. **用操作和状态替代重复文案。** 搜索独占一行，窄宽窗口用可换行的字段说明或标签防止截断；保留现有可组合筛选和匹配数量。待审行显示任务名、中文申请类型、撤销/改派/阻断结果；组标题、条数和确认框承担信息表达。组织异常组件仅在有阻断时显示；公司信息仍保留数量、上限和排序控件，不再解释排序控件已表达的行为。

## Risks / Trade-offs

- 确认后另一人批准或新提交申请 → 以公司锁及版本/确认集合核验拒绝过时提交，保留未提交表单并提示刷新，不把刚出现的申请纳入批量撤销。
- 任务身份、执行权限与审批路由互相独立 → 用不同写入和审计记录验证；普通业务操作仍走既有审核规则，不让离职命令成为通用业务写入口。
- 旧前端提交组织草稿的生命周期字段 → 同步部署管理页面及后端；旧请求整单拒绝并提示刷新，不以兼容模式静默执行。
- 完整证件号可用于精确查询 → 只允许当前公司独立管理员查询，避免 URL、日志和响应泄露；无匹配与未授权有不同状态。

## Migration Plan

1. 在上一轮管理端实现之上部署离职编排及受限结构命令，再同步发布管理端页面和搜索；保留旧历史和接管关系，不对既有任务重写负责人。
2. 使用当前种子在显式选定的演示库验证职位与证件样本；保留模式和正式业务库不回填。
3. 旧版管理端与新契约不兼容，回滚时管理端页面、服务和路由成组回滚。已经办结的真实离职、申请和接管记录保留，不以回滚恢复账号或假造审批。
4. 先验证并归档上一轮管理端 change，使其员工目录、离职和文案要求进入主规；再同步或归档本 change，避免同名要求合并顺序颠倒。
