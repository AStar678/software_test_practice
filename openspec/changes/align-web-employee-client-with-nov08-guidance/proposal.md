## Why

下次检查改用根目录员工 Web，现有页面仍保留横向事项日历、卡片内滚动、单月人员日程和下拉通知筛选，未满足 [2026-11-08 更改指导](../../../docs/requirements/潘多拉-更改指导-2026-11-08.md)。已归档的 `2026-11-09-prepare-employee-client-contracts-and-business-upgrade`（A）提供共享契约及过渡 Web，但不代表完整新交互或四角色演示体验已交付，需要本 change 补齐检查使用的 Web。

## What Changes

- 首页上方事件纪、任务看板各保留少量预览，点击卡片先开完整清单，取消内部纵向滚动；每日事项改为独立纵向连续月历，绘制跨日事项条、名称、三态颜色及命中日清单。
- 复用已有日期范围事项、全局任务表单、独立表单置顶、日志填充源、节假日、入职时长及授权下属联系方式契约。已有表单置顶和入职时长以回归为主，不重新实现服务端业务。
- 在日志创建/编辑中按所属日主动追加事项和任务名称；卡片及列表统一以所属日显示、排序，真实创建时间和首次 24 小时冻结不变。
- 公司月/日视图展示后端年度节假日名称与休/班；补手机长按、单次震动能力调用、二维日期命中、跨月边缘自动滚动及日视图拖动/键盘/确认的当天边界。
- 隐藏员工资料组织身份，统一真实“部门 ▸ 团队 ▸ 职位”展示，完善下属电话/邮箱空态；人员日程支持连续跨月、固定清单操作及嵌套返回恢复。
- 通知改为六类型标签、已读三段按钮和单图标精简/完整切换，固定筛选区并保留动态分类、全量筛选、全局未读与历史只读规则。
- 修复动画演示种子的入职日期、两种独立置顶、本人负责任务分布、父子任务链和日内/逾期场景；通过显式目标库准备近期可操作数据，保持幂等、不覆盖业务修改及极限夹具隔离。
- 用 Web 增量规格明确替换冲突的旧横向日历/数量标记/卡片内滚动规则，更新对应自动化与资源交付核对。现有业务权限、审核、版本、幂等和既有数据兼容继续有效。

## Capabilities

### New Capabilities

无。复用现有能力边界。

### Modified Capabilities

- `pandora-requirements-aligned-prototype`：首页及事项月历、日志日期和填充、资料路径、人员连续日程、通知布局、手机任务拖动与日内边界、四角色演示及本次 Web 验收边界。
- `china-holiday-calendar`：承接已有年度数据契约到 Web 月/日标识，移除最终客户端展示只由未来 Flutter 承担的限制，不改变缓存及任务时间语义。

## Impact

- 实现范围：根目录员工 HTML/JS/CSS 与 `backend/` 内确有必要的服务修复、演示数据、检查脚本和打包资源配置；不修改 `flutter/`、`android/`、`android-shell/`，不构建 APK、不新增桥接或系统推送、不重做 PC 管理端。
- 重点入口：`潘多拉-每日事项.js/.css`、`潘多拉-工作区接入.js`、`潘多拉-日程视图.js`、`潘多拉-个人资料.js`、`潘多拉-任务接入.js`、相关主题/日历 CSS；`DemoSeed.java`、`prepare_demo.py`、相关浏览器/契约检查、`backend/pom.xml` 与资源版本。
- API/数据库：优先消费 A 已交付契约，不预设新增接口或结构迁移；确认的后端缺陷才最小修复，保持 Web/Flutter 共享兼容，不改历史迁移或归档 A。
- Web 手机触摸与桌面均在验收范围；震动使用浏览器已有能力并记录实际设备支持结果，无能力时保留视觉反馈，不把桌面模拟或 API 调用成功当作真机震动/旧套壳验收。
- 用户已明确本次优先 Web、暂缓 Flutter；保留现有 Flutter change 原状，后续恢复时按届时主规格重新协调其共享 delta，本次不宣称完成其任务或移动端交付。
