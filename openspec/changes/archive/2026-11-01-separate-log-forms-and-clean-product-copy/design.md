## Context

动机见 proposal.md。员工页由根目录 HTML 顺序加载原生 JS/CSS，日志实际表单在 `潘多拉-工作区接入.js` 覆盖原型实现；PC 管理端为根目录 `admin.html` 内联页面/脚本。不存在需要改动的 Android 原生界面或新增客户端交付。

当前 `openLogForm(id,date)` 以是否有 id 选择数据，但两种模式共用 `logFormView`，编辑仍构造三天日期列表并禁用 `lf-date`。`check_log_backfill_entry_browser.js` 也把该 disabled select 当作编辑成功条件。`潘多拉-标签评论.js` 的 tagSelectHTML 注入标签维护规则长说明，日志表单注入归属/只读规则段落；工作区分析页直接显示内部 method 值作为兜底。这些是已定位的产品可见问题。

现有首次24小时冻结、同日唯一、作者写权、关联任务授权和幂等/API由服务端裁决；个人日志 change 已归档，当前列表只列本人并直接点卡片进详情。其他活跃 change 负责近三天创建入口、通知、排期和下属工作区，本 change 不重写这些合同。

## Goals / Non-Goals

**Goals:** 将创建和编辑的页面组织、草稿身份与提交目标分开；保留共享字段基础组件及原权限校验；让日期只读展示仍与标签对齐；清理实际可达界面的冗余说明而保留决策必需信息。

**Non-Goals:** 不改数据库、日志日期/首次创建时间/冻结规则，不扩展他人日志或任务编辑权，不删除 AI 地图或改分析算法，不过滤用户正文或历史，不改归档文件，不部署或做手机真机测试。

## Decisions

### 1. 两个独立界面，基础组件可共享

保留明确的创建与编辑入口兼容现有委托，但分别构造 create/edit 视图及草稿模式，重建、子页返回和保存都按显式模式与目标 ID 校验，不再由一个模板仅改标题/disabled 属性。可以共享标签、正文、任务关联及错误控件的小函数；这些组件不决定日期候选、模式切换或提交目标。

创建查询公司近三天的缺失日期，草稿不持有已有日志 ID；编辑先以真实 ID 读取可编辑记录，日期使用可读的非交互展示字段，完全不构造日期候选。编辑日期不发写入请求，服务端仍拒绝伪造改期；不通过隐藏字段放宽业务约束。

保存路径沿用既有创建/更新接口和幂等/ETag。创建抢占冲突、网络失败、版本冲突及冻结都保留当前模式的草稿，给出简短结果，不自动切换到另一个模式。关联任务不可见时按原关系保留/主动清除规则处理，不能因拆表单静默丢关系。真实首次创建时间与删除重建冻结沿用原逻辑。

### 2. 不用禁用下拉框来承载编辑日期

`p-log-meta` 保留两列/窄屏单列布局，以字段容器而非同为 select 作为对齐基础；编辑日期展示字段与标签控件的高度、标题间距和边缘一致。320/390/1440分别测量创建和编辑，长正文滚动、选任务子页返回、保存/关闭及焦点可达都保留。

更新 `check_log_backfill_entry_browser.js` 中“编辑必须 lf-date.disabled”的旧实现假设，改验明确目标、不可改日期、无创建候选和真实更新原 ID；继续保留原脚本的创建三天、个人列表、评论及关联任务嵌套动作断言，不能为了通过新布局删掉行为检查。

### 3. 按可达界面与信息用途清理文案

不做全库关键词删除。员工入口以 `潘多拉-交互原型.html` 的实际脚本链为准；管理端以 `admin.html` 及其实际加载资源为准。逐项区分静态解释、必要状态/提示和业务内容，在实施记录中保留检查入口及去留原因。

| 界面/来源 | 已定位内容及处理 |
| --- | --- |
| 标签选择与维护：`潘多拉-标签评论.js` | 删除标签维护/多单选/删除规则长说明和重复维护说明；保留标签名称、选择能力、已删除状态及实际维护权限 |
| 日志创建/编辑：`潘多拉-工作区接入.js` | 删除重复归属与上级只读段落；保留必要字段、保存错误及当前冻结状态 |
| 任务详情/日程/表单：任务接入、日程视图、任务表单模块 | 清理静态开发/规则说明；保留真实待审、失权、历史只读、审核原因和本轮月/日拖动的简短必要操作反馈 |
| 分析：工作区接入模块 | 方法代码映射为简短中文来源；保留真实范围、更新时间、方法说明，不声称外部模型生成 |
| 登录/账号/个人资料：API、原型、个人资料模块 | 清理原型解释与重复规则段落，保留管理员维护字段等必要简短提示、密码校验和失败反馈 |
| PC 管理端：`admin.html` | 同步审查实际人员/组织/公司信息/历史/账号流程，移除开发解释，保留原子保存约束、危险确认和可执行校验提示 |

保留上述真实业务信息是对原规格的兼容，不以“删除所有提示”为验收。原型注释、文档、历史迁移及真实业务内容不进入产品静态文案替换集合；不在运行时按“原型/标签”等词过滤用户数据。原生端及历史未加载副本不在本次交付范围。

### 4. 与其他 change 分工

`refine-task-creation-notifications-and-review-routing` 完整替换 Personal work logs 的旧自动进入编辑条款，并负责近三天入口；本 change 增加独立界面合同，不再完整 MODIFIED 同一条款，避免归档时互相覆盖。已归档日志页的 self-only、日期/标签对齐和直接点卡片继续适用；这次改的是编辑日期的呈现方式，不减少原字段。

通知去重复、月历日级显示和下属无拖动由各自活跃 change 实施。公共标签 helper 的文案修改与 A 的任务多标签控件协调，保留日志单选和任务多选。基础任务字段“可见即可编辑”暂缓，与本 change 无关。

## Risks / Trade-offs

- [原共享模板/委托在子页返回时复用错误模式] → 用创建缺失日期与显式编辑 ID 两组真实操作验证草稿、嵌套任务选择、关闭及失败重试，不只断言标题。
- [旧测试把 disabled select 写死] → 改为日期不可改、无创建候选及更新同一记录的行为断言，同时保留对齐测量。
- [清理说明删除必要业务信息] → 根据表中用途逐项审查待审/冻结/失权、确认和分析来源，验证对应状态仍可理解且动作可用。
- [全局替换损坏业务内容] → 仅修改静态模板/安全显示映射，用含同词的真实正文和意见验证原样保留，不迁移/批量更新数据库。

## Migration Plan

无迁移。先拆分日志界面与模式，再更新共享布局及静态文案，运行相关日志/API/真实浏览器回归，最后交叉检查员工和PC管理端可达状态并记录证据。由后续 apply 更新 implementation-notes.md，独立 verify 通过后才归档；本轮只完成规划，不复用其他 change 的历史 PASS。云端发布另行处理。
