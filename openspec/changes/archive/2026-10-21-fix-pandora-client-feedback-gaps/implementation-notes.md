## Verification Reminders

- `mvn package` while a backend is running replaces the jar under the live classloader and makes static assets return 404. Restart the service after every package before judging browser/assets behavior. This was observed once and fixed by restarting; it is not an application regression.
- The task-form counts and sorting are intentionally client-side over the complete authorized set (`/tasks` pages). More than 200 effective rows were verified; very large datasets may need the deferred server-side optimization.
- The table depends on `P.data.me.organizationTimeZone` from `/me`. If it is missing/invalid the page must stay in the error/retry state; do not replace it with `Intl.DateTimeFormat().resolvedOptions().timeZone`.
- Timezone-sensitive edge cases already covered: all-day start/due inclusive, timed task ending exactly at company midnight belongs to the next date for filtering, closed date intersection at both boundaries, invalid range keeps the last valid result.
- Sort tie behavior is intentionally `id` ascending even in descending order. Pinned state is deliberately ignored by the table but still affects only the owner's calendar.
- New pages that cache authorized data must register a `P.sessionReset` hook; otherwise logout/account switches can leak the previous account's rows or filters. The task form already does this.
- `run_check_isolated.sh` waits for the seeded `users` table because Tomcat accepts `/health` before `ApplicationRunner`s finish. Do not start checks on `/health` alone, and do not point these checks at the user's current database.
- The notification/historical fixtures require `CHECK_WORKER=true`; without the worker, `run-once` does not dispatch events and `check_notification_browser.js` fails on missing fixtures rather than on UI behavior.
- Non-table calendar coverage remains in the updated `check_home_calendar_browser.js`; its old search/count assertions were replaced by own-only and no-search assertions. Do not re-add calendar search/count checks.
- Detail visibility uses the backend every time. `403/404` handling is exercised through an employee whose effective owners were changed away; re-opening the old task triggers row discard + re-query.
- Remaining deferred scope: system push (DEV-029) and A-25 real-device/keyboard verification, as recorded by the V3 baseline. Browser evidence here does not replace real-device evidence.
- Evidence in `audit/2026-10-21/` is apply-stage evidence, not an independent e13 verdict. `verification.md` was not created or modified by this apply session.
