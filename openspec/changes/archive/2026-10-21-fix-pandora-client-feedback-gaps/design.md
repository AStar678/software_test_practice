## Context

动机与范围见 proposal.md。已检查 V3、差异分析及实际加载链：基础原型 → API → 任务接入 → 工作区 → 日程 → 个人资料。后加载脚本会覆盖同名函数，因此不能只修改基础 HTML 或旧渲染器。

已观察到：

- `潘多拉-api.js` 的私有 `all()` 以每页 100 条读取到游标结束，`P.reload` 保存全部授权任务至 `TASKS`；`P.mapTask` 保留 `raw`、原创建者、有序负责人、执行状态和待审类型。
- `TaskService.list` 先排除无有效版本任务、按 `Access.canSeeTask` 鉴权，再分页；`taskView/snapshotView` 已输出规定字段及安全人员摘要，并裁剪无权父任务。无需重写授权或增加列表查询参数。
- 当前 `visibleTasks` 被两层接入覆盖为全量副本；`viewTasks` 未检查负责人。日程月格、全天区、时间轴、日清单共同依赖 `viewTasks/dayTasks`。
- `rangeSummary` 使用互斥 `taskKind`，与 V3 的“创建和负责可重叠”冲突；`scheduleSearch` 只取 20 条，不适合作为新表格的全量搜索。
- `/me` 当前没有公司时区字段，定时任务没有 `startDate/dueDate`；直接按设备时区筛选会偏移业务日期。
- Maven 按静态资源白名单打包，新增脚本/样式必须登记。已有 browser 脚本包含旧日历搜索和计数断言，需按新契约更新；历史归档与 audit 证据不改写。

主规格中 Calendar task views 的日历搜索、三类互斥计数和全授权范围将被 delta 显式替换；Strict prototype scope 改为 V3。账户、手机号、通知及日志已有相应规格，本轮只做回归。

## Goals / Non-Goals

**Goals:** 分离完整授权任务与本人日历投影；建立唯一的表单结果计算管线，保证表格、搜索、排序、统计、分页一致；兼容现有详情、写入和认证；在现有构建服务中可验证。

**Non-Goals:** 不引入表格框架、独立任务账本、Excel 导入导出、公式或单元格直接编辑；不重构任务审核/授权/提醒，不增加第六主导航，不把本轮验收扩展为已延期的系统推送和真机专项。

## Decisions

### 1. 用完整授权数据在前端计算表单结果

复用 `all('/tasks')`，提取可复用的任务读取/提交函数供初始 `P.reload` 和任务页刷新使用。完整读取后一次性替换 `P.data.rawTasks`、`TASKS`、任务 ETag 及安全人员摘要；不得逐页向用户发布“完整”统计。保留现有 `epoch`，并为任务读取设置递增请求序号，初始加载和单独刷新共享提交判定，旧请求不得覆盖新账号/新刷新。

管线固定为：已成功加载的授权有效任务 → 按 ID 去重 → 关系 AND 完成 AND 名称 AND 日期 → 统计与全量排序 → 当前页切片。表格默认每页 50 条，前后页导航展示范围及总数；改条件或排序回第一页，刷新后页号超界则钳制到有效页。总数、排序永远不基于当前切片。

备选为扩展服务端关系、完成、排序、汇总参数。本项目本来已为工作区全量读取任务，前端方案可避免重复查询语义和后端接口扩张；大数据服务端分页优化留待实测有瓶颈时另提变更。

### 2. 任务表单是视图内部二级页面

新增 `潘多拉-任务表单.js` 与 `潘多拉-任务表单.css`，在日程脚本之后加载。以 `state.viewPage`（calendar/table）分派同一个 `page-view` 的渲染，底部仍选中“视图”；不使用任务详情共用 sheet 充当表格，避免详情/关联弹层抢占二级页。

进入表单记录日历模式、锚定日期、侧栏状态；返回不改这些值。表格与条件状态仅放会话内存，同账号在其他主页面往返保留表单条件，点击“返回日历”明确返回原上下文。退出、失效或切换账号清空表单条件、翻页、缓存、请求及返回上下文。

使用语义化 table，表头固定，任务名称首列固定；表格在自身容器横向/纵向滚动，筛选、统计、返回和底部导航可达。列头按钮显示方向及 `aria-sort`。行内名称按钮打开原任务详情；关闭详情保留筛选、页码和滚动，业务写入成功后刷新任务并重算。长说明、标准和备注只预览，详情查看全文；所有文本 HTML 转义。

### 3. 关系、完成、日期和排序采用明确规则

关系分别由有效负责人包含当前账号、`originalCreatorId` 等于当前账号判断；“仅可见”为两者均否，原 `taskKind` 不作为表格关系依据。表格可显示“负责”“创建”两个标记；统计逐项判断，不能将三个关系数相加当总数。

完成仅看有效 `executionState === 'done'`，`pendingKind === 'complete'` 仍是未完成。所有已有有效版的待审任务展示有效字段和待审类型/冻结，不显示提议 diff。逾期使用有效截止时刻与当前时刻比较，已完成排除；全天比较服务端 `raw.dueAt`，不使用本地日期午夜代替下班时刻。

搜索只对任务名称做 trim 后不区分大小写的包含匹配，最大 200 字符，按约 220ms 防抖；保留输入焦点，禁止从旧日历搜索请求取前 20 条代替完整结果。

日期默认两端为空，支持单端范围，结束早于开始时显示校验错误并保留上一次有效结果。复用既有 `TaskService.list` 的闭合日期相交语义：任务开始日期 <= 所选结束日期，任务截止日期 >= 所选开始日期。全天直接使用原日期；定时任务在公司时区提取首尾日期（截止为午夜也按其所属日期判断）；这与日历绘制的时刻区间切片属于不同用途，不改日历午夜无零长度副本规则。显示及筛选统一使用公司时区，设备时区不改变表单结果。

为此在 `WorkspaceService.me` 的组织联表读取中增加只读 `organizationTimeZone`，取组织 `time_zone`，不回传其他组织/人员敏感字段。是向后兼容字段，不改变认证、手机号和资料权限。前端用 `Intl.DateTimeFormat(..., {timeZone})` 提取定时任务日期并格式化，缺失/非法时区显示加载错误，不能悄悄使用设备时区。

排序初始为开始时间升序，点击同列切换升/降，换列先升序。支持名称（中文 locale 比较）、创建时间、开始、截止、紧急程度、执行状态；紧急/高/中/低、待开始/进行中/已完成为升序枚举顺序。时间用实际瞬时值排序，全天展示为日期；主键比较相同时一律按任务 ID 升序，降序只反转主列。置顶不参与表格排序。

### 4. 日历只收窄本地展示，权限仍由后端决定

将 `viewTasks(account)` 改为从完整正常任务中筛选有效 `assigneeIds` 包含本人；月、周、日、全天、跨日条、当日展开清单都走该函数。保留 `visibleTasks/TASKS` 全量，不修改 `Access.canSeeTask` 或 `/tasks` 默认授权范围，确保详情、导图、日志关联与 AI 不因日历收窄而漏数据。

移除日历 `scheduleSearch` 输入/结果、计时器/监听与 `rangeSummary` 渲染和旧测试导出，收敛为日期导航、模式、本人申请、创建和表单入口。月格真实隐藏数量与 `+N` 继续基于本人任务计算，不误删。日历任务保留负责关系的文字/图形标记与稳定配色，个人置顶与真实排期继续生效。

### 5. 权限变化和失败不伪装为空结果

进入表单和主动刷新重新完整加载授权任务；成功写入、审批或返回日历时刷新有效任务以反映负责人变化，应用从后台恢复也重新查询。刷新进行中遮蔽旧行与旧计数，失败显示明确错误及重试，不能把部分分页当成成功或显示为“没有任务”。无授权任务与有任务但筛选无结果用不同空态，均可清空条件。

详情始终重新请求后端；403/404 后立即废弃旧行、重查授权集，不得用缓存继续展示或操作。仅通知历史只读详情不通过 `P.upsertTask` 混入正常表格。没有实时推送的跨客户端权限变化，在进入、刷新、恢复及业务操作这些查询点反映，不承诺离线页面即时更新。

### 6. 其余反馈保留实现并建立新证据

复用现有 chapter11 浏览器、手机号矩阵、账号生命周期和管理端检查，验收 A-17/A-19/A-04/A-01/A-28；失败则在原权限边界内修复。`P.reload` 管理员提示改为 `/admin.html`，相关当前实施说明同步 PC Web 定位。日志、通知、手机号无需因本轮反馈重新设计。

## Risks / Trade-offs

- [全量读取占用内存且初次请求较慢] → 沿用当前加载架构，至少用超过两页 API 数据验证，无静默截断；性能问题依据实测另行服务端优化。
- [多页读取非数据库快照，并发新增/移除可能改变偏移] → 一次加载按 ID 去重并完整重读，不逐页显示统计；详情和写操作重新鉴权；本轮不承诺跨请求事务快照。
- [覆盖链导致新页面被日程重绘覆盖] → 统一渲染分派，在加载链最后接入；从真实构建服务验证五页切换、详情返回及 ResizeObserver 不覆写表格。
- [新时区字段或公共加载器影响旧调用] → 只添加字段并保留 `/tasks` 响应，增加时区和刷新竞态检查，复用账户/隐私回归。
- [旧日历脚本断言仍使用三类任务和日历搜索] → 只更新受本次契约影响的断言，保留跨日、并发、置顶及导航覆盖；历史归档 PASS 不改写。
- [桌面浏览器无法证明真机键盘/推送] → 本次记录桌面和窄屏浏览器证据，延期项保留明确说明。

## Migration Plan

1. 在隔离数据库/测试组织准备关系、状态、授权和超过 200 条的已发布任务样本；不恢复或覆盖用户当前数据库。
2. 完成时区字段、任务数据刷新与表单模块，再接入日历投影和搜索/计数迁移；登记静态资源并刷新缓存版本。
3. 运行当前单测及对应 HTTP/浏览器验收，验证构建后资源通过 HTTP 可达，保存本次基线、命令、结果和截图；同步当前交付说明。
4. 本变更不迁移数据库；需要回退时整体回退本变更的前后端代码并重新打包，不能只回退 HTML 留下旧资源组合。本轮仅建立规划，不执行部署或回退。
