## Goals / Non-Goals

**Goals:**

- 通过统一服务端裁决让候选、预览、提交、审核、有效版、列表和消息一致，复用现有事务、ETag 与幂等机制。
- 新增持久模型时保持公司隔离、原身份和历史，迁移可在隔离副本演练。
- 保留未冲突的查询和权限规则，以 25 项映射支持独立 e13 验证。
- 将 Web/管理端及配套后端作为本 change 的完整交付范围，记录共用后端兼容影响和范围外套壳交接事项。

**Non-Goals:**

- 不重写前端框架、替换数据库或新增外部服务；不把员工 Web 变成管理控制台。
- 不修改 `android-shell/` 或 `android/`，不执行 Android 资源同步、导航/桥接/键盘窗口适配、APK 构建签名、覆盖升级及 WebView/设备验收。上述工作由其他人员另行负责，非本 change 的交付前置条件；共用后端规则无法按客户端隔离，仍须记录兼容影响。
- 不据未知新 PRD 外推需求，不以本次文档生成、自动化浏览器或演示数据充当产品/真机验收。

## Decisions

### 1. 在增量规格中显式替换冲突，保留未覆盖业务

修改现有 requirement 的完整块，替换旧周视图/整周滑动、固定月格、全角色默认本人、受限创建派发、创建负责人路线及午夜冻结行为；通知撤回的受限上级只读例外一并明确。当前 OpenSpec 校验要求保留已有场景名称，因此历史名称继续作为稳定标识，其 WHEN/THEN 更新为本次行为，不因旧名称恢复旧要求。非创建路由在规格内完整描述，不要求实施者另从 V3 推断。其余未变要求和表单完整结果集管线继续保留。

相比另建一套 Web 规格，该方案避免同一 capability 存在互相冲突的规则；本轮仅写 delta，不改主规格或历史 PRD。

### 2. 使用独立的手机号认证键，不把号码变成公开 username

保留员工 ID、密码摘要和现有公开 username；增加规范化的员工手机号登录键/索引，认证只对员工按该键查询，管理员保持原账号登录。在现有无公司选择的登录契约下，员工认证键在全部可登录员工间唯一；不新增多公司选租户流程，冲突返回明确反馈。

沿用现有手机号允许的格式，统一去除展示分隔符、保留合法国际前缀等规范化规则，由一个服务负责认证与写入，不凭空强制新号段。管理员建号及员工/管理员改号原子更新联系号码与登录键；员工改号不可清空登录必需号码。缺号、重复号形成迁移阻断项，管理员通过既有写入流程修复，不自动生成号码、另建账户或让歧义数据参与登录。原公开用户名不再作为员工登录回退，测试夹具和演示入口一起迁移。

继续保留强制改密、密码策略、会话撤销和资料隐私；候选/通知/审计不输出认证键。直接把 username 改成手机号会经多个现有 DTO 泄露，因此不采用。

### 3. 分离创建候选与创建审核，不放开所有旧授权函数

新增“本公司有效业务员工”创建候选/校验路径，复用 `/assignee-candidates` 并明确其创建用途。Web 创建不再从受查看权约束的 `/users` 目录拼候选；返回最小人员/真实部门/职位字段，不含手机号。创建、创建重提、批准三处使用同一候选约束。旧派发/交接能力保持独立，不能全局改 `canDispatchTo` 为总是允许。

将创建路由从现有 `route` 分离，由创建人决定。创始人判定复用并补齐组织拓扑检查：排除管理员，校验本公司员工节点、上级引用和循环，只有可证明的唯一组织树根可维护标签及获得创始人原因。其他人员 managerId 真为空可按无上级创建免审，但不能因此获得根节点维护权；多根/缺失引用等组织异常不猜创始人，报告管理员修复。

预览请求显式标明创建/修改/进展/完成/重开/交接及所需任务上下文。保留原响应 route/reviewerId/requiresApproval，增加可读免审或阻断原因；旧形态可按无 taskId 为创建、有 taskId 为既有非创建预览处理，重提入口显式使用创建上下文并检查原申请人。预览、提交、批准及组织变更刷新共用对应计算函数，组织授权版本变化后丢弃旧预览。

创建待审期间换直属关系时只重算创建人当前直属上级；不可用则保持阻断与修复提示，不上溯。非创建仍走已有有效/提议负责人有序路线、改派与显式自审。已有创建待审按新规则重新裁决，旧审核人不可决定；若新规则合法免审，则在持锁校验截止与版本后留因生效，不能保留一个要求形式自审的旧待审。

### 4. 复用任务版本生命周期，精确调整表单

- 创建及创建重提不再产生完成标准输入或必填校验。新版本中缺省值规范为空字符串，现有 TEXT NOT NULL 可继续满足；检查后续约束是否禁止空值，仅在存在冲突约束时增加前向迁移。历史已有值在更新/复制版本时保持，不批量清空，也不要求新任务填写。
- 保留角色初始化：下层本人、中上层空；至少一位有效负责人，移除本人不加回。
- 创建、编辑、重开共用 Web 自有时分控件（小时/分钟选项或数字输入，非 `input type=time` 的系统弹窗），用同一排期序列化和公司时区校验。取消只回退控件草稿，全天切换不丢原时分；本 change 验证移动浏览器中的 Web 行为，套壳资源同步、键盘/窗口容器适配及设备验证另行交接。
- 重开在原 action 表单加入全天、起止日期及时分，将原因和排期一起提交后端现有 reopen 分支。
- `expired` 接入结果名、按钮和校验；原申请人载入原提议改期，继续使用现有创建重提命令建立新 request，旧 request 不改回 pending。
- 差异直接渲染后端授权 diff 的前后值及有序负责人，不在前端重新排序比较。缺专用 diff 时只显示申请人有权内容，不能补读基线绕权。全部文本转义。

仅删输入或只改提示无法满足后端契约，因此同一阶段改前后端及夹具。

### 5. 连续月份与日内时间轴共用本人有效任务源

将日历人员筛选固定为当前真实账号，删除选择器和过期持久状态。全局授权集及任务表单数据源保持独立，日历不得从全局移除他人任务来达成过滤。复用现有完整授权分页加载，先完整取回当前授权正常任务，再投影本人；连续月份主要按可见窗口增量挂载月份。未来若增加日期范围接口，必须保持跨月相交语义，不能只查开始日在月内的任务。

月模式使用前后哨兵补挂相邻月份，以月份/业务日稳定键避免边界重复；卸载远处月份时用等高占位和可视日锚点保持位置。选择远月、返回今天、改变月格高度及任务刷新均保持或重建明确日期锚点；账号变化清除缓存。拖动手柄/双指才调高，单指普通竖滚不抢手势。

日轴将分钟数映射到纵向位置，先按真实日期截取任务，再为每个相交组分配完整并发列数；真实时段与最小命中区分离，对短任务/点任务处理命中冲突，不能隐藏第六列或扩大工期。全天区独立滚动，无前五项截断。保留月格真实“+N”、两行标题和个人置顶，标签色统一由共享呈现函数输出；默认粉色不进入标签色板。

相比新增第三个“瀑布流模式”，在月模式连续浏览可保留已确认两模式及现有月格操作；日轴不代替跨月浏览。

### 6. 任务表单接通入口，保留现有全局计算

日历按钮复用 `openTable/closeTable`，返回上下文增加连续月份的可视锚点。保留完整加载→授权正常任务→去重→组合筛选→全局排序/计数→分页的既有顺序，不能边翻 API 页边报完整统计。

列序设计默认：任务名、本人关系、执行状态、待审/需处理标记、截止、紧急度、负责人、开始，其他创建来源、时间、文字详情、历史完成标准及父任务靠右。具体宽度可在实施时按手机可读性调节，全部内容和原排序能力保留，表头行同步。修改列序只做适用浏览器检查，不单独写镜像结构测试。

### 7. 日志保留同人同日记录位置，按真实创建时间冻结

保留现有作者/业务日唯一键，为日志加逻辑删除状态（如 deleted_at），不再物理删除。活动列表/正文详情过滤已删除行；同日重建在事务中恢复原位置、保留最早 created_at 并递增 row_version，创建前同时检查近三天及原冻结点。原日志的标签、评论和引用不能因恢复同日位置而变成另一作者或另一日对象。使用服务端注入 Clock 计算 `created_at + 24h`，统一 `editable/deletable/frozenAt`，达到边界拒绝更新和删除。

删除前先检查本人、版本、时间，幂等重试不能复活被冻结行。存量活动日志用已有 created_at 回填，不用迁移时间；此前已物理删除且事件留有 logId 的记录，迁移从可证日志创建事件和时间恢复日位置占用信息，无法证明业务日的历史删除记录记录迁移限制，不能编造历史。需要修复的历史异常在启用新写入规则前报告。

作者目录返回授权后的真实部门、团队及人员信息，不含号码。Web 在各层搜索、联动清理无效条件，允许无团队及范围内全部；正文权限保持原管理链边界。相比只新增 freezeAt 字段，保留删除位置才能堵住同日删建重新计时。

### 8. 标签目录可变，审计快照不可变

新增公司级 tag 表（ID、公司、名称、色板值、逻辑删除时间、版本）。任务关联放在 task_versions 的单个 nullable tag_id，日志为单个 nullable tag_id；通过单值字段、复合公司外键/服务检查拒绝多选和跨公司。任务 diff、历史、申请快照补标签值快照以保留审计；正常详情按目录当前名色展示，目录删除后固定其删除时值和已删除标记。

已有对象持有被删除标签时允许原引用继续流转并清除/替换，但提交不得新增其他已删除标签引用。创始人维护 API 独立于管理员控制台，复用拓扑根节点检查；会话能力只辅助入口显示，每次写入重新鉴权。色板预定义，默认粉色只用于未标记任务；同一呈现函数服务日志列表、药丸和日历。

### 9. 评论作为独立聚合，通知采用专用接收矩阵

新增评论表：公司、对象类型及任务/日志引用、作者、正文、created_at、edited_at、deleted_at、row_version。以对象类型约束和相应复合外键/服务校验保持公司隔离，索引按对象和 created_at/ID。提供对象详情下的列表/发表、评论 ID 下编辑/删除；分页按发表时间和稳定 ID，写操作沿用 Writes 与 ETag，不允许 parent/reply 字段。

每次读写使用正常任务/日志权限，不能调用历史通知例外来证明可访问；更新删除还验作者。正文纯文本转义，沿用应用文本长度校验；不动任务版本或日志编辑时间，不进入任务审核队列。任务/日志业务冻结不锁评论。

新增 comment.created 事件并明确对象引用（日志通知不能硬塞 taskId）。事件接收集合仅取当前有效负责人或日志作者、去重并剔除评论者。送达和打开重新验对象权限；评论被删除时读取/投递裁剪正文摘要，不能从 outbox 或历史载荷拼回。编辑删除不产生新通知。保留既有业务通知矩阵及自通知，只有评论走排除本人规则；不能全局改变所有通知接收逻辑。

### 10. 正式管理端与受限团队入口复用已有后端

`admin.html` 增加“任务历史”“通知管理”页签。历史使用现有 `/admin/tasks/{id}/history`，补管理员专用分页查找/定位任务接口；不得调用员工列表充当全公司历史范围。通知使用现有 `/admin/notifications` 与事件撤回接口，展示服务端可用状态、严格三分钟窗口及撤回的业务边界。

获授权部门负责人在员工“我的”增加受限“团队管理”入口，新增最小读取当前可管理部门、团队及合法负责人候选的接口，写入复用 `createTeam/updateTeam`。授权不是管理员，不读取全组织/员工敏感数据；转交后刷新入口与组织授权版本。团队负责人本身不扩查看或创建以外业务权限。

### 11. 演示与验证使用真实数据，隔离运行

扩展 `DemoSeed` 或显式演示准备脚本，使用手机号、固定可识别演示标记及幂等写入，仅在指定演示环境运行。准备十条公司事项、足够跨月份/重叠/全天任务、待审及各状态、分页表单、部门团队、下属日志、标签评论和通知。演示账号须本身具有下属日志和任务的合法权限，不以切角色脚本绕过。

沿用 `run_check_isolated.sh`、受控 Clock、Java/HTTP/Chrome 基础，更新引用 username、创建旧路由或午夜冻结的旧夹具和断言，保留非创建及隐私回归。本 change 仅以 Web、管理端和后端证据验收；Android 套壳的构建、签名、升级及设备检查由其他人员另行验收，不将浏览器结果写成套壳通过。规划调整后须重新独立验证，旧报告不因范围缩减自动变为 PASS。

### 12. Android 套壳移出本 change，保留交接边界

用户明确本机无法承担 Android shell 工作，交由其他具备环境的人员实施。原 S01、任务 10.4—10.8 和 11.2 的套壳部分整体移出本 change 的实施及验收范围，不要求本机补装工具、取得密钥、构建 APK 或连接设备，也不作为本 change 完成及归档的前置条件。保留这些历史编号供交接追溯，不将其勾选完成或记为已验证。

接手范围包括完整员工 Web 资源同步（非仅主题）、套壳入口与桥接/UUID/连接配置、五页及“日志”导航、返回层级、键盘和滚动、原包名/原签名及递增版本、资源和 APK 摘要、构建安装文档、保留配置的覆盖升级与实际 WebView 连续演示。接手人需原签名密钥、SDK/构建工具、apktool、adb 及已有旧包的测试设备，后续由其单独安排实施和验收，本轮不创建新 change 或新增规划文件。

## Risks / Trade-offs

- [公开 username 或 DTO 泄露号码] → 分离登录键，保留目录最小字段，加入目录/通知/审计隐私负例。
- [共用路由或授权被全局放宽] → 按操作显式分支，创建与非创建分别验证，交接、查看权和管理员权限负例持续有效。
- [日志历史物理删除信息不全] → 新版本先保留删除位置，迁移只使用可证据恢复的信息，异常清单明确，不重置已知首次创建时间。
- [日轴密集窄列和跨月补挂手势冲突] → 以超过五项、短时点任务及月格调整的浏览器命中/滚动场景验证，真实时段不被点击尺寸覆盖。
- [目录改色与历史一致性] → 当前引用解析目录，审计写值快照；删除目录固定末态，业务对象和记录不级联删除。
- [日志评论事件无 taskId 被既有通知管道漏投] → 通知引入通用对象引用，分别覆盖任务和日志投递、失权与删除摘要裁剪。
- [旧原生客户端仍提交旧字段或显示旧提示] → 保留可兼容请求/响应字段并记录行为变化；原生代码修改不纳入本变更。
- [旧套壳仍含旧资源且共用后端行为变化] → 记录已知兼容影响、当前 Web 版本和移交范围，接手人单独完成资源/桥接、签名/升级及设备验收；本 change 的 Web 通过不代表套壳可用或已交付。

## Migration Plan

1. 在隔离数据库副本运行预检，统计缺号/规范化重复、组织根与直属关系异常、历史完成标准、日志创建时间和已删除证据。输出不含明文号码或凭据的阻断清单；备份原始结构数据。
2. 以 V16 起顺序新增 Flyway 迁移，不重写旧迁移：登录键/唯一约束与分阶段回填、日志删除保留机制、标签及关联快照、评论与索引。无冲突才收紧唯一性；绝不自动捏造手机号或组织归属。
3. 先部署兼容字段的服务端契约，迁移已有创建待审并复核截止、版本、组织路由；保留原历史与审批终态。完成手机号修复后启用员工手机号认证；独立管理员修复入口保持可用。
4. 构建打包 Web 和管理端静态资源；新增模块若存在须加入 `pom.xml` 资源清单及 HTML 加载顺序/缓存版本。Android 资源同步、APK 构建及安装由接手人另行安排，本 change 不修改两个 Android 工程。
5. 在隔离环境运行迁移、HTTP/并发边界和服务页面浏览器验证；准备持久演示数据，用同一账号验证 Web 完整路径。形成 C01—C25 的当前范围证据和套壳交接说明，作为修订规划后的独立 e13 验证输入。
6. 回滚优先修复前进；如需恢复旧业务规则，须协调服务与 Web 版本，从迁移前备份恢复到隔离库验证，再执行数据恢复，并向旧客户端接手人说明兼容影响。Android 包版本、安装及回退方案由其另行安排，不作为本 change 的执行任务。仅回滚旧二进制会恢复物理删除/旧路由等错误且可能忽略新增引用，不能当作完整回滚。实际部署与数据恢复不由本轮规划执行。
