# Proposal

## Why

通知列表信息过多且缺少已读/类型组合筛选，手机创建任务的标签、排期和选人操作不够直观。现有非创建审核按任务业务责任方路由，与用户要求的“触发操作者的直属上级审核”不一致，需要统一前后端和已有待审处理。

## What Changes

- 通知增加默认精简列表：所属任务（非任务通知显示所属对象）、通知类型、已读状态、时间；正文在详情查看。支持已读/未读/全部与类型组合筛选，保留完整摘要显示切换。
- 通知详情对同一任务合并重复跳转，评论消息保留定位评论的用途；按事件、申请和对象自动生成展示信息，验证缺失对象及受限内容的安全兜底。打开即已读，返回列表立即更新状态、计数和当前筛选结果。
- **BREAKING**：任务共用标签由单选变为可多选。圆形/胶囊色块按行自动换行，名称显示于下方，点击切换选中；保存、详情、编辑、审核差异及历史完整支持标签集合，旧单标签数据兼容迁移。
- 创建及重提表单按开始/截止分组排列日期和时间，手机窄屏可换行，统一必填日期与时刻，以“设为全天”快捷填入开始日 00:00 和截止日次日 00:00，保留组织时区和现有日期校验。
- 创建负责人候选改为按真实固定职级和直属关系构成的可展开树，支持多选、搜索、已选列表、确认和取消；维持原候选权限。
- 负责人选择明确区分真实职位、部门和团队；公司层无部门人员显示公司层级，不伪造部门、不显示空值或重复身份。
- **BREAKING**：创建、修改资料/负责人、进展、完成、重开、交接全部由本次实际操作者（申请人）的当前直属上级审核。任务创建者、业务接管人和所选负责人不再决定审核归属。已有有效待审按新规则刷新并留痕，旧审核人失权。
- 用户已确认：固定创始人沿用创建审核的免审规则；其余人员上级缺失/无效一律阻断。沿用现有公司共用标签，界面交付为网页及在线安卓套壳。私人标签数据与日志单选保持原用途，维护权限按追加的创始人规则，独立原生界面不在本次范围。

- 本人日历保留月/日、横向日轴及表单入口。拖动粒度、入口限制和待审虚线投影统一由 `fix-hourly-schedule-drag-and-log-type` 承载：月历按日显示及调整、日轴按小时，仅本人视图提供拖动；任务详情沿用现有操作权限。
- 基础资料/负责人编辑仍仅当前业务责任方可申请；“正常可见即可编辑基础字段”是用户明确暂缓的待确定事项，不在本轮扩大权限。

## Capabilities

### New Capabilities

无，沿用项目现有规格组织。

### Modified Capabilities

- `pandora-requirements-aligned-prototype`：通知精简、筛选、去重复跳转和自动生成；任务标签多选；排期输入与树形选人；统一操作者直属上级审核；完整替换个人任务表单范围、关系筛选及日志创建入口的旧条款。

## Impact

- 前端：`潘多拉-工作区接入.js`、`潘多拉-任务接入.js`、`潘多拉-交互原型.js`、`潘多拉-标签评论.js`、`潘多拉-api.js`、日程和现有样式。
- 后端：`TaskService`、`WorkspaceService`、标签服务、候选目录/组织树、组织调整/停用/接管及待审刷新、事件投递与审核权限。
- API：通知筛选字段；任务标签集合兼容旧 `tagId`；候选增加必要的组织父节点信息，不返回联系方式。
- 数据：新增版本化多标签关联迁移，不修改已应用迁移，不清理业务数据；历史已办结审核不改写。
- 验证：后端审核/标签/通知集成与权限测试、升级兼容测试、手机和桌面真实浏览器交互。现有单标签与业务责任方审核断言必须更新，其他权限回归保留。
- 云端发布与手机安装不属于本次规划执行；部署前需要验证和明确发布范围。

## 追加入口调整

- 任务表单只显示本人原始创建或当前负责的任务，排除仅因上下级关系可见的任务。
- 所有标签创建/改名/改色/删除统一由固定创始人维护，员工在任务/日志编辑时选择或清除；日程移除标签管理和图例，保留任务颜色投影。
- 写日志统一创建今天、昨天、前天尚未创建的日志；已创建日期不在创建选择器中，编辑从详情进入，重复创建冲突不转编辑。

## 协同与验证状态

- 本 change 负责创建输入、通知、审核、个人任务表单及标签/日志创建入口；下属页面入口由 `redesign-subordinate-workspace` 负责，最终排期交互与日历待审展示由 `fix-hourly-schedule-drag-and-log-type` 负责。日志界面分离及产品文案清理由 `separate-log-forms-and-clean-product-copy` 承接。
- 本轮只更新规划。保留既有 verification.md 的 FAIL 和实施记录；旧接管/交接测试须适配申请人上级审核，不能恢复旧审核路线来通过旧断言。受影响任务重新打开，须按新规划实施及独立验证后再考虑归档。
