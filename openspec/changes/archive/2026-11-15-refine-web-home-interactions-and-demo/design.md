## Context

动机及确认范围见 [proposal.md](proposal.md)。这是一项跨 Web、PC 管理端、后端查询、结构迁移和演示准备的调整，需要设计文档约束共享契约与交互边界。

主规格当前明确禁止事项拖动，并规定任务看板按派发倒序；本次 delta 修改完整原要求及相应场景。评论要求则明确区分员工 Web 入口移除与后端作者删除能力保留。

## Goals / Non-Goals

**Goals:** 用有效版本驱动排序和逾期样式；保持事项原ID/完整范围、版本、幂等及账号隔离；标题字段通过前向迁移完整退役；少量真实种子即可演示新增行为。

**Non-Goals:** 不引入日历依赖、端点拉伸、小时轴或审批；不改评论后端、不改资料算法、不降低业务密码规则；不编辑 `android/`、`flutter/`、`android-shell/` 或其规划。不在本轮提案操作数据库或生成运行证据。

## Decisions

### 1. 看板在服务端按三键排序后截取

在 `homeRead()` 的完整当前授权范围内使用 `v.due_at ASC`、显式紧急度序 `urgent/high/medium/low`、`t.id ASC`，最后 `LIMIT 10`。保留原选入条件和有效版本连接；不以派发时间作第四键，不新增逾期分组，也不引入表单或月历置顶。

`task_versions.due_at` 已是规范化真实截止：全天在 `TaskService` 依据公司时区及截止时刻生成，直接复用；不能改为对 `due_date` 拼午夜，也不能拿提议版本排序。首页任务投影增加有效 `dueAt` 和 `executionState`，以ISO时刻返回，前端按原 `now > dueAt && state != done` 判定。这样即使看板任务不在通用任务缓存内也可独立渲染。清单创建/恢复及已有正常刷新时重算；不新增后台定时刷新体系。

前端原样消费顺序，预览取前三条，清单展示同一十条。淡玻璃红样式只挂在清单任务行，提供不新增可见教学文案的逾期语义；紧急度仍右对齐。拒绝“前端对旧前十条重排”，因为会漏掉真正更早截止的任务。

### 2. 两周可视密度和固定日期列

维持原月份加载、唯一日期、范围分页和浏览锚点；两周仅是视口密度。三轨道不变，事项条建议32px并由同一布局变量控制，日期行继续保留原可点击空间。视口按两条周行及星期表头计算，月标题/边界纳入布局校准，不沿用造成三周可见的52vh伸展；不同视口和月边界均验证，滚动中允许部分周行露出。

`overflowHTML()` 用日期索引输出明确 `grid-column: col+1`，必要时固定同一行；隐藏数量继续来自完整分段集合。相比依赖占位元素补齐，显式列定位能同时处理周日和任意稀疏分布，不改变点击日或计数。继续用固定轨道高度防止加载前后跳动。

### 3. 每日事项自有的整段拖动状态机

在事项模块内实现 `idle → pressing → dragging → confirming → saving`，关闭/切账号可从任一临时态清理。沿用公司月历约500ms/8px门槛、触摸与鼠标、抓取后边界自动滚动及可用时单次短震动；普通滚动和短按保持现有路径。无需重构公司月历拖动引擎。

按抓取点所在真实日期记录 `grabDay`，指针目标按七列与周行取 `targetDay`。用公历日序差平移原完整 `startDate/endDate`，不按本地毫秒差计算天数、不取可见片段起点。完成事项仍可按原本人编辑权限移动；不设置首尾拖柄，整个事项条都作移动操作。临时ghost/目标高亮不写入缓存；边界滚动补载不卸载当前来源，月外非交互空格不作为有效目标。

松开后通过原弹层展示新旧范围及确认/取消，不改正文和完成值；零位移不提交。确认使用已读取原版本与固定目标日期对调用既有 `PATCH /daily-items/{id}`，同一操作重试保留幂等键，不在重试时再算一次差量。成功复用并补齐旧/新覆盖月份和日期清单刷新；失败保留原可靠投影、明确冲突/重试，保留浏览锚点。Escape、pointercancel、失焦、退出和会话变化取消临时状态及事件监听，抑制拖动后的click，不误开清单。

### 4. 事件纪折叠与排版使用局部共享样式

保留卡片打开清单，预览只做两行clamp；清单行采用可键盘激活的按钮式语义和 `aria-expanded`，按真实事件纪ID维护本弹层展开集合，一条切换不重建其他行或重置滚动。关闭清单后可恢复默认折叠，不引入跨登录持久偏好。正文始终保存完整纯文本，以安全转义及原换行展示，仅视觉截断。

为两卡及其清单定义正文排版规则，覆盖现在任务标题单独的12.5px/600样式，建议统一15px、常规正文字重、1.5行距；窄屏可统一14px。优先级等元信息独立，避免全局修改主题字体。上方容器需容纳三条两行预览，不以卡片固定高度再次裁掉第三条；短屏通过整页滚动保持可达。删除“统一发布”和n/10的DOM而非仅隐藏。

### 5. 公司事件纪仅正文，使用前向迁移

新增当前最新迁移之后的Flyway版本，仅删除 `home_items.title`；不改已应用迁移。已退役personal行不恢复，其旧路径涉及title的SQL/允许字段同步清理。移除 `OrganizationService`、首页列表/详情以及旧home-item路由的title投影、参数、自动正文截取和SQL列；活动公司信息写入口只接受body，传title按既有未知字段规则400拒绝，鉴权、版本、十条并发限制及调序不变。

管理端删除 `companyTitle`、标题列、data-title和请求中的title，员工端去掉 `body || title` 兜底，`DemoSeed`公司事项只传正文。更新活动接口示例、交接契约及检查夹具中的公司信息title，范围限定对象，不能批量删除任务/通知title。旧公司title数据按用户明确决定退役，不拼入正文；迁移断言body、ID、排序、版本、创建时间均保持。

不选择保留隐藏title或每次自动生成，因为会继续维持用户要求删除的模型。接口为明确不兼容调整：当前Web/管理端与后端同版本交付，不为未交付Flutter保留旧字段；后续客户端应读更新契约。

### 6. 置顶、评论和资料修改限定呈现范围

表单行按 `tablePinned` 增加状态类，名称及所有数据单元格使用同一浅蓝玻璃渐层/高光，置顶规则覆盖偶数行、hover和active样式，保留焦点可见性；普通行沿用斑马纹。删除表内“表单置顶”span，详情按钮及服务端分组不变，不改变任务标签配色。

共用评论渲染移除删除按钮，并移除删除动作分发及不再使用的前端删除函数，不能误删同文件内标签删除动作。后端 `CommentService`、路由和通知脱敏测试保持原能力；原Web回归中“可删除本人评论”断言改为入口不存在及编辑可用。`tenureText()`只删可见后缀，本人和下属复用函数，保留服务端asOfDate和未设置空态。

### 7. demo默认与少量可演示记录

同步 `application.yml`、`start-demo.sh`、`prepare_demo.py`、`backend/README.md`及使用默认演示密码的活动检查为111，保留 `PANDORA_DEMO_PASSWORD`显式覆盖。种子直接编码演示账号密码，不需要改正常 `Credentials` 的长度规则；不变更 `PANDORA_DB_PASSWORD`，不自动改已有账号hash。

| 行为 | 默认演示样本方案 |
| --- | --- |
| 看板清单逾期红底，预览无红底 | 复用主角 `task-<role>-2` 历史正常任务，确认按新顺序进入前十；配已有未来任务作对照 |
| 两行省略及独立展开 | 将现有十条事件纪中1–2条改为自然长正文，含合理换行；不增加第十一条 |
| 整段拖动并刷新 | 复用已有从昨天至明天的跨日事项，必要时仅调整一条种子正文使其易辨 |
| 表单置顶玻璃蓝 | 复用已独立表单置顶的第2条任务，保留非置顶任务对照 |

无需为删除文案等清理项额外造数据。若现有内容不足，只补1–2条正常业务样本；周日溢出、同值排序、并发和多页仍用隔离夹具，不向默认demo灌测试数据。准备后用真实账号读接口并操作、刷新取证，记录准备日、构建和样本ID；保留模式/重复准备不补写已有编辑或重置密码。默认启动脚本已有显式重建语义不扩张，本提案不执行它。

## Risks / Trade-offs

- [两周视口遇跨月头部或短屏时只见部分第二周] → 将周行、表头和月标题一并校准，验证四个既有视口和月边界，禁止退回三完整周或缩小目标。
- [长按拖动与原滚动/click竞争] → 门槛前不接管滚动，激活后明确接管，取消清理和click抑制分别验证；真实触摸设备证据与合成事件结果分别记录。
- [title删列后旧服务/旧管理页无法运行] → 同版本部署、刷新资源版本，迁移前留快照；更新活动调用方，禁止只改管理端表格。
- [全天截止或待审投影引起红底/排序错误] → 使用current_version的due_at，临界相等不逾期，构造全天/时区/待审夹具对照。
- [复用历史检查错误沿用旧规则或旧密码] → 使用当前检查入口并修订其真实断言；兼容脚本`check_home_calendar.py`只是转发，不能视作单独新增覆盖。
- [演示样本随时间变成更多逾期] → 用明确准备日验证；普通启动不自动滚动改期，当前演示通过新空库或受控重建取得当前种子，不静默覆盖旧库。

## Migration Plan

1. 后续apply先在隔离空库和含不同title/body的升级夹具验证新迁移，确认原迁移校验和、正文及其他业务保留；同步代码、种子、文档及当前回归。
2. 构建同版本后端与Web静态资源并验证资源指纹。部署前保留旧库及构建快照；停止旧进程后升级，禁止旧代码与删列后schema混用。
3. 默认演示通过明确目标的新空演示库或原受控准备流程生成少量样本；保留旧库可回退，不向普通业务库执行演示重建。
4. 删除标题的回退需恢复迁移前快照及旧构建到隔离/停写环境；仅重新加空列不能恢复旧独立标题。其余纯样式/排序回退也必须与接口及结构版本协调。

## Validation Strategy

实现阶段扩展当前检查，覆盖后端全量先排序后取十、三键同值及排除条件；body-only CRUD/未知title拒绝/权限/旧版本与空库升级；浏览器四视口的两周三轨道、稀疏列+n、单击展开和只清单红底、置顶固定列及交互态、评论编辑及无删除、本人/下属时长。拖动覆盖跨周/月中段抓取、确认/取消、滚动短按分流、失败/冲突/会话切换及重试不二次移动。优先扩展 `check_fixed_web.py`、每日事项现有套件、管理端当前检查和demo流程；文案等低影响项在同一浏览器检查中断言，不另建镜像单元测试。

最终运行适用后端测试、受影响当前集成/浏览器检查、资源打包检查及真实demo登录/样本演示，实施记录区分真实API/真实浏览器/合成触摸和未覆盖范围，不宣称Flutter验证或本轮已验证。
