# Design

## Context

动机见proposal。根目录原生JS/CSS按模块组合，日志数据/详情/冻结/评论由现有服务端裁决。先前变更仍未归档，代码共用同一工作区，本轮按用户最新明确要求独立跟踪。

## Goals / Non-Goals

**Goals:** 日志页本人列表、详情与评论入口、创建编辑字段一致，并消除旧人员状态对日志页的影响。

**Non-Goals:** 不改变服务端现有上级阅读权、作者编辑窗口、日志唯一性、评论授权或数据库；不重新实现先前统一创建入口，不部署云端、不做手机真机测试。

## Decisions

1. 日期与标签均使用field/label/select，短字段标题和相同间距/高度；沿用响应式单列/双列网格。分别测量创建和编辑320/390/1440控件坐标与高度。
2. 卡片以独立data-log-card和可聚焦语义激活；捕获点击时排除button/a/input等交互控件，Enter/Space仅卡片自身聚焦时触发。复用openLogDetail和评论加载；不给父卡片data-log属性，避免共享委托抢占编辑或任务按钮。
3. 日志页只从当前me.id派生过滤与计数，不依赖旧部门/作者状态；本人读取使用scope=self，空态明确个人日志。人员资料的既有合法阅读使用scope=visible&authorId及独立弹层，不替换本人列表数据；详情回读到全局缓存仍被本人过滤隔离。保留API授权以免误删正常权限。
4. 本轮独立变更依赖先前25项实现，共用日志回归fixture和工作区文件。规划、任务与实施证据独立记录；旧变更不包含本轮三项任务。

## Risks / Trade-offs

- [卡片父级误拦截编辑或任务] → 排除内嵌控件，实际浏览器分别验证。
- [阅读他人详情写入缓存后混入本人页] → 当前身份作为唯一过滤依据，测试旧筛选、资料阅读、返回和刷新。
- [字段在窄屏溢出或双列不齐] → 同结构、短标题，真实浏览器截图和几何测量。
- [先前未归档变更共享文件] → 明确依赖和实施指纹，不声称独立checkout或已归档。

## Migration Plan

无数据库迁移。打包网页资源并更新本地演示服务，保留数据库；后续云端发布另行处理。回退仅回退本轮页面改动，不能回退先前标签集合和审核规则。
