## Context

动机及六项范围见 [proposal.md](proposal.md)。本轮是既有 Web 体验的定点修复，涉及共享弹层、事项、本人/人员日历及演示种子，满足跨模块设计条件。

源码调查得到以下事实；显示缺陷尚待实现阶段真实浏览器复现，不能将静态判断当成修复验证：

| 区域 | 当前落点及已观察事实 |
| --- | --- |
| 通知 | `notificationsView()` 标记 `noticeList`，共享 `renderSheet()` 只有 fullscreen 开关；`.sheet` 设置 max-height 而未固定列表高度 |
| 事项 | `barHTML()` 输出 `is-completed`，CSS 完成色却匹配 `is-done`；清单、详情、月份图例及表单另有状态/跨日解释 |
| 月历点击 | 捕获阶段已按日期命中打开清单，但鼠标 pointerdown 立即 `beginScheduleDrag()`，结束统一抑制点击；只有触摸走长按 |
| 人员月历 | 旧 `.staff-month-tracks` 留有三行44px，新声明只写 auto-rows 为18px并将容器按三行18px计算；旧显式行高仍生效。溢出渲染跳过空列，按钮未指定 grid-column |
| 本人资料 | `renderMe()` 的信息卡与 `readonlyRows()` 都渲染入职日/时长；下属资料卡有独立渲染路径 |
| 演示 | `DemoSeed` 只建 `tag-focus`，仅一条任务和一篇日志各用一个标签；`check_final_demo.py` 断言日志恰好只有该标签 |
| 启动 | `start-demo.sh` 默认 DROP/CREATE 指定演示库、构建再首次准备；`--keep` 及单独重复 `prepare_demo.py` 保留修改。`PANDORA_SKIP_BUILD=1` 会复用旧 JAR |

规格基线为主规格加 `align-web-employee-client-with-nov08-guidance` 的现有 delta。本轮六个 MODIFIED 块从该前置 delta 的完整要求和场景继承，尤其 `Daily-item span labels and status` 尚未进入主规格；归档/同步先前置再本轮。不得回退为主规格尚存的旧横向事项数量标记，也不修改前置 change 来隐藏差异。

## Goals / Non-Goals

**Goals:**

- 让点击、待激活长按、实际拖动及滚动拥有明确边界，继续复用现有仅排期确认和权限裁决。
- 让容器尺寸、实际轨道和可点击区域一致，并通过真实输入及几何测量验收。
- 用现有有序共用标签模型补充真实演示，不引入新的数据维护路径。

**Non-Goals:**

- 不改日视图鼠标激活方式，不重写整个拖动系统，不将下属页面变为可排期页面。
- 不改事项状态算法、实际日期、任务有效版/待审投影、审核、冻结及后端权限。
- 不新建 API/数据库迁移，不改演示库默认重建与保留模式语义，不自动升级既有演示内容。
- 不改 Flutter、原生 Android、套壳或 PC 管理功能；共享全局样式须避免影响 PC。

## Decisions

### 1. 只为通知列表增加可撤销的固定高度状态

共享弹层根据栈顶 `view.noticeList` 切换专用状态类，返回、关闭及更换为其他视图时重新计算并移除。通知列表 height 使用现有响应式最大高度公式：手机扣安全区及既有顶部余量，桌面沿用既有外边距；不是首次打开按当时内容测量并缓存，也不是所有设备硬编码同一像素值。

弹层头部不收缩，消息内容区占剩余空间并内部滚动，继续利用通知筛选区已有 sticky 行为。加载/空/错误只替换内部内容。详情沿用其原高度，返回列表时恢复固定高度、筛选及位置。

不选择修改所有 `.sheet` 的统一 height，避免把资料、表单和任务详情一起撑高。

### 2. 统一三态类名及颜色，保留操作语义

状态判断仍为 completed/open/overdue，统一使用同一映射覆盖条、清单和详情；修正 completed/done 的匹配差异。红/蓝/灰为已确认语义，具体色值使用现有主题的可读色阶，颜色变量同时应用边线、底色和必要文字。

清理月份状态图例、清单重复状态文字、详情重复徽标和表单跨日解释；保留事项正文、实际日期、完成复选控件及其必要名称。辅助技术通过 aria-label/aria-checked 或隐藏文字获取状态；不将用户正文中的“已完成”“跨日”等词作为清理目标。原条上符号若保留，只作小型辅助识别，不恢复冗长说明。

不通过改变逾期算法或删除完成操作解决视觉冗余；更新任一覆盖日后继续按旧/新范围刷新全部受影响月份。

### 3. 月视图鼠标复用等待长按流程

月视图鼠标与触摸均进入约500ms待激活状态，短按释放只清理定时器并让真实 click 到达现有 `monthHit()`；真实端点也适用。长按门槛前不 preventDefault、不捕获指针、不生成拖影、不设置点击抑制；超过移动容差或发生滚动则取消候选并避免滚动后误点。

达到门槛后才执行原拖动激活、捕获、预览和点击抑制。激活后的取消、无位移及失去捕获继续不写入且不弹清单；有位移松手继续原轻量确认。日视图鼠标保持原流程，触摸保持现有长按。

不采用“立即开始拖动但无位移时补开清单”的修补方式，因为它仍会在短按时错误展示拖动反馈且不符合用户确认的门槛。月历回归必须用真实鼠标/触摸事件，不能仅通过 DOM `.click()` 证明修复。

### 4. 清理人员月历旧轨道约束并显式定位溢出列

在现有人员月历样式内统一显式轨道行为，以 `--staff-lanes`/`--staff-row` 为尺寸来源；清除旧三行44px及旧绝对定位、透明容器等与现有 DOM 冲突的声明，而不是继续叠加更高优先级补丁。当前三条18px及行间距为默认，容器高度须包含相同的行距、padding及边框计算。

日期行、任务轨道、溢出行按正常流各自占位，标题只在条内省略；隐藏轨道条保持不绘制、不命中。溢出按钮显式使用其日期列，或保留七列完整占位；优先显式列定位，不能依赖跳过空列后的自动排布。`+N` 继续从完整周片段的隐藏集合按日计算。

不以增大 z-index 或容器 overflow:hidden 掩盖冲突，这会留下丢失内容或错误点击区域。现有只读路径、待审虚线和任务完整分页保持。

### 5. 本人组织信息只去掉重复字段

`readonlyRows()` 当前用于本人组织区，移除其入职日/时长输出，保留本人信息卡原字段与空态；若实施时有新增调用方，限定在本人组织区使用组织字段构建器。下属卡路径保留原输出，不改后端 hireDate/tenure 或计算算法。

不做通用资料组件重构，也不通过 CSS 按行位置隐藏，以免误伤下属及缺层组织数据。

### 6. 种子增补多标签，通过现有重建交付

保留 `tag-focus` 的稳定 ID、名称和已有引用，新增一个稳定 seed key 的动画业务共用标签，采用可辨的第二种颜色。为现有四主角可访问的两条正常任务、两篇近期日志设置两个有序标签；尽量复用现有业务，不增加主线任务密度。任务更改沿用现有业务服务/审核，日志遵守现有维护规则，读回有效引用。

任务首标签顺序保持稳定，颜色仍由首标签决定；日志检查不再硬编码某篇日志仅有 `[focus_tag]`，改为针对明确样本校验有序集合，并保留目录、权限及非主角无专门业务等现有断言。

无需 manifest 结构变更或版本升级：默认启动先建空库，新种子自然生效；保留模式旧库不补数据是既有约定。单独 `prepare_demo.py` 仍幂等。更新受影响文档，明确正常重建与 `--keep`/跳过构建区别，不为第4项新增旧库升级器或清库路径。

### 7. 在现有回归中增加用户可见行为证据

通知在四种视口记录切换筛选/模式/加载/空/错误前后的外框矩形并检查内部滚动。事项检查 computed style、跨日完成及可见文案/辅助语义。公司月历覆盖真实短按和长按、端点/跨日命中、滚动取消及原仅排期确认；现有鼠标拖动助手仅对月视图增加等待，不把日视图一起改为长按。

人员月历检查任务矩形、轨道边界、+N列位置和中心点命中，而非仅检查页面无横向溢出；用隔离密集夹具覆盖仅某一天溢出、首周空位及跨周/月任务。资料用现有人员浏览脚本增加本人一次/下属仍有的断言。演示用新隔离目标库和真实 API/页面验证种子、重复准备及保留编辑，复用 `check_final_demo.py`。

本轮验证不需要先运行会重建当前用户演示库的 `start-demo.sh`；集成夹具使用明确隔离目标，启动脚本默认语义通过已有脚本/文档及隔离演示准备链核对。触摸合成结果不充当实际手机证据，未覆盖设备行为在实现记录明确。

## Risks / Trade-offs

- [共享弹层状态泄漏] → 根据每次栈顶视图切换类，覆盖详情返回、关闭、账号切换和其他弹层。
- [旧 CSS 高优先级继续生效] → 删除冲突声明并测量实际矩形，尤其待审状态和窄屏；不只检查声明文本。
- [鼠标长按降低直接拖动速度] → 这是已确认的点击优先交互；沿用约半秒门槛与原拖动视觉反馈。
- [清理文字误删业务内容或无障碍语义] → 只移除渲染模板中的冗余说明，保留用户正文、日期和控件名称。
- [修改种子但演示仍加载旧 JAR] → 文档和检查明确默认构建/跳过构建区别，以当前构建在新隔离目标读回。
- [前置未归档 delta 被后续覆盖] → 本轮保留完整前置要求和场景，先前置后本轮合并；只在本轮改动处覆盖，不自动写其他 change 或 Flutter。

## Migration Plan

1. 实施修改限定于 proposal 所列 Web、演示种子及受影响检查/文档，不改历史迁移与其他客户端。
2. 刷新所改静态资源的 HTML 内容版本，按既有 Maven 白名单打包，并通过 `check_web_resources.py` 核对服务实际加载字节。
3. 执行相关隔离回归并记录四视口截图、矩形/命中及 API 读回证据。需查看新演示主线时使用正常重建入口；保留模式不承诺新增样本。
4. Web 回退使用前一构建；种子变更不触发既有库升级，保留数据的目标无需内容回滚，重建演示的回退使用既有备份/前一构建及显式隔离演示目标。
5. 交付 implementation notes 后由独立 e13 验证；归档本轮之前先完成前置 Web change 的独立验证及规格合并，不能用本次规划宣告任一 change 验证通过。
