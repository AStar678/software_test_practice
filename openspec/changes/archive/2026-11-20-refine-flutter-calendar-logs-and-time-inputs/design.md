## Context

`TaskCalendarPage` 由公司页和下属路由共用；当前用连续月份列表、日期锚点和独立的当天面板实现月／日切换。月历在整格上绘制粉底，顶栏直达日视图使用滚动锚点吸附的日期。月历拖动已有真实抓取日、全局指针位置、边缘滚动和独立确认流程；目标日期目前只用于预览，没有绘制到格子上。动机见 `proposal.md`。

## Goals / Non-Goals

**Goals:** 保持普通月历的尺寸和命中区不变；用同一个按天改期流程处理本人月历和展开周接续；让本人、各下属和账号的浏览状态及权限隔离。

**Non-Goals:** 不增加独立周路由、连续周导航、展开周的端点改期或新的排期接口；不把月外补位改成可落格，不安排独立的跨月拖动修复或改动首页每日事项。

## Decisions

1. **周展开是月历内的显示状态。** 在年月标题行右侧放一个有提示及焦点状态的图标，使用浮层列出与该月相交的真实周日期范围，跳过完全属于其他月份的占位行。月历卡片继续使用原有高度；浮层比逐周在日期格里加按钮多一次点击，但不占任何任务条、拖柄或日期区域。展开用原日历内容区的实际可用高度渲染七列，复用日头、条带、任务状态和 `+N`；不套用以单月边界裁剪后的周结果。用周一起算的绝对日期标识所选周，复用两侧月份的授权任务及节假日数据，按任务 ID 去重并按实际覆盖范围投影；按已有加载、错误及重试惯例呈现，避免把部分数据当完整结果。共享周布局时保持首页每日事项的原单月裁剪行为。
2. **来源状态和今天的数据单独处理。** 展开前记下月历锚点，打开日期清单或日视图时保留来源是展开周还是普通月历，关闭按层级返回；收起恢复月历位置。顶栏直接读 `businessDateProvider`，不读取视口日期。当前缓存不能证明当天完整时，使用现有任务范围查询补载，不先滚回今天，也不把未加载当成无任务。沿用人员与账号世代守卫，防止晚到响应覆盖其他人员、其他日期的面板。
3. **页面持有手势，月历提供落点。** 展开周只在本人且任务满足现有改期资格时识别长按；抓取时保存指针 ID、任务和实际抓取日。达到有意移动的阈值才收起周并让选中周在月历中可见，手势的移动、抬起或取消由切换前后持续挂载的页面层接收。单纯把 `LongPressDraggable` 留在周任务条上并替换周网格不可行，因为移除源组件后 `onDragUpdate`／`onDragEnd` 不再回调；要求用户松手重按则不满足一次手势。复用既有月历按天计算、边缘滚动与排期确认，避免新增一套周内排期算法。未移动直接释放不切换不确认；若已切到月历，取消只清理手势和预览，不返回周或写入。
4. **高亮和确认共用当前有效日期。** 在月历日期格里用不占位、不拦截事件的描边绘制目标，避免和今天日期行的粉底或任务条标签色混淆。切回月历、滚动或补载后的几何变化须以当前指针和实际月历视口重新命中；只接受可见的本月日期格，忽略月标题、月外补位和裁剪视口外的缓存格。稳定布局前不沿用周坐标或旧高亮推断排期，释放或取消后清空高亮。无需为了颜色反馈新增拖放目标或改变月格数据。
5. **日志只改两个共享标记，时间只锁定输入方式。** 在 `work_logs_page.dart` 改列表与详情的冻结文案，沿用 `log.frozen` 判断和既有权限。对 `task_form_page.dart` 与 `task_action_pages.dart` 已有 `showTimePicker` 调用用 `TimePickerEntryMode.inputOnly`；普通 `input` 仍能切回表盘，另写弹窗则会重复现有输入校验、格式及焦点行为。

## Risks / Trade-offs

- 月末／年末周的数据来自相邻月份 → 覆盖并去重七天的授权任务，正确保留节假日、续接段、错误状态和 `+N`。
- 周收起与月历恢复之间有布局间隔 → 在稳定帧后依据最新指针重新命中，高亮与确认使用同一判断；立即释放、取消、多指和后台中断不得产生意外改期。
- 窄屏可能使年月标题、错误重试和展开入口抢空间 → 保留可点尺寸，利用原标题行的弹性区域，不覆盖网格；用短屏和放大文字夹具验证。
- 下属路由共用组件 → 在交互入口和确认边界都守住只读限制，保留合法评论，不依据任务自身可编辑字段绕过来源权限。

## Migration Plan

仅随 Flutter 客户端发布，无数据或服务端迁移，无新持久化偏好；回退客户端版本即可撤回这些交互变更。
