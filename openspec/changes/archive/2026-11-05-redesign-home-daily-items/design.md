## Context

动机与最终范围见 proposal.md，验收契约见本 change 的 delta spec。以下为已只读核对的现状：

| 区域 | 当前实现 | 本次影响 |
| --- | --- | --- |
| 导航 | `潘多拉-交互原型.html` 的五页入口、`潘多拉-交互原型.js` 的 `PAGE_TITLE`，以及 `潘多拉-api.js` 的登录/加载文案 | 更新可见名称，保留内部 map/view 页面键和路由，减少对原任务日历的耦合 |
| 首页 | `潘多拉-工作区接入.js` 覆盖 `renderMap`，渲染四个 quad；`潘多拉-正式版.css` 固定两行两列，`潘多拉-手账主题.css` 追加主题覆盖 | 改为两张上方卡片和下方通栏每日事项；必须同时处理最终生效的样式，不能只改基础 CSS |
| 任务看板 | `WorkspaceService.homeRead` 读取 active assignment、未完成、已有有效版本，额外排除 `original_creator_id=本人`，按 assigned_at 倒序、任务 ID 稳定限十条 | 删除创建者条件，保留真实负责关系及有效发布边界；界面紧急程度仅展示 |
| 个人事项 | `home_items` 混放 company/personal；个人项无日期/完成状态，有 sort_order、row_version，正文上限2000、总量十条；`/home/items` 提供 CRUD | 每日事项使用独立模型，现有公司信息不改为个人日历；退役 personal 写入路径 |
| 首页读取 | `/home` 同时返回 companyItems、assignedTasks、personalItems、recentLogs、businessDate；`P.reload` 直接映射 personalItems | 切换首页响应和映射；移除首页日志查询，不移除本人日志页及公司页使用的日志数据 |
| 任务月历 | `潘多拉-日程视图.js` 集成纵向月流、任务跨度、拖动、端点、小时轴、密度、日志和审批投影 | 每日事项不基于该渲染器改造，只共用纯日期工具及现有弹层基础设施 |
| 写入基础 | `WorkspaceController` 通过 `Writes.run` 执行幂等、会话/组织校验；更新删除用 If-Match，详情返回 ETag | 每日事项沿用同一写入基础，不自造本地持久化或完成切换命令 |
| 实际检查 | `check_home_integration.py` 等历史入口已委托给当前套件，`check_fixed_web.py` 驱动 `check_fixed_employee_browser.js`；管理端十条限制在 `check_admin_contract.py` | 更新实际执行的断言，新增有行为价值的每日事项专项；旧四象限 PASS 不能作新页面证据 |

当前最新数据库迁移为 V28。暂缓 change 计划新增日志标签和私人标签清理迁移、修改工作区文件，尚未实施。本 change 不依赖其结果；迁移号按实际落地顺序分配，禁止两者占用同一版本或编辑历史迁移。

## Goals / Non-Goals

**Goals:** 每日事项有独立的存储、读取范围、日期状态与横向滚动容器；数量汇总不受清单分页影响；日期和完成状态维护具备与项目一致的版本和幂等保证。首页去掉日志后不再为该卡片查询近十天日志，任务看板可准确纳入本人创建并负责的任务。

**Non-Goals:** 不扩展任务系统为通用 todo，不给每日事项添加审核、时刻、重复、提醒、标签、评论或共享，不引入外部日历库；不重写公司页日历。旧个人事项为非生产数据，用户明确无需迁移保留；不建设旧数据补日期向导或旧客户端兼容层。原生 Android、旧套壳资源与 APK 构建不在本次交付范围；独立管理端公司信息不随首页改名而重构。

## Decisions

### 1. 页面键保持，首页用三个模块重新布局

保留 map/view 内部键与原页面挂载点，更新员工 Web 导航、标题、可访问标签及登录/错误/加载等当前可达静态文案。“公司”仍是现有个人任务日历入口，不意味着全公司可见；人员工作页中“日程”作为具体业务功能名称可以继续存在，不做全文字符串替换。

上方事件纪和任务看板保持原左右顺序和各自滚动，下方每日事项 `grid-column: 1 / -1`，占据下半部分主要空间。移除 logs-quad 及空位、原个人事项列表和新增按钮，重设 map-grid 行定义。正常屏幕优先同屏容纳两层布局；短屏保留每日事项七行的最小可用高度并允许主内容纵向滚动，禁止用裁切强行满足旧的整页不滚动约束。横向滚动仅发生在每日事项区域，固定左侧星期表头不跟随。

任务看板沿用当前 SQL 查询，移除 `t.original_creator_id<>?` 及对应参数，显式维持已有有效版、active assignment、execution_state 非 done 条件，按 assigned_at DESC、task ID ASC 取十项。核对当前正常发布可见性，不能通过本次放宽创建者条件纳入未发布或历史只读任务。本人创建后成为负责人也应具有真实 assignment；不以任务创建时间伪造派发时间。

备选为全局更名内部页面键及替换全部“日程”字符串，会额外扰动任务和人员返回路径，因此只改入口显示。保留四象限空卡片则与三模块要求冲突。

### 2. 独立 daily_items 表，旧 home_items 只保留公司信息

新增 `daily_items`，保存 id、organization_id、owner_id、item_date（DATE）、body（TEXT，接口限2000字符）、completed（布尔，默认 false）、row_version、created_at、updated_at。添加组织内账号复合外键及按 `(organization_id, owner_id, item_date, created_at, id)` 查询的索引；无 task_id、work_log_id、标题或 sort_order。日期、正文和完成状态同事务更新，修改成功递增版本；完成使用“设为 true/false”的明确赋值，不使用服务端 toggle，以便重试。

使用下一号新增 Flyway 迁移创建新表，并明确清理 `home_items WHERE kind='personal'` 的旧非生产数据，不填造业务日期，不动 company 行、任务、日志或既有审计；旧迁移 V1/V3 不改写。关闭 `/home/items` 的 personal 创建/编辑/删除路径，保留公司信息读取和原管理员维护路径；员工仍不能写 company。不强制收缩 home_items 表结构，避免无必要影响管理端。

独立表比在 home_items 追加大量仅 personal 适用的可空字段更容易保证私有范围与日历查询，也避免 company 的十条上限和 sort_order 混入每日事项。用户已明确不需要旧数据保留，因此不增加回填和双写方案。

### 3. 日期计数和分页清单分开，全部读取由服务端限定本人

新增 `/api/v1/daily-items` 系列接口：

| 操作 | 输入 | 输出/规则 |
| --- | --- | --- |
| GET `/daily-items/summary?from=YYYY-MM-DD&to=YYYY-MM-DD` | 含首尾的合法日期范围，最多93天 | 范围及按日的 openCount/completedCount；成功响应中未出现的日期表示零，失败不缓存为零；只计本人全部事项 |
| GET `/daily-items?date=YYYY-MM-DD&limit=50&offset=0` | 单日、分页，limit 1–100 | items、total、分页信息，按 created_at ASC、id ASC；不以状态重排 |
| GET `/daily-items/{id}` | 真实事项 ID | id、date、body、completed、rowVersion及 ETag；不附任务/日志对象 |
| POST `/daily-items` | date、body | id、rowVersion；默认 completed=false，无十条总量/单日上限 |
| PATCH `/daily-items/{id}` | date、body、completed 的允许子集 | 原子保存、递增版本，completed必须为布尔；省略字段保持原值 |
| DELETE `/daily-items/{id}` | 指定目标与版本 | 删除该项并返回明确结果 |

日期仅接受有效 ISO 公历日期，JSON 以 YYYY-MM-DD 传递；不通过 UTC 午夜时间戳往返日期。默认公司今天来自已有 businessDate，日期工具不依赖设备时区。正文按项目既有空白校验和2000字符约束，返回时保留内部换行。未知字段、taskId、authorId/ownerId、subjectId 等不允许成为改写或查询他人的入口。

新增独立 `DailyItemService`，在 `WorkspaceController` 增加对应路由；服务端员工业务资格、会话、同组织和 owner=actor 过滤对 summary/list/detail/write 一致执行，管理身份也不能越权读取。所有写入通过 `Writes.run`，PATCH/DELETE 以打开时 ETag 校验；重放仍按现有会话/组织边界，删除成功后相同幂等键重试可重放，不在控制器强行先读已删除行而阻断重试。未知/他人 ID 使用项目一致的不可读响应，不暴露存在性。

内部如记录必要审计事件，只带事项标识、动作元信息，不带正文、不投递收件人，不生成任务/日志业务事件。列表的 items/total 应为同一读取快照；分页期间出现并发创建/删除后重新读取并按 ID 去重，不把旧 total 或旧 offset 结果当作最新完整清单。

不将所有事项塞入 `/home`：保留 companyItems、assignedTasks、businessDate；移除 personalItems、recentLogs 及其专用查询。`P.reload` 不再构造 PERSONAL_STATE；公司页/日志页实际使用的 work-logs 读取仍保留。summary 按月及邻近范围加载，详情和日清单按需读取，避免取消上限后首页变成无界全量查询。分页列表与精确全日 summary 分开，避免把首50条当当天总数。

### 4. 用独立横向日期流实现轻量日历

新增 `潘多拉-每日事项.js` 和专用 CSS，加入 HTML 引用、缓存指纹及 Maven 静态资源白名单。以周一为每周起点，一列七个日期、一行对应一个星期，左侧表头固定。日期列按真实连续周序列生成，按月加载数据而不是把每月补满的相邻日期格重复挂载；同一日期只出现一次。跨月共享同一周列时，每格仍带完整日期标识，月初/跨年边界显示简短年月，顶部显示当前锚点月份。

横向滚动采用浏览器滚动和触摸惯性，接近左右边缘时追加或前插相邻周/月范围；前插按原锚点日期及像素偏移补偿位置。DOM限制在邻近窗口（例如最多12个月），移除远端时同样保持锚点；未挂载月份可再次加载。年月定位、上一月/下一月及回今天是额外可访问入口，不替代连续滑动。日期格和月份控制支持键盘操作及可读名称；识别滑动阈值后抑制click，不能把横滑落点当日期点击。

组件维护独立 `selectedDate`、`anchorDate`、横向偏移、已加载范围、请求序号、日清单和弹层状态；不复用 state.viewDate、monthHeight 或任务月流。仅共用纯日期格式/公司今天工具、认证请求、弹层和焦点设施；不导入任务事件布局、拖动及日轴。

每个日期格下预留固定标记行：蓝在前、灰在后，各色宽度用 `n=clamp(count,1,5)` 映射，高度例如4px、1条宽4px、每档加3px、5条及以上宽16px、圆角为高度一半。混合状态最大共34px（含间距），置于有足够宽度的日期格内；0项不渲染对应颜色，保留标记行高度。最终尺寸可随主题微调，但0/1/2/3/4/5+映射、等高及双状态并列规则不可改变。`aria-label` 提供完整日期及精确蓝灰计数。

备选为将任务月历转置，会把跨度、密度和拖动等无关特性一并带入；整月翻页控件又不满足连续滑动，因此采用纯日期列流与独立汇总。

### 5. 清单、详情、编辑按层返回，成功后回读受影响日期

点击日期后用现有 sheet 基础打开当天事项列表；保留完成项和未完成项的创建顺序，行内 checkbox 显示完成状态，文字打开只读详情，checkbox 阻止冒泡。清单提供按该日新增及分页加载，详情只有日期、纯文本、完成状态和编辑/删除等必要动作。创建/编辑为日期输入和正文，删除确认独立，完成/取消完成也可在详情操作。

悬浮加号固定在每日事项卡片可视区域右下方，底部和右侧留出内容安全空间，不固定到公司页或覆盖主导航。默认当前选中日；未选择时公司今天。详情/编辑/确认沿 sheet 栈只退一层，保存清单滚动与焦点来源，关闭清单恢复原日历横向锚点；改日期后刷新原日和目标日但返回原日清单，用简短结果告知目标日期。

保存草稿包括 epoch、itemId、读取版本、原日期、拟保存日期/正文、mutation slot，完成操作保存明确目标布尔值。成功后按旧/新日期失效 summary 和清单缓存并回读，防止局部减加与并发修改误计数；回读失败保留成功结果并提供刷新，不能误报写入失败而再建一条。更改/删除前读取真实版本，冲突保留草稿并要求处理，不无提示改成最新版本重试。

查询缓存按组织、账号、会话 epoch 和日期范围区分；请求序号隔离快速切日、滚动补载及关闭弹层后的响应。成功写入后的旧 summary 请求不得倒灌，相关范围需递增查询版本。切换主页面保留当前账号每日事项位置，但退出/失效/换账号立即清理状态、弹层、版本及缓存；迟到响应丢弃。

### 6. 验证当前执行路径并协调暂缓 change

保留 `check_admin_contract.py` 的公司信息十条和只读检查；更新 `check_fixed_employee_browser.js` 中旧四象限、个人项十条及首页日志断言，旧验证报告不改写。新增每日事项 API 与浏览器专项，复用隔离 fixture、真实认证和实际后端；必要单元验证日期/分组/版本权限边界，浏览器验证真实布局、横滑和返回行为，不以字符串匹配代替交互验收。构建后通过服务实际读取新增 JS/CSS，核对 Maven 白名单和资源指纹。

本 change 可先独立实施，不编辑暂缓 change 的规划文件。后者的日志多标签任务不再包含首页近期日志卡片；若后实施，合并 `潘多拉-工作区接入.js`、`潘多拉-api.js`、工作区服务及检查时以本 change 的三模块及独立事项契约为准，不恢复旧 personalItems/recentLogs。保留公司的任务日历和任务权限测试作为回归。

## Risks / Trade-offs

- [任务看板误把“当前负责”扩大为全公司可见] → 保留 active assignment 和正常发布检查，只删除创建者条件；自建负责、他建负责、仅创建、已移除、已完成及未发布一起验收。
- [取消上限后计数仅含首屏或前十条] → summary用数据库全量分组计数，清单分页单独取数，验证同日超过100条及全部完成/混合状态。
- [星期转置或跨月共享周造成漏日/重日] → 按连续周列构造，按真实日期去重，覆盖月初星期日、跨年及闰年二月，前插/裁剪保持日期锚点。
- [蓝灰两段在窄格挤压或触摸目标过小] → 每格保留足够列宽与至少44px交互区域，小标记不承担独立点击，窄屏用横滑容纳；短屏允许页面纵向滚动。
- [完成/移日后旧响应把标记改回去] → 写入使受影响查询版本失效，成功回读服务端汇总，不使用缺少版本的乐观累计。
- [借上级或管理员范围读取私人事项] → 无 subject 参数、所有操作按本人组织和ID过滤，检查同级、上级、独立管理员及跨组织请求。
- [新增数据库版本与暂缓 change 冲突] → 实施时按当前最大版本顺延并记录，旧迁移不改；不把另一未实施 change 作为隐含依赖。
- [旧原生客户端读取被移除首页字段失败] → 本次统一 Web/后端新契约，明确记录 Android 后续适配，不声明原生通过、不发布 APK。

## Migration Plan

1. 实施前确认最新迁移号，在隔离库执行新增迁移：创建 daily_items、仅清理旧 personal home_items。既验证从当前 V28 升级，也验证空库全链，核对 company、tasks、work_logs 数据未变。
2. 后端和员工 Web 同时采用新首页与每日事项接口；更新实际 fixture/当前检查中依赖旧个人项的路径和必要说明，避免演示初始化再次插入已退役 personal 数据。
3. 运行 Maven 单元/打包、专项 API 与真实浏览器检查，覆盖320/390/1440及短屏；保留公司页月流/任务创建/日志页和管理公司信息的必要回归。实施记录列明执行证据、资源指纹、迁移号和原生端未适配范围。
4. 本轮不执行部署。后续如需回退，应成套恢复对应前后端构建及迁移前数据库备份；清理的非生产个人项不提供在线逆向恢复，不通过破坏性降级脚本冒充无损回退。
