## Verification Reminders

- **Native Android / old shell are not adapted.** `/home` no longer returns `personalItems` or `recentLogs`, and `/api/v1/daily-items` plus its summary/list/detail/write contract are new. `android/` and `android-shell/` were not edited and no APK was built; native models/requests and the home contract still need a follow-up change.
- **Deferred change coordination.** `refine-notifications-task-editing-and-staff-browsing` shares `潘多拉-工作区接入.js`, `潘多拉-api.js`, `WorkspaceService.java`, `WorkspaceController.java`, `backend/pom.xml` and check files. When it is implemented it must keep the three-module home and the independent daily-item contract, must not restore `personalItems`/`recentLogs`, and must drop its home recent-log tag adaptation. Its planned migration must start at **V30**; V29 is taken and historical migrations were not edited.
- **Irreversible cleanup.** V29 deletes `home_items` rows with `kind='personal'`. The user explicitly confirmed these are non-production data and no online reverse migration is provided; a rollback needs a database backup.
- **Layout coupling.** The home page fits the standard 844px phone because `潘多拉-每日事项.css` overrides `.app-main.is-map` and `#page-map.is-active` with ID specificity and uses a fixed 165px upper row plus a 330px calendar (7×44px rows, 22px month head, 52px reserved for the FAB). Any future change to `.phone` max-height, `.app-main.is-map`, or the task cards can reintroduce clipping; rerun the 320/390/1440/short checks.
- **Sparse summary semantics.** Dates absent from `summary.days` mean a confirmed zero for that closed range; a failed request must not be interpreted as zero. The UI shows a month-level retry on failure and no markers while loading.
- **Scroll restoration is date-anchored.** `restoreScroll` relies on the leftmost date plus pixel offset, retries across layout frames, and ignores scroll events while the map page is hidden (`clientWidth === 0`). The browser suite covers a page switch and an account switch; unusual focus/scroll combinations should be rechecked.
- **Demo data.** `DemoSeed` now creates three daily items per employee (one completed); `check_final_demo.py` passed. Any manifest consumer that assumed personal items must be checked separately.
- **One flaky regression.** `check_calendar_drawer_browser.js` failed once on its CDP drag-the-handle-down assertion and passed on an immediate rerun. The company-page drawer code was not modified; treat that assertion as pointer-timing sensitive and rerun once before reporting a failure.
