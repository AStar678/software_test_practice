## Goals / Non-Goals

**Goals:** 在同一应用内按依赖阶段修复 DEV-001—028、030—035；把权限判定、路由、时间和事件语义集中复用，使浏览器、HTTP、调度和重试得到同一结果。每阶段交付端到端能力并留存编号化证据。

**Non-Goals:** 不换技术栈、不拆微服务或引入外部模型；不重演历史提交归档，不改写历史审计结论。依用户本次指示，DEV-029 系统推送、PWA/原生端、HTTPS 部署和 A-25 真机专项延期；保留可扩展事件结构，但本轮只验站内渠道，不能宣称 V2 全量验收通过。

## Decisions

### 1. 保留单应用和事务机制，按依赖阶段落地

依次实现「数据/组织/账户 → 权限 → 路由/申请/交接 → 失效/提醒 → 消息 → 首页/日历/日志/分析 → 集成复验」。不另建重复 capability；delta 完整替换 13 条旧要求、移除 Manager consultation、增加 8 条业务要求。保留主规格路径，apply 更新测试/文档，正式同步规格在后续 sync/archive 工作流执行。

保留 `Writes` 的组织 → 任务 → 申请锁序及 ETag/幂等协议；将组织权限版本带入 Actor/能力快照，在事务内重读权限并检查旧幂等回放。新增管理写入也走相同机制；不采用只在页面上隐藏按钮的授权方式。相对重写状态机，此方案能保留已经成立的竞争控制并降低回归范围。

### 2. 独立组织与能力模型

新增部门、职位、角色定义及角色分配/数据范围；用户持有必填 department_id、position_id，可空 team_id、manager_id、独立组织层级和 reviewer_available。团队引用部门及负责人，团队创建/负责人转交须检查显式团队管理能力；负责人不自动成为有派发权的中层。层级用于审核位置，角色/职位名称不用来推断层级。

授权服务明确区分 `canViewTask`、`canDispatchTo`、`canReadLogAuthor`、`canSeePerson`、`canReadPhone`、`canHandover`、`canReviewRequest`、`canManageOrganization`，并给候选、人员树和分析提供同源范围查询。任务部门从有效负责人部门求交集，创建者/本人负责关系保留；中层日志只比较 manager_id，不借用任务权限。管理员默认只有管理能力，公司/部门/个人员工权限按正式边界配置，不能仅凭资料范围、职位名或管理员身份放开手机号或待创建提议。

组织维护校验公司复合外键、一人单团队/单上级、必填字段、环、团队部门一致及一公司一管理员；变动递增 authz_version、使旧候选和分析失效，并触发待审路线检查。离职只建审核可用性及交接必需处理，不交付完整账号启停流程。

### 3. 账户和资料遵循已确认口径

保留 username、BCrypt 及摘要会话；新增 must_change_password、凭据版本及受限会话能力。新建/重置生成随机初始密码并仅在成功交付时展示，数据库只存哈希；密码值不得进入日志、普通审计、outbox 或幂等响应缓存。采用独立的一次性交付回执：响应丢失不能重复回显密码，管理员可再发起重置生成新密码，不通过缓存存明文恢复。

强制改密由认证过滤器统一门禁，允许本人改密/退出，拒绝其他 API；客户端先完成改密再加载工作区。新密码至少 10 字符、含字母数字且不超过 72 UTF-8 字节；日常改密校验旧密码，首次/重置以受限认证证明并校验初始密码。改密事务撤销全部会话，返回重新登录指引，不签发静默普通会话。保留姓名/邮箱编辑和现有手机号格式校验；管理员写手机号只回执字段变动，不回显号码。

按 2026-10-19 纳入的调整，`GET /api/v1/users/{id}` 先检查当前资料查看权，再单独决定是否返回手机号：本人可读；他人仅限同组织有效员工的实际管理链上级，且调用者组织层级须更高。沿当前 manager_id 链遍历并防环、拒绝跨组织及失效的中间关系；同级、下属、其他管理链或仅有管理员身份不能读取。每次请求重新鉴权，组织变更后旧上级不能继续读取。邮箱仍仅本人可见；目录、任务摘要、日志筛选、通知、分析、审计、outbox 和普通工作区人员缓存不含号码，详情号码不写入普通人员缓存或消息历史 DTO。

“我的”下属资料列表取当前资料可见人员与实际管理链下属的交集，可包含间接下属，不扩大 `profile_read` 本身的范围；`reports` 范围仍只允许直属下属，`company` 范围可展示链内间接下属。人员详情不提供派发入口。日志仍独立调用 `canReadLogAuthor`，中层不能因可见间接下属资料/号码取得其日志权。任务 3.5 重新打开以验证新矩阵，旧的“他人一律不可读号码”证据不证明新规则通过。

### 4. 统一路线计算与可追溯改派

负责人关系增加 ordinal 并设版本内顺序唯一；插入、读取、表单换序、diff 和历史全部按 ordinal。路由返回 `{reviewerId, basisAssigneeId, path, reason, authzVersion}`：最高组织位置 → 同级保存首位 → 其直属链有效审核人 → 原创建者兜底 → 确实无审核人；空负责人/环/越组织等返回错误，不包装为无需审核。废弃共同上级算法及 actor=creator=reviewer 的 direct 分支。

新增只读审核预览（如 `POST /tasks/reviewer-preview`，不生成申请），前端负责人/排期等变更后刷新真实人选；提交仍在事务中重算，预览不作授权凭证。创建/负责人变更/交接采用 proposed，其余采用 current；详情同时给当前任务与本申请路线。组织维护和扫描通过专用路线刷新事务持久化改派记录、增加申请版本、生成对应事件；GET 不再静默动态算出一个与数据库/通知不一致的人。组织在途变动后决定仍须重验；有链转无链时按无审核人规则留因直接处理，并先做截止校验。

无审核人允许 current_reviewer_id 为空，仅有明确原因的 direct 记录可如此；不创建空审核人的 pending。申请人只返回 proposed、状态和意见，本次审核人另有 comparison/base/diff；原始 base_version_id 等可反查旧值的字段不向申请人暴露。App 不返回完整审计。

### 5. 交接和重开是独立命令

新增专用交接设置与 `handover` 申请种类，授权本人或直属领导为该员工当前负责的任务替换其负责人位置，保留其他人的相对顺序；目标必须同组织、有效且在合法交接目标范围。负责人候选与普通派发接口分别鉴权，不能借交接修改标题/排期。交接来源、被交接人、设定人及审批人落记录；批准时再次检查专用资格和新路线。

重开仅原创建者发起，可提供完整定时/全天排期字段，复用表单验证；生效时在同事务更新排期、执行状态 doing 及 execution_round。保留原创建者/创建时间，退回/撤销/失效都不增加轮次。有效版本语义、完成退回 doing 与撤销恢复 previous_state 的差别保留。

### 6. 截止校验与调度共用受控时钟

注入统一 `Clock`，提供组织时区业务日期；测试用可控时钟，不修改操作系统时间。集中计算 applicableDeadline：create 或实际排期变更用 proposed D，否则 current D；提交时 `now >= D` 拒绝，pending 在 `now >= D` 失效，逾期提醒在 `now > effectiveD`。零工期不发比例提醒。

抽取 `expirePending` 业务事务，供提交前、决定前与扫描调用，保持组织 → task → request 锁序、状态条件更新和唯一终态。**过期状态必须提交后才返回业务错误**：避免在同一个回滚事务内先失效后抛异常导致失效记录消失。API 可由外层事务编排先提交失效结果再拒绝决定，后端响应返回最新终态供前端刷新。竞争检查在获得锁后取当前时刻；重复运行不重复事件/解冻/逾期。

扫描顺序为路线刷新/过期处理 → 常规提醒 → 事件投递/消息清理；每个阶段边界重新检查当前状态。expiry 更新申请与提议版本 expired、解冻但不发布提议，保留有效版与原执行状态；创建不发布，重开仍 done。已生效未完成任务已逾期则另记 overdue 事件，可在展示摘要中合并说明但不可吞掉两类记录。

用 schedule_version 替代仅截止变化的 due_version 语义：S/D/全天/业务日期实际变化生效时递增；同内容变更、进展不递增；重开另增 round。公司下班时刻默认 18:00，作为每次排期提交时快照保存；设置修改应用于之后的新排期/排期修订，不静默改写已有或在审排期，管理页明示生效范围。已有任务需调整时通过正式排期修订以重算提醒和截止，避免设置保存瞬间使旧申请无记录失效。

提醒键包含 org/task/recipient/round/schedule/node，node 为 20/10/5/overdue。迟到扫描选择最近已到节点，并记录更早节点已跳过，避免下一次补发旧节点；后续节点照常发。提醒账本和事件同事务；排除完成、pending、未发布和已撤权接收人。

### 7. 明确事件、消息副本与历史只读边界

扩展事件：initiator、task、request、有效/提议版本引用、发生时间、标题和可公开变动摘要、接收原因；操作历史保存授权后的字段前后值，有序负责人差异不丢。消息副本绑定 event_id/request_id、delivered_at、read_at、hidden_at、expires_at、版本号；事件级 revoked_at 区分全事件撤回与个人删除。消息打开用受保护的幂等 open 命令自动标已读再返回详情；普通列表 GET 不改变状态。旧审核消息只查自身 requestId，不按 taskId 搜任意 pending。

事件接收矩阵直接按正式版 5.6.1 落实；已发布申请提交仅本审核人，申请人从独立申请跟踪；创建未发布结果仅申请人/审核人；生效后再通知任务人员。一次操作多字段生成一条事件摘要，event+recipient 唯一。改派、失效、交接建立专用类型。移除负责人事件可依据已生效变更的旧负责人事实向被移除者投递变更通知；不能仅凭任意 recipients_json 就赋予查看权。

投递时重新核对事件可见性：普通尚未送达消息在收件人失去权限后不下发受限内容，不提前授予历史入口；专门移除事件验证旧有效负责人事实后实际送达，方创建受限历史入口。待创建仍只可给申请人/指定审核人。已送达消息不因后来撤权从收件箱消失。

新增 `/notifications/{id}/task` 专用只读 DTO：要求本人有效已送达消息、有已发布任务，逐次检查隐藏/撤回/保存期；失权时显示说明，仅返回当前有效资料及可独立授权的关联摘要，不返回 proposed、diff、敏感联系信息、操作能力或日志。不将历史任务写入客户端正常 TASKS 集合；普通 `/tasks/{id}` 保持正常权限，其他查询不反向扩大。

保留期以事件 occurredAt 转公司时区加三日历月，自动月末截断，`now >= expiresAt` 即终止入口；清理调度可稍晚但读接口不能等清理才封锁。撤回校验事件发起人/管理员及 `0 <= now-occurredAt < 180s`，不以 worker 投递时间延长窗口。全事件撤回禁止后续正文投递，对副本显示占位；副本删除只影响本人。清理删除消息正文/副本，不删除业务版本、申请或审计。

### 8. 统一实际页面数据来源和日历算法

保留 `4247dcc` 已加入的表单与通知列表调整，并从实际加载的后端接入页面验收：任务说明及完成标准 textarea 最小高度为 234px；写/编辑日志使用占满可用容器的全屏弹层和伸展正文区；通知列表不再提供底部刷新/关闭按钮，保留头部关闭入口。弹层切换须正确复原全屏样式和页脚状态；键盘 Tab 焦点包含头部关闭按钮，空列表也可退出。通知列表的简化不取消后续的自动已读、删除/撤回或原申请绑定要求。新增任务 11.7 记录这批代码的构建后浏览器回归，未执行前不标为验收通过。

首页直接使用后端 assignedTasks；新增 task_assignments 的接收人派发时间，首次创建生效/新加入负责人记录，未移除者仅换序不重置，移除后再加入产生新派发。取本人被他人派发且未完成前十项，后端排序、前端不二次重排。个人条目新增只读详情层，复用现有本人 CRUD 与十条限制。

日历集中由 `潘多拉-日程视图.js` 负责，清理前置旧函数的竞争覆盖。侧面板、搜索、本人申请、悬浮按钮及条件返回按规格完成。置顶新增 user/task 偏好，仅影响本人月格和日列表；同组按 startAt/ID 排序，真实时轴不位移。

月条按公司时区日期相交分周，容量为不超过五条且按可用高度计算，标题 CSS clip，日期格打开完整当日列表；保留精确隐藏集合及跨周跨度。周/日只对 allDay=true 放全天区；定时按每天 `[00:00,next00:00)` 裁分，午夜终点不产生次日空块。使用固定可读小时高度及纵向 overflow:auto，取消 fitSchedule 的压缩、cap 和 +N。按真实相交区间分组、列复用并按组完整列数算宽；点击热区与真实时长标记分别处理但不能覆盖他项。高密度浏览器案例逐个点击，真机密度体验另记延期，不能借延期恢复聚合。

日期行单独处理 pointer/touch 水平意图、松手阈值和整周对齐，竖向意图交由滚动；切日模式整周保持 weekday，日期点击与任务点击分离。范围计数采用去重 taskId 和互斥关系分类，月数量按自然月边界而非网格相邻月填充；待完成数量与 done/overdue 独立，标签可读且非纯色。

### 9. 日志和分析复用当前权限

日志新增 `(organization_id,author_id,business_date)` 唯一约束；create 仅公司 today，已有返回可编辑记录指引/冲突；update 禁止变日期；所有 edit/delete 在锁后检查 today==businessDate 及午夜冻结，safeLog.editable 同源计算。树/姓名搜索用专用日志作者范围；加载默认 self，不在 render 时清条件；申请移到视图、审核移到通知。

统计与词云范围、建议范围分别由后端按角色/授权裁剪，中层可见部门统计但个人建议不能沿用 visible。统计复用正常有效任务查询，增加紧急分布和 pendingComplete，排除已完成逾期。词云由标题/说明实际分词、停用词及频次提取，优先可用中文分词能力并为未登记新词提供真实文本提取策略，不用旧固定 KEYWORDS；具体词数/字号可作为实现细节。临期算法与提醒复用，冲突按相交排期，高紧急提示独立；进入/刷新重算而非静态生成按钮。记录来源/权限版本/生成时间，读取旧分析再次鉴权，剔除或拒绝失效结果。

## Risks / Trade-offs

- [旧数据缺真实部门、职位、负责人顺序及派发时间] → 执行迁移预检及有来源的回填，缺失明确报告，不编造历史。旧的有效结果不按新算法追溯撤销。
- [重复日志与唯一约束冲突] → 输出重复集并暂停该约束启用；提供保留全部原文的合并/冲突归档方案，经管理修复后再建约束，不静默删除。
- [过期错误导致整个事务回滚] → 终态提交与错误响应明确分层，测试确认失效落库、解冻及事件在异常路径仍成立。
- [历史消息例外扩大普通权限] → 专用 DTO/入口及独立负向权限矩阵，客户端不把该任务合并进正常集合；未送达与移除事件分开核验。
- [一天全量分栏在窄屏极密时难点] → 浏览器验证全部可点击与准确时段，保留真机项延期；若以后需要替代布局，另提设计变更，不能自行聚合或声称真机通过。
- [同组织写事务串行影响吞吐] → 沿用当前小规模设计，本轮保证正确性，不把组织锁改为未经验证的新并发模型。
- [后台及新静态资源未被 Maven 打包] → 更新明确资源白名单并在打包后的实际入口验收，避免只检查根目录文件。
- [尚未实现系统推送] → DEV-029 和 A-25 继续列为延期，不能作为本轮闭环或全产品验收 PASS；后续优先评估 PWA/Web Push。

## Migration Plan

1. 在隔离副本预检 V1—V4 数据，保存行数/约束/指纹及备份恢复证据；仓库 SQL 快照仅在空测试库恢复，不覆盖用户数据库。实现新 Flyway 迁移，不修改旧校验和。
2. 扩展可回填列及组织/授权/消息/偏好表；按明确管理配置建立部门与职位映射，禁止把旧 team 无条件认定为真实部门。缺映射或重复数据生成可审查报告，未解决不启用正式写流程。
3. 负责人旧顺序先依据可证明的原请求/版本资料回填；无法恢复时记录 legacy-order-unknown，用旧查询确定性顺序作兼容读并由首次正式编辑明确保存，不宣称恢复了真实提交顺序。旧待审需重算新路线并记录 migration reassignment；已到期立即失效，不 retroactively 改动历史已生效结果。
4. 派发时间优先采用可追溯的版本生效/负责人新增记录；无法恢复时标记时间来源为 legacy-estimate 并明确兼容排序，之后真实新派发必须精确记录。旧通知从可证明的 domain_event/request 绑定迁移，禁止按当前同 task 的 pending 猜配；无法绑定的旧审核消息只读且不提供审核按钮。
5. 对重复日志保留原记录/原文及冲突来源，在隔离迁移演练中形成无损归并结果，再加唯一约束与非空/顺序约束；不能恢复的历史摘要如实标缺，不用新数据反填伪造旧通知。
6. 发布时暂停写流量/worker，备份后应用已验证迁移，部署后端及构建资源，再启用过期、提醒、投递和清理。冻结现有全天排期快照，设置变更仅影响后续排期修订；校验旧幂等回放不能绕过新权限/旧免审。
7. 运行迁移副本、真实 API、受控时间/竞争及浏览器复验，记录当前 commit、迁移版本、DEV/AUD 场景和产物路径。失败先停新写/worker；优先前向修复，确需回滚时恢复成对的备份与旧程序，避免旧程序写入不认识的新状态。
