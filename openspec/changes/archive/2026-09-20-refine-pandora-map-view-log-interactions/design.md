## Context

参见 `proposal.md` 的动机与 `specs/pandora-requirements-aligned-prototype/spec.md` 的行为约束。当前原型是无依赖的单文件应用：`.app-main` 统一承担纵向滚动，导图象限仅设置最大高度；视图以固定 104px 日期列形成可横向滚动的日历，并按截止日把任务压入单元格；日志页将审核、请示、自建任务和日志列表依次渲染。任务数据已经包含 `start` 与 `due`，公司和个人信息也已有内存状态，因此本次不需要改变实体边界或引入依赖。

原型需要直接打开运行，并在桌面手机外框以及 375×812、390×844、430×932 移动视口中保持可用。页面操作仍只在当前会话内生效。

## Goals / Non-Goals

**Goals:**

- 让导图在任意支持视口中稳定占满业务内容区，并把滚动严格限制到各象限内部。
- 用真实起止时间驱动响应式类甘特布局，使月、周、日视图在不横向滚动的情况下表达任务跨度。
- 为视图下钻、返回和时间范围切换建立单一状态模型，避免任务点击与背景点击冲突。
- 将日志页内容切换收敛为单选筛选，同时保留现有命令、权限和工作流。
- 保持键盘操作、焦点可见、非颜色区分及现有任务/日志详情入口。

**Non-Goals:**

- 不引入第三方日历或甘特图库，不增加构建步骤或服务端存储。
- 不修改任务、日志、审核、通知或请示的权限规则与生命周期。
- 不为任务提供拖拽排期、缩放、依赖连线或视图内编辑。
- 不改变导图之外页面的通用纵向滚动，也不改变其他列表的排序规则。

## Decisions

### 1. 按当前页面切换主内容区的滚动责任

导图激活时，`.app-main` 使用隐藏溢出，导图页和四象限网格均以 `height: 100%`、`min-height: 0` 参与纵向 flex 布局；网格使用两列两行且每行 `minmax(0, 1fr)`，每个 `.q-body` 使用 `flex: 1` 和 `overflow-y: auto`。离开导图后恢复 `.app-main` 的纵向滚动。

这比给象限设置固定像素高度更能适配预览栏、手机外框和不同屏幕高度，也能保证头部与底部导航不移动。导图末尾的说明卡直接移除，而不是仅视觉隐藏，避免它继续影响布局和无障碍树。

### 2. 信息条目使用同一套受限 CRUD 交互

公司信息和个人信息的象限标题区各提供添加按钮；每条记录提供编辑和删除图标按钮。公司信息操作继续由上层权限守卫，个人信息操作只作用于当前身份。添加按钮在达到 10 条时禁用并给出上限说明，保存处理仍再次校验长度，避免只依赖界面状态。

个人信息首次发生新增、编辑或删除前，先把日志派生摘录物化为当前用户的可编辑数组；之后的变更不回写日志。删除使用现有对话框容器进行明确确认，避免窄屏中的误触。备选方案是长按或滑动删除，但其可发现性与键盘可用性较差。

任务格移除自身及备注的裁切规则，元数据允许换行，任务项按内容自然增高；溢出由所属象限滚动区承接。

### 3. 用范围归一化和任务泳道绘制类甘特条

新增视图专用排序与范围计算，不复用当前供其他页面使用的 `sortTasks`：

- 排序键依次为 `due - start` 降序、紧急程度序值升序、`due` 升序，最后以任务 id 保证稳定顺序。
- 对每个视图先计算 `[rangeStart, rangeEnd]`，只保留与范围相交的任务。
- 每条任务将开始和结束时间截断到当前范围，再换算为 0% 到 100% 的 `left` 与 `width`；条形本身严格表达时间跨度，文本标签在所属泳道内换行并限制在图表边界内，不通过扩大条形伪造时长。

月视图仍按自然周分行，每一行以七天为横轴；跨周任务在相交的每一周生成连续分段。周视图以七天为横轴，日视图以 24 小时为横轴，并使用较疏的主刻度标签保持手机宽度可读。每个任务占独立泳道，按上述顺序从上到下排列；只有视口高度策略限制同一周行可见泳道时才把剩余项聚合为 `+N`。本人负责与本人派发继续使用文字标签和实线/虚线边框双重区分。

备选方案是压缩现有固定宽度日期格，但这仍按截止日期而非任务跨度表达信息，且缩窄后文本更难阅读。使用 SVG 也能画条形，但 HTML 按钮与 CSS 定位更容易复用现有任务详情、换行和键盘焦点行为。

### 4. 视图粒度由背景下钻与层级返回控制

移除月/周/日分段控件，保留 `viewMode` 与 `viewAnchor`，并让二者只通过以下路径改变：

- 初次进入视图页为当前月；年月选择器直接更新月锚点。
- 月视图的每个自然周背景携带周起始日期，背景点击进入该周。
- 周视图的日期背景携带具体日期，背景点击进入该日。
- 周视图上一个/下一个移动 7 天，返回时进入包含当前锚点的月份。
- 日视图前一天/后一天移动 1 天，返回时进入包含当前锚点的自然周。

任务条和 `+N` 是独立按钮并优先处理事件；背景处理只接受背景自身或明确的空白命中区，因此不会在打开详情时同时下钻。年月选择器采用弹出面板，包含年份调整和 12 个月网格，能直接跳转而不要求逐月点击。

### 5. 保留并更新视图主体上方说明板块

现有范围/图例卡继续位于类甘特主体之前，并根据当前粒度展示时间范围、我负责/我派发的边框含义和“跨度、紧急度、截止日期”的排序规则。导航按钮与年月选择入口也放在该区域，但与说明文字形成独立工具栏，避免遮挡或使标题跳动。视图页不再渲染底部“本范围内任务”列表；任务详情统一从甘特条或 `+N` 弹层进入。

### 6. 日志页将命令与单选内容筛选分离

状态增加 `logFilter`，允许值按身份动态派生。`logs` 始终是默认值；切换身份时重置为 `logs`，当前值在权限或数据变化后不可用时也回退到 `logs`。

功能板块分成两组：写日志、创建/派发任务、发起请示等按钮仍直接打开表单；日志、待我审核、我提交的自建任务、我的请示、待处理请示使用单选语义的筛选控件。渲染时只生成所选筛选对应的一个列表，零条记录显示局部空状态。审核动作完成后保留“待我审核”筛选并刷新其计数和列表。

备选方案是保留所有区块并用锚点跳转，但这不满足单选内容呈现，也无法降低长页面的扫描成本。

### 7. 回到顶部跟随日志页滚动容器

继续使用 `.app-main` 作为日志页滚动容器。仅当日志页激活且滚动距离超过一个小阈值时，在内容区右下方显示带可访问名称的上箭头图标按钮；点击后将 `.app-main` 滚动到顶部，不改变 `logFilter`。切换筛选时主动回到顶部，避免新列表从旧滚动位置开始。按钮避开底部导航和弹层层级，并在离开日志页后隐藏。

## Risks / Trade-offs

- [固定四象限在极矮视口中每格高度有限] → 保证象限标题固定、内容区独立滚动，并在目标视口逐一验证最小可操作高度。
- [短时任务的真实条形宽度不足以容纳全部文字] → 保持条形时间宽度真实，将标签布局限制在同一泳道和图表边界内，并通过任务点击提供完整详情；不得用横向滚动解决。
- [月视图跨周任务需要拆成多个视觉分段] → 所有分段复用同一任务 id 与样式，点击任一分段进入同一详情，并用边界样式提示延续。
- [背景下钻与任务按钮事件冒泡冲突] → 使用明确点击目标和事件优先级，并增加任务点击不改变 `viewMode` 的交互验证。
- [筛选项会随身份变化] → 每次渲染前校验可用筛选集合，身份切换时显式恢复默认日志筛选。

## Migration Plan

1. 先调整导图滚动容器和信息条目 CRUD，在三个身份与目标手机视口中确认权限、上限和内容完整性。
2. 引入视图专用范围、排序与条形几何辅助逻辑，以新月视图替换固定宽度日期格，再接入周/日下钻、返回、年月选择和前后导航。
3. 移除旧分段控件、横向自动定位和底部任务列表，并确认所有任务仍可通过条形或 `+N` 进入详情。
4. 重构日志页为命令区、单选筛选区和单一内容区，再接入滚动监听与回顶按钮。
5. 直接打开 HTML，在桌面外框及 375×812、390×844、430×932 视口执行规格场景；若需回退，通过版本控制恢复单个 HTML 文件。
