## Verification Reminders

- **Pre-existing check failure:** `check_web_resources.py` reports the stale `潘多拉-每日事项.js` cache-busting query described above. It predates this change (HEAD file hash already `5197767f9526`); the verifier should not attribute it to the admin change, but it will keep that suite at 14/15.
- **Existing handover rule retained:** offboarding still refuses unfinished task assignments (`UNFINISHED_HANDOVER_REQUIRED`); the wizard displays them but does not complete employee-side handover. Pending requests involving the departing employee must be settled or, for their own unpublished creation, cancelled in the offboard request.
- **Legacy takeover tab retained:** "停用与接管" can still stage a deactivation inside a full organization plan. It shares `OrganizationPlans.save` and the same invariants; the new employee-page offboarding is the dedicated route. Task 2.4 only required removing employee creation from the organization-adjustment page.
- **Founder-onboarding edge:** independent onboarding accepts `placementType=founder` only while the company has no founder, so the migration-repair dead end is avoided. The fixture always has a founder, so only the second-founder rejection is executed; the no-founder onboarding path is implemented but not service/browser-tested.
- **Comment coverage:** `taskHistory` now returns comments (including logically deleted ones) so the delta-spec "评论" item stays queryable after soft deletion. Tasks did not list this explicitly; it was added to match the requirement. Only the API check covers the content; the browser history check covers the read-only deleted surface without a seeded comment.
- **Filtering scale:** `/admin/employees` filters in memory over the existing admin directory and has no pagination; this matches the approved design trade-off and was not changed.
- **No founder/identity data invented:** legacy employees keep `idCardNo: null` / `idCardRecorded: false`; the list shows "未设置". Only administrators can read or correct the value.
- **Browser evidence scope:** all browser checks use disposable fixture databases and real Chrome. The real demo database and seeded 12-employee demo were not used for this change; no normal business database was touched.
- **Historical suites updated, not widened:** `check_admin_hire_browser.js`, `check_fixed_admin_browser.js`, `check_admin_contract.py` expected names, `check_employee_contracts_upgrade.py` and `check_organization_plans.py` were updated only for the intentional contract changes (direct onboarding replaces the plan draft; new employees require an identity number). No new coverage was added to those historical suites beyond preserving their checks.
- **Shared error-text changes:** `Writes.checkVersion` / idempotency-key messages and `WorkspaceService` field labels are now Chinese without header/field names. These affect all API callers, but no existing assertion depended on the old wording; the employee copy audit and hire suite still pass. Employee Web/JS was not otherwise modified.
- **Not covered:** concurrent independent onboarding races (the lock/plan concurrency is covered by `check_organization_plans.py`), non-Chrome browsers, and any real-demo DB upgrade beyond the disposable V38 fixture.
