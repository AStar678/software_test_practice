刷新故障目前为用户报告加静态原因定位，尚无本轮浏览器复现证据。2026年10–12月按当前分块合计13周，日期列宽仅598px，加间隔仍不足宽屏；没有溢出则无法依靠后续滚动启动补载。实施时先记录真实刷新路径的尺寸、月份范围和滑动结果，验证该原因并检查是否还存在布局时序或事件绑定问题，不能把推断写成已验证修复。

## Goals / Non-Goals

**Goals:** 让布局根据实际内容行高和容器尺寸工作；每个真实日期归唯一月份；内部日期锚点独立于可见文案；日历在初始布局完成时即可继续向两边浏览。

**Non-Goals:** 不改每日事项存储、接口、完成状态和分页一致性算法，不复用公司页任务月历，不引入日历或视觉依赖，不重排首页任务或事件纪内容。

## Decisions

### 1. 用列表内容高度预算分配上方空间

移除165px固定行上限及会抵消新最小高度的34vh上限。上方两卡同高，内容区扣除卡片内边距和标题后，至少可完整容纳三条普通单行条目；常规窗口以三至四条的高度为目标。采用与实际列表条目行高/间距一致的样式预算，验收以真实边界框为准，不把标题或半条裁切的条目计入三行。长正文继续自然换行并在卡片内部滚动，不保证任意长三条正文全部同屏。

日历保持七个44px日期交互行，去掉底部悬浮加号及52px专用预留；标题区删除锚点副标题并收为一行。短屏优先保留两个区域的可用最小高度，以主内容纵向滚动承接，不通过裁切或压缩触摸目标强行同屏。

备选为直接缩小日期格，会影响七行可读性和触摸；简单按视口百分比分配仍无法保证上方三条，因此不采用。

### 2. 标题、加号和月份工具共用一行

标题右侧紧接新增加号，年月/今天及前后月工具位于同一行右侧。加号沿用工具按钮的圆角、边框和高度，使用半透明薄荷绿底、浅色内高光及轻微阴影表达玻璃感；背景模糊只作增强，不依赖它才看得清。保留清晰的 `新增每日事项` 名称、焦点态和足够的点击区域。

在320px窄屏通过减少空隙和水平内边距适配，不恢复副标题、底部浮动入口或覆盖日期的控件。沿用原 `daily-new` 动作及选中日/公司今天默认日期，保留表单及返回焦点行为。

### 3. 每月独立占据周列，边缘仅留非交互空位

每月从1号所在周到月末所在周构建4–6列，仍以周一至周日为七行。只为本月真实日期创建日期按钮；首尾周的其他位置为不承载日期、无点击目标、键盘跳过的空位。相邻月各自拥有边界周，不跨月共用日期列；月份之间保留稳定水平间距。DOM中的真实日期按时间递增，无重复、无漏日。

年月头左侧与1号所在列对齐，完整显示年份和月份，允许占用后续列宽，不能被单列46px宽度截断；月间距与月头共同避免相邻月份标签碰撞。日期格删除所有1号角标和相邻月日期样式。固定星期表头继续与七行对齐，顶部为年月头保留同高空位。

每月 summary 的读取范围改为本月1日至月末，`blockContaining`、缓存失效和移日后的两月更新按真实日期归属处理；接口和稀疏零计数语义不变。内部 `S.anchor` 由可见月份/日期计算，不再依赖已删除的 `dailyAnchorLabel`；前后月以当前浏览锚点推进，选中日期保持独立。键盘按真实日期移动，跳过空位；月初、月末、闰年、跨年均能继续浏览。

保留跨月共享周的方案无法保证年月头处于1号列上方，也不符合用户要求的月间分隔，因此替换现有分块规则。

### 4. 布局稳定后主动补足范围，所有导航共用补载规则

提取按容器宽度、目标日期/月份与像素偏移补足两侧内容的协调逻辑，由初始渲染、页面刷新、前后月、年月定位、回今天及容器尺寸变化调用。日期挂载且容器可测量后，保证锚点附近有覆盖视口的内容及两侧可滚动余量；初始三个月只作种子窗口，不作数量上限。不能等待首次 scroll 才使日历可滑。

首次进入/刷新定位公司今天所在月份并使今天可见；同会话切页返回优先恢复已保存的真实日期和像素偏移。隐藏或零宽容器延后测量，采用布局帧/尺寸观察触发，限制重试次数并在会话变化或DOM替换时取消过期工作。保留最多12个月的有界窗口、按需summary与失败重试；批量前插/裁剪后按日期位置差补偿，避免依赖旧月份固定宽度。

滚动、补载、恢复与尺寸观察防重入；清理旧计时器/观察器和过期会话回调。删除副标题后仍更新内部月份锚点，不能把标签缺失误作“不需要更新”。

备选为无限预载或只扩大固定初始月数：前者使范围无界，后者不能覆盖宽度变化及隐藏页恢复。只修翻月分支也不能解决刷新后直接滑动的问题。

### 5. 总数决定唯一标记的宽度，状态只决定颜色

复用服务端 `openCount/completedCount`，令总数 `total = open + completed`。total=0不画标记，total>0只画一个；宽度沿用 `4 + (min(total,5)-1)*3` px，高度4px。open>0为蓝色，否则为灰色。用户已确认长度与完成状态无关：1未完成+4已完成与5未完成都为16px蓝杠，5已完成为16px灰杠；单条为圆点。

保留完整日期及精确未完成/已完成数量的可访问名称，不将视觉封顶当数据上限。完成/取消完成只改变颜色所需状态，不改变总数宽度；创建、删除、移日才可能改变宽度。继续用写后真实summary回读、查询版本及会话隔离，不引入本地增减计数或后端total字段。

按未完成数决定宽度会在事项未增删时改变数量含义，与用户本轮确认相冲突；蓝灰并列也明确取消。

### 6. 以直接用户路径更新验收

在现有隔离数据库、真实认证和Chrome专项中增加回归。每个目标视口都从保留会话的真实页面刷新开始，先测滚动范围，再不点击前后月/年月/今天地执行真实横滑或横向滚动输入，验证可以双向越过初始范围；不能预先调用定位动作或只派发合成scroll事件使缺陷自行消失。覆盖320×740、390×844、1440×900、390×600及运行中从窄变宽。

布局用至少四条短条目检查上方三条完整可见，检查标题行、加号颜色/位置、月头与1号列对齐、七行和底部导航可达；保留截图供审阅玻璃感。日期覆盖包含1号为周一/周日、四/五/六周月份、闰年二月和十二月到一月。标记覆盖0/1/2/3/4/5/>5、混合、全完成、完成往返及移日；清单分页不影响总数。

更新旧的双标记、浮动按钮、副标题月份、连续周列和宽屏免滑动断言；继续运行原维护、分页、生命周期、焦点及公司日历回归。归档报告保留为历史记录，新证据归入本 change 的独立目录。

delta保留现有场景标识 `Open an empty day and create with the floating button` 以满足完整替换的校验约束；其WHEN/THEN已改为标题栏加号，该历史名称不要求保留悬浮入口。

## Risks / Trade-offs

- [月边界空位增加横向宽度] → 这是用户要求的分隔；限制DOM窗口，并保持锚点补偿和独立横向滚动。
- [月头文字比单列宽，窄屏碰撞或截断] → 月头在整个月块内排版，起点对齐1号列，检查完整年月和相邻月头边界。
- [移除副标题导致前后月锚点停止更新] → 将状态推导与文案更新解耦，以无副标题的真实交互验证。
- [首次布局/补载时序与切页恢复竞争] → 统一协调逻辑，按会话及渲染代次取消旧任务，零宽延后测量并防重入。
- [三行被误解为三个任意长正文] → 明确以三条普通单行条目验收，长条目保留换行及独立滚动。
- [加高上方卡片使短屏出现纵向滚动] → 接受该取舍，七行日期和标题按钮全可达，不压缩44px目标。
- [旧测试继续鼓励蓝灰并列或仅在翻月后验证] → 与规范同时更新断言，将刷新后首次手势设为独立验收入口。
