动机及范围见 [proposal.md](proposal.md)。本次基于仓库当前根目录 Web 和已归档 A 契约，不等待 Flutter change 完成。

## Goals / Non-Goals

**Goals:**

- 形成真实账号可连续操作的检查路径，覆盖指导12项的本次范围；权限、有效版/待审投影、日期和返回行为一致。
- 月份流共享可复用的日期/几何处理，但首页事项、本人任务、每个人员日程拥有独立数据源和状态。
- 以现有契约交付，错误、失权、未加载、空数据不混淆，旧响应不能污染新账号/查询。

**Non-Goals:**

- 不引入前端框架迁移、全站样式重做或统一所有分页协议。
- 不把资料路径变成授权依据，不把事项变为任务，不用日轴边界限制一般任务排期。
- 不修改现有 Flutter 规划或实现，不改 Android/套壳、不新增震动桥接；设备能力不足如实记录。

## Decisions

### 1. 在现有接入模块内改造，保持业务入口和会话框架

优先修改现有 JS/CSS，复用 `P.request`、`P.mutation`、弹层栈及会话 epoch。若抽出纯日期/月份布局辅助文件，必须同时加入 HTML 顺序、Maven 静态资源和资源检查，不另造全局应用状态。对比整站改框架，该方案将风险集中到本轮明确交互。

每类异步读取绑定 epoch、账号、对象/人员、查询条件及请求序号，关闭/替换来源后丢弃迟到结果。仅同账号有权的已加载内容可作为失败保留；失权立即清除正文。返回保存日期锚点及像素偏移、清单滚动和焦点，不仅保存绝对 `scrollTop`。

### 2. 首页使用预览与完整清单两层状态

`/home` 仍决定事件纪及最多十项任务看板的范围/顺序。卡片约取前三条，取消 `.q-body` 的内部纵向滚动；卡片点击进入对应清单，清单任务再开详情。首页纵向滚动、卡片按下位移和点击分离，键盘激活可用。清单用现有弹层重建机制恢复位置，不在详情关闭时重新打开一份顶置列表。

### 3. 每日事项从范围记录建立纵向月份投影

保留事项 CRUD、真实ID、`startDate/endDate`、版本及重试语义，替换横向布局与 `scrollLeft` 锚点。以公司月历样式构建每周七列、跨周片段、条外可读名称和溢出入口；可复用公司周片段算法，但不能将事项塞入任务集合或引入任务字段。

每个月（含必要网格边界）用 `/daily-items?from=...&to=...&limit=100&offset=...` 读取完整分页；单次窗口不超过93天。原记录可跨更长日期，客户端不截断，跨月缓存按ID合并。未读完或失败不将首屏当全量，不用摘要代替条带数据。按月补载/卸载以控制DOM，滚到边界保持当前日期及偏移；初始化和宽屏不足滚动高度时补足可浏览月份，不限制为静态三个整月。

已加载记录按 `completed/open/overdue` 着色；建议完成绿色、未完成蓝色、逾期红色，落实为可调整CSS变量并同时提供文字/可访问状态，这些色值是实施默认而非用户指定。完成/编辑/删除后按旧、新完整范围失效相关月份和清单，维护现有清单文本/完成控件分离。手机事项区域与首页滚动须实测边缘衔接，不形成无法访问上方卡片的手势陷阱。

### 4. 日志以所属日展示，填充作为草稿内的原子追加

本人及合法人员入口的日期/相对日使用 `businessDate`，排序沿用后端所属日顺序或等价稳定比较；`createdAt` 继续用于详情及冻结，不改保存契约。创建/编辑复用一个填充行为，GET `/work-logs/fill-source?businessDate=D`，只接受完整成功响应。

请求携带草稿/日期/epoch标识；返回前同步当前输入，向最新正文追加“每日事项”“任务”两组原文名称，组内按ID去重，不覆盖用户等待期间输入。按钮在本次请求进行中防重复，之后再次主动点击视为新的追加，不推断或重写用户已编辑文字。若完整追加超过10000 UTF-16单位，整体保留原文并提示，不截断或部分写入；空结果/错误同样保原文。冻结资格按真实 `frozenAt`/当前读回处理，最终写入仍由服务裁决。

### 5. 公司节假日按年懒加载，不参与排期

在日程模块按可见年份读取项目 `/calendar/holidays/{year}`，以年份及账号生命周期管理请求去重/缓存。月格与日标题使用同一映射。stale继续显示旧有效安排；missing及读取失败明确但不阻塞任务，不补造周末“休”。不向外源发移动端请求，不引入新年度数据格式。实际部署须核对来源连通和年度缓存；A 的本地样本通过不代表当前公网抓取通过。

### 6. 拖动采用显式手势状态及日期命中

手势状态为 `idle → pressing → dragging → confirmation`；约500ms前，超过移动容差、第二触点、滚动或取消结束候选，正常滚动/点击保留。激活只调用一次浏览器可用的短震动，提供浮起与目标反馈；不支持或调用被拒绝仍保留视觉反馈并记录实际结果。桌面保持原鼠标和键盘方式。

不能仅在长按后修改 `touch-action`：浏览器会在手势开始决定滚动接管。触摸路径使用能在激活后可靠阻止默认滚动的非被动触摸监听，并与鼠标/笔Pointer路径去重；中断、失去捕获及系统取消统一清理计时器、浮层、自动滚动和点击抑制。通过真实手机浏览器检查滚动与拖动交接，合成事件只做补充。

月历用指针实际位置命中周行/日期列，记录最初抓取日，以目标日差量调整完整任务；边缘自动滚动持续重新命中，并沿用月份补载。拖动期间保证抓取数据及捕获源不会因月份卸载丢失；续接段无伪端点。

日轴保存来源业务日边界，在提议计算、键盘、确认和提交前统一校验 `dayStart <= start <= due <= nextDayStart`，且开始不能等于次日零点；不自动夹紧到边界造成时长变化。00:00–24:00截止允许，整条移动保留工期/分钟，端点保留另一端。来源日约束随轻量排期草稿传递；通用详情排期不带此约束。继续复用原因、版本、幂等和审核，绝不直接保存拖动结果。

### 7. 资料共用路径格式，人员月历共用布局但独立持有月份流

`P.staffOrgLine` 和人员资料/工作页使用真实 departmentName/teamName/positionName，过滤缺层后以“ ▸ ”连接；内部 role/placementType 保留，资料可见层不展示身份。本人其余组织行保留，下属原分散组织行改为路径；电话/邮箱/已入职有明确空态，时长沿用后端 tenure，不在Web再实现另一算法。

人员日程缓存按 epoch/账号/人员/模式管理，各月独立分页读取 `/tasks?assigneeId=...&calendarPreview=true&from=...&to=...`，继续应用有权投影和待审虚线。新增前后月份不清空旧月份，失败仅标记失败月可重试；当前人失权才清除正文。清单分固定标题、可滚动内容、固定操作三段，嵌套详情返回恢复月份锚点与清单偏移。保持下属全链仅评论可写，即使当前查看者也是创建者/负责人。

### 8. 通知使用已有服务端组合筛选和全局计数

列表按 `/notifications?category=...&readStatus=...&limit=...&offset=...` 加载，使用服务端动态分类、过滤后total及独立unreadCount，模式仅改变已加载行的呈现。避免只筛当前页或从筛选行数计算全局未读。打开仍调用原open命令并回读当前详情，历史只读与原requestId关系保留；返回按原查询刷新并恢复有效相邻位置。

顶部类型横滑标签、紧凑已读分段、单SVG图标切换模式；建议简单三角与复合几何，沿用项目SVG/CSS、不引入位图或图标依赖。可触范围约44px，模式名称和选中态可访问。筛选区置于列表滚动区之外；条件为默认时不显示重置，模式切换不算类型/已读条件。

### 9. 演示种子版本与检查按实际使用结果调整

沿用光屿动画/《星尘》、四位主角及稳定ID。新演示清单版本拟为3，种子与 `prepare_demo.py` 使用同一版本；旧版本库拒绝隐式升级内容，清楚指向显式新空目标库，普通准备继续幂等。优先准备新演示库保留旧库，不新增自动删库或普通启动重置。准备日明确写入manifest；刷新不改期，实际检查日期变化时通过显式新目标准备。

按每位主角的创建/负责并集及本人负责子集核对约10–20条有意义个人任务，避免分派重复计数、创始人本人日历空及员工积压。用真实父子任务串起逐级拆解/直属审核；补真实格式入职日、独立置顶、当天短任务、正常逾期、跨日/周/月及补写场景。任务名只用业务语言。非主角仅保留必要共享协作，测试日志/撤权/极限场景移到独立夹具，保留其测试覆盖。

准备及检查走真实服务/持久库，既有审批、交接、接管、标签、评论、通知需可操作；检查断言从固定58总数或“创建量达标”改成角色页面实际范围与状态覆盖。现有个人置顶和时长API以回归为主。

### 10. 规格、检查和打包共同更新

delta完整承接受影响需求，删除旧横向/唯一数量标记两项，新增纵向/条带状态，修改首页、日志、资料、人员月历、通知、拖动和演示；节假日改为本次Web实际展示。未改的表单查询、表单置顶、范围事项、填充源及授权契约继续有效。

现有Flutter delta也触及共享需求，本次不编辑它；恢复Flutter工作时须对届时主规格重新协调，尤其不能把已删除的横向/数量标记要求重新带回。此依赖记在本设计，不能在本次归档时顺带归档Flutter或宣称任务完成。

更新旧浏览器断言到新交互，保留隐私/审核/分页/版本/冻结/有效版等不冲突断言。使用320×740、390×844、1440×900和390×600检查，覆盖加载失败/重试、切账号迟到响应、嵌套返回和只读。根目录文件更新后刷新内容版本，重新打包并用 `check_web_resources.py` 核对JAR字节；如新增资源则同步白名单。

## Risks / Trade-offs

- [同方向多层滚动争夺手势] → 首页卡片无内部滚动；月历/清单明确滚动区，手机实测长按前后和边缘衔接。
- [月份补载与任务捕获竞争] → 按日期锚点修正偏移，拖动期间保留来源数据及必要DOM，结束统一清理。
- [月份范围或分页不完整导致漏条] → 窗口≤93天、全页读取、ID去重；局部失败不报全量成功。
- [刷新或返回后失权内容复现] → 会话/人员/查询序号检查，失败保留与失权清空分别处理。
- [实际浏览器不支持震动] → 保留视觉反馈及支持记录，不扩展套壳范围，也不把模拟调用报告为真机通过。
- [检查时演示数据已过期] → 按明确准备日新建显式演示目标，保留旧库/修改；不通过页面刷新重置日期。
- [历史测试或Flutter delta覆盖新规则] → 本次更新冲突断言和delta，未来Flutter恢复时重协调；原归档不改写。

## Migration Plan

1. 以A现有数据库/API为基线实施Web，不预设结构迁移；确有数据库修复只新增迁移并保留历史校验和。
2. 在隔离库运行受影响服务/浏览器检查，保留当前实现证据与未覆盖设备限制，再打包核对静态资源。
3. 用显式新空演示目标准备版本3和当前准备日，连续准备两次、重启、四角色走查及业务修改保留检查；不清理原库。
4. 交付根目录资源及匹配的后端包/演示目标说明。回退保留此前包和旧演示库；无结构变化时可回退资源/包，若发生新增迁移须先验证兼容或用备份恢复，不让旧代码压缩跨日事项。
5. apply写明实现与证据交接，另行独立e13验证后才考虑归档；本proposal不执行实现、准备数据库或部署。
