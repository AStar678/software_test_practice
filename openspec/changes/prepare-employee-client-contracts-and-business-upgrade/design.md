动机与范围见 [proposal.md](proposal.md)；全量业务与验收编号见[迁移盘点](../../../docs/reviews/潘多拉-Flutter完整迁移盘点与Change边界-2026-11-08.md)。基线为 `dd0d0d5`，Java 21/Spring Boot/MySQL/Flyway，统一 `/api/v1`，认证、字段授权、审批、版本与幂等已集中在服务端。

## Goals / Non-Goals

**Goals:**

- 用稳定、可说明、可重复验证的服务契约支持完整 Flutter 员工端；新增读取使用当前有效版、明确完整性和当前授权。
- A 独立交付后，PC 和过渡员工 Web 可继续使用；已有任务/审批/日志/评论/通知/统计服务可直接复用。
- 解决盘点第 6.3 节的范围查询、表单管线、节假日、入职/邮箱、日志填充、兼容、错误七类问题，避免把关键设计留给 B 猜测。

**Non-Goals:**

- 不创建 Flutter 工程或 B，不改 `android/`、`android-shell/`，不交付 APK/设备交互；系统推送继续延期。
- 不在 A 重做员工 Web 的纵向事项条、首页清单新交互、手机长按震动/二维拖动、下属连续月历、通知新布局等 B 工作。
- 不重写认证和任务状态机、不清理无关兼容字段、不扩大全公司人员/日志/联系方式权、不引入离线写入或外部 AI。

## Decisions

### D1. 服务端契约升级与客户端呈现分开验收

沿用现有 capability `pandora-requirements-aligned-prototype` 修改事项/表单/资料/管理/演示规则，并增加跨端读取与交接要求；独立新增 `china-holiday-calendar`，因为其来源、缓存和运维可独立描述。过渡 Web 的横向事项计数布局被显式限定为 A 阶段保留，不冒充最终 Flutter 纵向事项月历。

其他 54 条规格中未改的规则继续生效。B 以后从 A 归档后的规格与当前 90 项清单开始，不同时维护两份相反 delta。A 的交接文档必须逐行标注复用/本次增量/PC/待 B 呈现，不能只登记新增 API。

备选：把 A 写成“后端做 12 项”会丢完整迁移依赖；把 B 全部 UI 需求并入 A 又无法独立验收，均不采用。

### D2. 范围事项保持单记录、显式日期对和安全旧请求映射

数据：以新增迁移将 `daily_items.item_date` 重命名为 `start_date`，新增 `end_date` 并从原日期回填，完成非空及 `end_date >= start_date` 约束；保持 ID、owner、body、completed、row_version、created_at/updated_at，不重写历史迁移。按组织/本人/日期范围优化索引；相交查询为 `start_date <= to AND end_date >= from`。范围可以跨年，查询窗口上限不限制事项自身持续天数。

规范 DTO：`id,startDate,endDate,body,completed,status,rowVersion,createdAt,updatedAt`；status 为 `completed|open|overdue`，以公司 businessDate 与 endDate 比较，完成优先。兼容 `date=startDate` 仅作旧响应的起点投影，更新过的 Web 必须读完整日期对，不能将投影当全部范围。

| 请求 | 确定契约 |
| --- | --- |
| POST `/daily-items` | 新请求 `{startDate,endDate,body}`；旧 `{date,body}` 等价同起止单日；两种输入不能混用，新日期对缺一拒绝；完成初始 false |
| PATCH `/daily-items/{id}` | 日期对一起提供或一起省略；省略保留原范围，正文/完成可独立改；新日期对可显式缩短范围，版本检查不变 |
| 旧式 PATCH 带 `date` | 当前项仍是单日才允许等价改期；当前为跨日则 409 `DAILY_ITEM_RANGE_REQUIRED`，即使所给 date 恰为起点也不压缩；只有 completed/body 且省略日期可正常保留范围 |
| GET `/daily-items?date=D` | 选覆盖 D 的全部记录，稳定 `createdAt ASC,id ASC`；原 limit 默认 50/最多 100、offset/nextOffset 保留 |
| GET `/daily-items?from=F&to=T` | 新增范围模式，与 date 互斥，F/T 都必填、闭合范围最多 93 天；按 ID 不重复、与日清单相同排序/分页；含完成，返回原完整范围而非截断到窗口 |
| GET `/daily-items/summary?from=F&to=T` | 保留最多 93 天格式；把相交记录按覆盖日计数，每日 openCount 包括未完成且逾期项，completedCount 计完成；同 ID 每天一次，缺省日明确为零 |
| GET 详情、PATCH、DELETE | 继续真实 ID、本人同组织、ETag/If-Match 和现有幂等；失败不能部分改日期或完成 |

分页响应保留/明确 `items,total,limit,offset,nextOffset`，日期/范围回显；增加 `businessDate,organizationTimeZone` 供状态判断。每次响应在一致读快照内计算总数与本页。跨页存在并发变更时和现有 offset 契约一样需重取，文档明确不承诺多次请求冻结快照；客户端以 ID 去重、查询代次隔离，写后重载相关范围，不把尚未读完的数据标成全量。

备选：为每一天复制记录会破坏“一次完成整条”；仅扩计数不能画条；强迫旧客户端日期写入跨日项会破坏数据，均不采用。

### D3. 新增后端个人表单管线，不改变通用任务列表

新增 GET `/tasks/table`，在路由上与 `/tasks/{id}` 按静态路径区分。只接受下列参数，未知/非法枚举/倒置日期为 400：

| 参数 | 取值与默认 |
| --- | --- |
| relation | `all\|assigned\|created`，默认 all；原始创建或当前负责并集先限域，再按此筛选 |
| completion | `all\|unfinished\|completed`，默认 all；只看有效 executionState，完成待审仍未完成 |
| q | 去首尾空白、不分大小写的名称包含匹配，最多 200 字 |
| from/to | 各可省略，默认所有日期、不继承日历；按主规格首尾所属公司日期相交，不用日历午夜排除规则代替 |
| sort/direction | `title\|createdAt\|startAt\|dueAt\|priority\|state`、`asc\|desc`；默认 startAt/asc；紧急度升序 urgent/high/medium/low，状态 todo/doing/done |
| limit/offset | 默认 50/0，limit 1–100，offset 非负整数 |

处理顺序：当前正常读取授权→已有有效版本及原始创建/当前负责并集→关系/完成/名称/日期全条件→任务 ID 去重→tablePinned 分组（true 在前）→组内当前排序及同值 ID 始终升序→总数与分页。数据为有效版，冻结/待审类型可见，完整提议/diff 不附带。

名称比较固定由后端使用 `java.text.Collator.getInstance(Locale.SIMPLIFIED_CHINESE)`、TERTIARY 强度及 CANONICAL_DECOMPOSITION，按原始标题比较，不按设备语言、Unicode 码点或数据库默认 collation 排序。数字作为文本比较，不做自然数字排序（“分镜10”在“分镜2”前）；大小写参与三级比较，规范等价 Unicode 文本可比较相等，此时直接按 ID 升序。中文样例“阿”在“波”前；实施时记录锁定 JDK/locale provider 与包含中文、a/A、数字、重音/规范等价及同名异 ID 的完整升降序样例，作为 Web/Flutter 共用契约夹具。旧 Web 的 zh-Hans-CN 本地排序表达中文排序意图，新接口统一以上服务比较器为准；客户端不再二次排序，比较器升级须显式核对样例，不能静默更换。

响应 `{items,total,limit,offset,nextOffset}`，行沿用正常任务安全投影并含 `tablePinned,canTablePin`。读取与权限以现有批量装载/一致读机制复用；第一版允许在服务端对已授权集合内存筛选排序，保持批量查询且避免每项 N+1。以后可转 SQL 管线，但不得改变语义。提供大于两页和后页置顶的正确性/查询规模证据，不把内存实现宣称为无限数据量保证。

`/tasks`、其 nextCursor 形式及日历/父任务/普通搜索用途不改。过渡 `任务表单.js` 切到此接口，不再拉全量又重新排序；保留现有列、筛选、返回和账号隔离。表单页使用独立查询/分页数据，不把当前页覆盖为共享任务集合，防止返回日历或父任务选择时只剩表单首 50 条。

备选：继续两端各自拉全量会重复范围/排序逻辑并增加 Flutter 成本；直接收窄 `/tasks` 会破坏正常有权读取和日历用途，因此用独立表单路由。

### D4. 表单置顶独立于日历偏好，绝不成为权限来源

新增 `user_task_table_pins`（organization_id,user_id,task_id 复合唯一及必要外键/索引），不迁移或双写 `user_task_pins`。PUT/DELETE `/tasks/{id}/table-pin` 使用 Bearer+Idempotency-Key，操作是设置/清除本人偏好，返回 `{taskId,tablePinned}`，不要求任务 If-Match，不增加任务 rowVersion、不生成任务审核/通知。与日历 pin 的既有非任务写入模式一致。

合法资格：当前正常已发布且可读，并且本人原始创建或当前有效负责，含已完成和已有有效版的待审任务；不是按业务接管人猜“我创建”。每次读写与幂等重试都重验当前资格。残留偏好可以保留在数据库，但不参加失权任务的结果与计数，也不能授予历史/下属上下文写权。

普通任务详情和表单投影新增 tablePinned/canTablePin；日历 pinned/canPin 不改；历史通知只读投影不得给可执行能力，人员浏览模式只读亦不呈现/调用这些动作。服务端仍依据本次普通授权裁决，客户端 source 字段不当通行证。A 的 Web 正常详情增加独立按钮，嵌套下属模式沿用现有禁写约束。

备选：给现有 pin 加可选 mode 容易令旧客户端/能力提示串用，采用明确新路径和新字段。

### D5. 按日志日期提供只读完整名称聚合

新增 GET `/work-logs/fill-source?businessDate=YYYY-MM-DD`，不接受 userId。当前有效员工可读取任一合法公历业务日的本人名称源；缺日期/非法日期为 400，不以日志创建的近三日窗口限制这个纯读取接口。创建与编辑是否允许追加，仍由其日志创建/当前编辑权限决定。尤其“前天补写的日志次日仍未满 24 小时”可以合法编辑，不能因日期已移出近三日就禁止其填充。不读取或写入某篇日志，不要求它已存在，也不使冻结记录变可编辑。

响应 `{businessDate,organizationTimeZone,dailyItems:[{id,name}],tasks:[{id,name}],complete:true}`，一次在同一正常数据读取范围内返回两组完整去重名称（无默认分页截断）。事项 name 使用独立事项的 body 原文；不新增标题字段或截取首行。任务用当前有效标题，仅正常已发布、本人当前有效负责且实际时段覆盖业务日的任务，含完成，不使用 pendingSchedule。旧 allDay 以首尾日包含；定时 `[S,D)` 与当日 `[dayStart,nextDayStart)` 相交，午夜截止排除次日；S=D 归其公司日期，不能被空区间算法丢掉。

两组稳定排序：事项 createdAt/id 升序；任务有效 startAt/id 升序。接口无总数/部分成功假象，两组读取任一失败整体返回错误而非 `complete:true`。无结果是两个空集合。日志正文现有 10000 个 UTF-16 code unit 上限保留，按现有 Java String.trim 去首尾 U+0000–U+0020 后检查 String.length，事项 body 可多行且单项最多 2000；聚合不得为迎合正文上限静默截断或返回部分成功。A 的交接须注明长度计算口径及长源样例，B 在追加前处理合并正文超限。文本的标题、分组换行和主动追加是 B 的 UI 责任；A 只证明完整名称和失败语义，不改正文、可选任务关联、事项状态或审批。

备选：让 Flutter 分别拼多个分页接口易漏项并混淆日历覆盖与表单日期筛选，选择服务端聚合；不预先生成/写入日志文本。

### D6. 入职资料由管理员写入、服务端统一时长投影

新增可空 `users.hire_date DATE`，存量为 null，不用 created_at 回填。管理员直接创建员工、组织计划 newEmployees、员工 PATCH 都支持 `hireDate`：ISO date、null 清除/缺失默认空，晚于公司今天拒绝；编辑省略保留。对既有字段的部分请求/并发/原子保存规则不变。组织计划只承接新员工日期，不借该入口改既有员工资料。

PC `admin.html` 新增日期输入、编辑回读/清除和组织草稿新员工保存；列表/详情可核对。沿现有员工 orgVersion/profileVersion 机制使资料刷新可见；日期变化不改凭证或派生新的业务身份，不额外撤销所有会话。初始密码仍只回显一次，事务失败不半建号/写日期。

本人 GET `/me`、`/me/profile` 及有权人员 GET `/users/{id}` 增加 `hireDate,tenure`；tenure 为 null 或 `{years,months,days,asOfDate}`，同一响应使用公司今天。算法按时间线完整经过：从 hireDate 先取可完整增加的最大年数（周年不存在则当月最后日），再取不超过今天的最大 0–11 月数（用当前年锚点加月并截月末），最后取锚点到今天的实际天数。每步不越过今天，不用 365/30 换算。闰日/月底用例固定在测试与文档，B 直接渲染，避免 Flutter 再写另一套时长算法。

本次同时修改 `Minimal profile page` 与 `Account password lifecycle` 的邮箱规则及场景，消除旧“任何他人详情不返回邮箱”断言；账号密码、手机号登录与撤销规则不变。

日期/时长仅上述详情和管理员维护读取，普通目录/负责人候选/下属树摘要不附带。本人和当前实际链上级且通过原资料/电话详情资格的读取者可在 `/users/{id}` 得到 email（可空）；同级/非链/跨公司不读。当前组织状态每次重验，不把手机号存在与否当资格。过渡 Web 仅补详情字段展示及缺失空态，组织身份隐藏/统一职务路径的新呈现留 B，原始 role/placement 数据继续服务内部授权。

备选：用账号创建日不是真实日期；两端自行计算可能在月底分叉；给目录加邮箱会扩大隐私范围，因此采用管理员真实日期+授权详情投影。

### D7. 节假日缓存只影响标识，读取不依赖实时外网

新增 `GET /calendar/holidays/{year}`，只供当前有效员工及独立管理员，返回 `{year,region:"CN",status,days,source,updatedAt}`。status 为 ready/stale/missing：成功完整校验的缓存 ready；后续刷新失败仍用原值且 stale；无有效缓存 missing/空 days/updatedAt=null，不推算休班。days 为按日期升序的 `{date,name,isOffDay}`，仅包含官方特殊安排，未列出普通周末不自动合成官方“休”。缺失与失败原因用安全 code 表达，不暴露外源原始错误。

按 region/year 缓存公共官方年度安排（头记录+日记录或等效原子 JSON），记录来源标识/版本或内容哈希、官方通知引用、成功更新时间及最近刷新结果；维护审计保留实际管理员及其组织。整年验证通过才原子替换；拒绝跨年、非法日期、重复、休班冲突、空名称、非布尔值、无可核对官方年度依据的“已发布”结果。数据补丁也必须来自同口径校验，不能维护百年预测表。

外源采用后端固定配置适配器，首选核验 `NateScarlet/holiday-cn` 的年度文件及 `papers`/日期/休班数据；启用前记录可访问 URL、格式、年度样本、维护/使用条件和官方通知交叉核对。该候选当前未被验证。若核验不能满足，仍按相同适配契约选择可核对官方安排的年度来源，记录结果后才能启用；不改变 API、规格和任务范围。测试用本地固定年度响应覆盖失败/错误格式，不能因此省略真实来源核验。

普通 GET 只读本库，不逐手机直连/同步拉外网。后台在启动后及每日维护窗口检查当前年/次年；首次读取其他缺失年只登记一个按年去重的后台获取意图，失败后同年自动尝试间隔至少 24 小时。仅接受 1900–9999 的四位公历年份；合法但无来源记录的过去/未来年返回 missing，既不生成预测也不无限循环。已缓存历史年持续可读。

提供管理员维护 POST `/admin/calendar/holidays/{year}/refresh`（Idempotency-Key、当前 admin 权限），用于明确按年刷新；不接收 URL。实施文档给出安全调用方式及刷新审计；A 不扩为完整 PC 节假日编辑器。外源请求有固定 host/路径配置、连接/总超时和响应体上限（建议 10 秒/1MiB）、有限重试/按年互斥；抓取/解析不占用年度缓存写事务，最终提交用短事务并重验当前维护资格与幂等。GET 不因外源故障失败，未知年稳定 missing。即使已缓存年份刷新失败，也只改刷新状态，不改原数据/成功更新时间。刷新失败维护请求返回 502 安全错误并保留缓存。

备选：手机直接读开源数据会分散可用性/校验；硬编码未来年份无法据官方公布；每个 GET 同步抓取会放大请求。采用后端有界抓取和持久缓存。

### D8. 过渡 Web 适配只覆盖 A 的契约变化

- `潘多拉-每日事项.js` 保留横向日期/数量外观，日清单改覆盖日读取，表单/详情显式起止日和三态、范围摘要失效覆盖旧/新范围。保留真实 ID、版本、幂等、完成控件及返回栈；跨日从任一日操作同一记录。不需要先实现最终纵向事件条。
- `潘多拉-任务表单.js` 使用服务端管线和 nextOffset，保持已有表格列组/排序/筛选/返回。`任务接入` 正常详情增加独立表单置顶，不给下属/历史路径按钮。
- `个人资料/工作区接入` 对已新增的详情字段显示真实入职时长、邮箱及对应空态；不恢复团队管理/联系人目录。不在 A 做组织身份隐藏/整套职务路径重排。
- API 层只调整新能力；普通 `/tasks`/其他 cursor 仍按各自契约读取。修改资源后使用现有资源版本更新机制，保证在线 shell 下一次加载获得配套 Web；不构建 shell 或声称已验证容器。
- 不立即下线员工 Web。部署时后端先兼容旧单日请求，再更新页面/资源版本；未刷新的旧页若尝试跨日旧改期得到明确冲突，要求回读/刷新而非静默缩短。库已存跨日记录后不支持无备份直接退回只懂 item_date 的旧后端。

备选：在 A 做完新 Web 会重复 B 成本；完全不适配会让 A 无法独立交付，采用最小可安全使用的适配。

## Risks / Trade-offs

- [服务端表单首版仍可能批量内存排序] → 保留可替换实现边界，使用多页/查询规模检查，响应只发当前页，不向客户端转嫁全量下载。
- [offset 多次读取期间有并发修改] → 每响应一致快照、明确非跨请求快照、ID 去重/重取，不给部分加载假完整结论；日志名称聚合单次完整读取。
- [日期对迁移破坏旧客户端或回退] → legacy 单日映射+跨日旧写拒绝，协同 Web 资源更新，升级前备份；禁止直接以旧二进制打开新结构。
- [入职日期通过某个组织计划入口漏校验] → 覆盖正式 admin.html 草稿 newEmployees 和直接 POST，统一校验、同事务、失败无半写；旧值保持 null。
- [邮箱经摘要或缓存扩散] → 白名单详情投影、真实链与资料权交集重验、目录反向断言与失权回归。
- [外部源失效/格式变动/尚未公布] → 来源核验与适配边界、有界重试、整年验证原子替换、旧缓存持续可读、missing 不预测；不依赖活网跑规则测试。
- [动画演示准备覆盖个人修改或删掉极限验证] → 显式演示库/重建入口和幂等 prepare，默认主线与隔离夹具分离，正常启动不做业务重置。
- [A 被误当 Flutter 已完成] → 90 项全量责任映射，A/B 证据分列，B 在 A 归档后另提，不勾选未实现客户端项。

## Migration Plan

1. 在隔离库捕获当前结构/行数据、Flyway 校验和与既有行为基线；实现新增迁移和升级检查。实施前读取最新已应用版本，使用后继版本号，不抢占固定历史编号。
2. 加入范围事项、表单偏好、入职日和年度缓存结构；无演示重建、无全局改名，空库/升级库相同结果。所有存量单日映射 start=end，入职未知为 null，表单偏好初始空，日历偏好保留。
3. 上线兼容后端及正式 PC 输入，配套更新员工 Web 受影响资源；对旧页旧请求、资料投影、完整业务及数据不变量回归。A 不承诺修改 Flutter 或 shell 安装包。
4. 显式选择演示环境准备动画主线/独立极限夹具；运行真实来源核验并加载可验证年度缓存。生产/其他业务库不自动替换演示内容。
5. 形成接口交接、检查记录与实施说明，独立验证本 change。A 归档后的主规格和契约作为 B 提案基线。
6. 回退优先停止新客户端入口/回退新读取或适配器并保留新增数据，服务使用兼容修复版本。若必须恢复旧结构/二进制，先停止写入并导出新增跨日/入职/偏好/缓存数据，使用升级前备份在隔离库演练后再恢复；不得静默压缩跨日事项以让旧版启动。恢复前后核对任务/日志/审计来源与稳定 ID。
