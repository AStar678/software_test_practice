# Proposal

## Why

本人日志正文未使用下属日志的阅读字号。排期拖动入口较小，纵向日轴没有手柄，月历按整日调整不适合小时级安排，需要修复交互并统一小时粒度。

## What Changes

- 本人日志列表和日志详情正文统一为下属日志正文的15px和1.55行高，编辑输入和评论保持原用途。
- 月历、横向日轴、纵向日轴的无文字按钮的边缘拖动区统一按一小时相对调整，保留原分钟和未调整端点。
- 扩大无文字按钮的边缘拖动区、明确操作提示；纵向日轴补齐拖动，保留正常滚动与点击详情。
- 拖动结束仍以已有编辑表单确认原因并按原审核规则提交，排期权限扩展为所有可见的未完成非待审任务，资料编辑权限、实际有效版本、ETag和冻结规则保持；取消、逆序和旧版本不能隐式写入。

- 已发布任务在任意审核期间以虚线和待审提示显示；有排期提案时日历显示提案位置，通过后实线，驳回/撤回/失效恢复原有效位置。本人及下属日程保持一致，标签颜色保留。

- 月历任务时段条按每日实际占用比例显示，跨日首尾保留小时偏移；可在月历直接移动整条或调整起止，续接段可直接平移，详情仍可精确调整完整排期。

- 修复普通HTTP地址下randomUUID不可用导致提交失败，公共写入入口使用安全随机请求标识兼容路径，重试继续复用同一幂等键。

- 任务标题和排期文字全部放进实际时段框；移除月历调时按钮及所有可见起止按钮，待审虚线框位置/尺寸/文字统一使用新申请排期。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `pandora-requirements-aligned-prototype`：统一日志阅读字号和小时级排期拖动。依赖当前已上线的三个未归档实现，本轮单独跟踪并取代旧月历按天/横轴按15分钟的交互要求。

## Impact

日程视图JS及日历样式、日志详情结构及主题样式、专项真实浏览器测试。后端仅增加授权任务的最小待审排期展示字段与日程范围投影，新增仅排期命令及对应提交/生效权限校验，不改变审核路线、提醒或数据库结构。先完成本地修复验证，云端发布与Git推送另行处理；按用户原指示不做手机真机测试。
