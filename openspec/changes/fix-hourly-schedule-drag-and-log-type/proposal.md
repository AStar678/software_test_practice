# Proposal

## Why

日志阅读样式与排期交互需要保持一致；后续实现把月格细分为小时，短任务过窄且拖动精度不适合月历。按用户最终确认，月历用于按日安排、日视图用于小时调整，同时统一已发布任务的待审虚线与提议位置。

## What Changes

- 本人日志列表和日志详情正文统一为下属日志正文的15px和1.55行高，编辑输入和评论保持原用途。
- **BREAKING**：月历按占用日期绘制日级任务条，不按小时缩窄或偏移；整条按天平移保留日内起止时刻和工期，两端按天调整对应日期、保留该端时刻并改变工期。午夜截止不多占次日，小时细节从日视图或详情查看。
- 横向/纵向日视图按一小时相对调整，保留分钟；支持整条移动和真实端点调整，纵向全天区同样有合法操作入口，不能因显示分类丢失拖动能力。
- 拖动仅绑定本人月/日视图，且任务已发布、未完成、非待审并有现有仅排期权限；表单和下属日程不提供拖动，进入任务详情后按原有操作权限办理。本人视图只列有效负责人任务不变，不把入口限制改写为后端仅负责人可调时。
- 拖动结束沿用仅排期确认、原因、实际操作者直属上级审核及创始人原免审规则；版本、幂等及冻结保持，取消、逆序和旧版本不能隐式写入。基础字段编辑权仍仅业务责任方，全面可见即可编辑暂缓。

- 已发布任务在任意审核期间以虚线和待审提示显示；有排期提案时日历显示提案位置，通过后实线，驳回/撤回/失效恢复原有效位置。本人及下属日程保持一致，标签颜色保留。

- 本人及下属月历使用相同日级跨度与待审位置；下属月历仅展示及进入详情，不生成平移或端点入口。跨周续接段不冒充真实端点，本人视图仍可整体平移。

- 修复普通HTTP地址下randomUUID不可用导致提交失败，公共写入入口使用安全随机请求标识兼容路径，重试继续复用同一幂等键。

- 月历标题和日期信息位于日级任务框内，日轴标题与时刻位于真实时段框内；不放独立“调时、起、止”按钮，透明边缘与键盘操作保留。待审框及文字一致取新申请排期，不残留旧框。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `pandora-requirements-aligned-prototype`：统一日志阅读字号；月历按日、日轴按小时；本人视图拖动与普通详情权限分离；已发布任务待审虚线和提议位置；HTTP写入兼容。取代原三视图统一小时/下属可拖动/小时比例月条的规划，通知/创建 change 删除旧15分钟与基础编辑者拖动条款，下属 change 对齐显示及入口。

## Impact

日程视图JS及日历样式、日志详情结构及主题样式、专项真实浏览器测试。后端仅增加授权任务的最小待审排期展示字段与日程范围投影，新增仅排期命令及对应提交/生效权限校验，不改变审核路线、提醒或数据库结构。先完成本地修复验证，云端发布与Git推送另行处理；按用户原指示不做手机真机测试。

本轮修订已有规划，保留原实施记录、verification.md 的 FAIL 及全天区无拖动 V-001。受影响任务重新打开，旧小时几何/下属拖动通过结果不适用于新合同；未独立验证前不归档。已归档个人日志 change 不改写，日志界面分离和文案清理由 separate-log-forms-and-clean-product-copy 承接。
