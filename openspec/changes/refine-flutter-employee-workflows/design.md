## Context

见 [proposal.md](proposal.md) 与 [规格增量](specs/pandora-requirements-aligned-prototype/spec.md)。Flutter 的 `TaskCalendarPage`、`WorkLogsPage` 已在本人和下属入口复用，现有 `ReadContext` 区分访问场景；修复应落在共用组件，而非复制两个页面。当前月历以 `_drawerDay` 在月历列表与日面板之间替换整棵视图；日志详情和列表已有返回时重读，这只能证明尝试刷新，不能证明实机显示了成功保存的版本。现有审核页已消费服务端 `diff`，但仅绘制对比或申请人摘要，没有补足审核人的快照入口与新建申请展示。

## Goals / Non-Goals

**Goals:** 用现有 Flutter 页面、资源和接口修复交互。让浏览状态、任务版本、软键盘及窄屏表现都有可单独验证的路径。

**Non-Goals:** 不新增依赖、服务接口、表结构、角色规则或强制数据迁移；不按 Web 重写整个 Flutter 页面，不修改 Web 或 PC 产品代码。只对已经复现且能定位的服务端问题做兼容性修正。

## Decisions

### 页面、正文与名称分别布局

- 五个主路由复用 `BrandMark` 和现有 SVG，页面语义独立于可见标记；下属和其他二级页仍保留明确文案。首页日期控件使用有宽度约束且能换行的工具栏，按可用宽度排列，保留原动作和点击区域，不使用无宽度约束的 `FittedBox` 来补救。
- 事件纪先用实际字体、可用宽度与两行限制判断完整正文是否放得下；只有截断时才重新为末端箭头分配空间，整条承担点击与展开语义，避免短正文被预留的箭头挤成截断。
- 名称渐隐和日志省略号不用同一个渲染策略。名称按真实文本布局和完整可见字素边界确定最后一个可见字符，仅对该字素应用局部遮罩；不选普通 `TextOverflow.fade` 的整段边缘效果。保持原文字用于详情和语义。不提前用固定字符数裁剪，避免中英文、字号或布局变化时错误。日志单独测量第三行，若剩余有实质正文则为省略号预留宽度，并在完整字素处收尾，补足显式换行造成的截断。

### 保留服务授权的任务与通知呈现

- 通知列表继续把分类及已读条件交给服务；详情复用集中维护的申请类型、状态中文映射，区分业务事件结果和关联申请状态。未知值不回显协议枚举。此前只读核对本机 `pandora_demo`：2026-11-18 创始人 `13800000001` 当前待审为 0，团队负责人 `13800000011` 有 2 条有效待审；这只是当时的数据证据，不作为当前或未来的固定测试数据。用隔离账号/夹具检验空与非空；仅在确需演示创始人待审且隔离验证覆盖不了时，考虑 `backend/` 的可重复演示种子，不覆盖现用库。
- 普通任务详情只展示有效版本和确切申请入口，收拢元信息；去掉常规完成标准控件及其普通表单提交分支，但保留 DTO、历史和授权审核渲染。负责人选择树沿用现有搜索、选人和重排模型，去掉嵌套滚动限制；标签差量只在确有变化时发送（含显式空数组），避免用提示语代替状态处理。表单截止列复用公司时区和全天截止解析，不从拼接的排期文案截字。
- 「提交进展」继续独立使用现有动作请求、版本及幂等方式，不借编辑任务绕过。保留 `reviewer-preview` 与成功后 `approval-requests/{id}` 两次不同用途的读取；失败区分保存失败和保存成功但暂不能回读审核人。任务详情的待审入口读取原返回的申请标识和当前授权，不用泛化的申请列表冒充某一条原申请。
- 审核页默认只呈现接口给出的 `diff`，不从普通任务对象自行重建。扩展现有提议区块，让审核人默认看差异、可展开获授权的提议/原有效版本。无旧版时直接呈现新提议；有旧版但空差异时保留真实的无差异状态。根据当前身份、请求上下文及实际授权载荷决定可见区块；权限变化、无快照或只读路由都不补造数据或升级裁决权。保留现有读写硬约束和申请人撤回逻辑。

### 本人和下属日程共用模式与锚点

- 区分月历可见锚点（公司日期＋视口内像素偏移）、当天清单日期、日视图日期及各自滚动状态。打开清单时保留底层月历，关闭恢复原焦点；日视图需要替换视口时使用既有日期/偏移恢复机制，而非把访问当天写成月历滚动位置。顶栏直进使用当前月历定位，未形成可见锚点时使用公司业务日；从清单进入使用实际命中日期。两条路径切回清单均保留同一天，显式回月恢复月历；详情返回保留来源层级。状态保持原账号和人员作用域。
- 日清单和日视图标题复用月历的年度节假日缓存，按公司日期的年份加载，不按设备时区改换日期。查不到当日记录则无徽标，不阻断任务加载或直连外源；后端的 ready、stale、missing 语义不变。
- 把视觉「待审核」与「有提议排期」分离：用待审冻结状态决定描边及语义，用合法 `pendingSchedule` 决定绘制在哪一天，不挪动详情与截止。复用任务样式在月条、轴、全天及清单上应用状态；已完成名称减弱并加删除线。
- 双指手势只调周行高度与可见轨道容量，不使用整页缩放。使用有上限和下限的周高及当前锚点，根据获得的两指纵向间距变化重算轨道、溢出数量和月块尺寸；松开前抑制遗留点击、拖动确认和写入，松开/取消妥善恢复普通滚动。兼容旧紧凑/舒展偏好默认值，密度设置按本人或下属与登录身份隔离。保留单指浏览及既有长按改期竞争关系。

### 日志回读和键盘按真实交互验证

- 先复现编辑按下保存到两层返回的链路，观察 PATCH 内容、响应版本及两次 GET。`WorkLogsApi.change` 已返回 `WorkLog`，优先将成功结果或等价的明确保存事件传回详情并更新当前记录，再在回到列表时按现有权限更新同一条并做必要重验，保留已加载分页与可见锚点。忽略跨账号、不同作者、旧查询代次或更旧版本的响应；不要单靠增加一处延迟或全量重置列表。若证据显示服务读旧，才修复共享服务的现有读写路径并补契约回归。
- 日期筛选面板用本地临时值，提交后一次重读，取消不改变查询。冻结取服务返回的真实冻结状态，不从下属只读或业务日期猜测。评论区由任务与日志继续共用，保证键盘出现时适配视口、安全区与焦点滚动，输入框至少可完整容纳一行并支持多行滚动，不为修复键盘将所有详情改为常驻输入条。编辑评论、列表分页和权限保持原样。

## Risks / Trade-offs

- [窄屏布局通过但真键盘仍遮挡] → 组件用最小屏宽、放大字体和模拟 inset，另用 Android 模拟器实际输入、滚动、发送和收键盘；不把模拟器结果当真机结论。
- [连续月份重排、双指和长按互抢] → 在跨月位置记录锚点，输入序列覆盖单指、双指、手指取消、重叠轨道、本人写入及下属只读。
- [已有旧请求或无授权载荷被误当无变化] → 覆盖无旧版、有旧版但无差异、差异非空、已裁决或失权、申请人/旁观者；后端仍决定授权。
- [日志异步回读抢占新版本] → 验证保存成功、失败、取消、第二页返回、慢旧响应及跨账号/作者，记录真实后端回读而不仅用假数据。

## Migration Plan

不迁移数据库。旧日历密度偏好按兼容默认值读取，所有任务历史和共享接口保持兼容。可以回退客户端版本而不用回退任何工作数据；隔离验证数据与用户日常 demo 库分开，验收不依赖清库或重置账号。
