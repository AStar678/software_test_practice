## Why

Flutter 员工端的通知、任务、日程和日志有多处与实际使用习惯或 Web 参考实现不一致：状态码外露，审核缺少上下文，月历返回跳位，窄屏溢出，日志保存后仍可能读到旧内容。把这些问题集中修整，降低日常操作成本，并明确本人和下属入口的共同验收口径。

## What Changes

- 删除指定的解释性文案，五个主页顶栏复用潘多拉标记；每日事项当天页只保留日期，「我的」无直属上级时隐藏该行。压紧事件纪条目，仅正文截断时提供展开；修复首页窄屏横向溢出。任务名和每日事项名在受限预览中仅截断时做末字渐隐，不用省略号。
- 通知详情显示中文申请类型和结果，不把无待审的演示账号当成筛选故障。任务详情改用紧凑的信息层级，去掉常驻审核路由说明和常规详情/编辑中的历史完成标准，保留独立「提交进展」及真实审核人提示。审核详情默认看变化，按权限补齐完整提议、原有效版本及无旧版申请的展示。
- 负责人树随表单自然展开，不单独滚动；去掉空标签的保存提示，不改变实际保存语义。公司任务表单用实际「截止时间」替代「排期」列。
- 本人及下属日程支持顶栏直进日视图、当天清单内切换「日视图／清单」；返回保留原位置，有节假日才显示标记。补齐任务完成删除线、待审虚线和月历双指调密度。
- 本人及下属日志使用统一日期筛选入口和三行正文预览；本人编辑成功后详情和列表读到新内容，不丢筛选和浏览位置。冻结和仅有查看权分别呈现。修复任务与日志的发表评论输入框在键盘弹出时被挤压的问题。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `pandora-requirements-aligned-prototype`: 新增 Flutter 专属的员工端展示、交互与回读要求，Web 现行行为不变。

## Impact

- 主体为 `flutter/` 的原生页面、控件、状态与测试；根目录员工 Web 仅作行为参考，不改 Web 或管理端。
- 复用现有后端接口与权限。仅当复现证实问题来自服务端时，才在 `backend/` 做兼容性修复；待审样例使用隔离演示/测试数据，不重置现用 demo 库。
- **Non-goals**：不改变审批、通知分类、角色、冻结与排期规则，不清除历史完成标准，不扩大下属入口权限；不修改或归档其他 change。
