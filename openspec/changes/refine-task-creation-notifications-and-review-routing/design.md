# Design

## Context

动机见 proposal.md。前端为根目录原生 JavaScript/CSS，安卓 0.2.3 套壳在线加载同一页面。后端为 Spring Boot/MySQL/Flyway，数据库已有 V27 私人标签迁移。当前工作区存在用户已有改动及重复文件，实施时仅修改实际加载文件。

已查明：
- `WorkspaceService.notificationsRead` 仅处理 `unread=true`，在列表元数据分页后才生成安全详情；通知列表由 `潘多拉-工作区接入.js` 展示摘要。
- `潘多拉-标签评论.js` 的共用标签是单选；`TaskService` 在版本表存储 `tag_id` 与名称颜色快照，创建/编辑/审核均按单值传递。私人标签独立保存。
- 创建表单实际由 `潘多拉-交互原型.js` 和 `潘多拉-任务接入.js` 组合；`潘多拉-任务表单.js` 名称虽相似，主要是任务列表页，不能误认作创建表单。
- 候选 API 提供姓名、部门、职位、团队、层级，但尚无构树所需直属父节点；现有选择器是部门+姓名列表，已有工作副本、确认/取消和有序多选。
- `TaskService.creationRoute` 已按创建人直属上级；`route/currentRoute` 非创建按业务责任方，相关逻辑覆盖预览、提交、待审刷新与审核决定。现有规格还在进展、完成、交接、接管及演示场景中要求旧规则，必须一起更新。

## Goals / Non-Goals

**Goals:** 统一服务端审核依据；完整保存多标签；最小新增目录字段实现真实树；复用现有表单、主题、授权与交互栈；兼容旧单标签数据。

**Non-Goals:** 不扩大操作权和资料可见性，不改管理员业务身份，不重建组织或清空数据，不引入前端框架。独立原生客户端暂不重做界面，但后端新规则和旧客户端兼容行为必须明确。

## Decisions

### 1. 审核依据统一为申请人

建立一个以 `applicantId` 为依据的直属上级路线；`context actor` 仅代表当前鉴权上下文，不得用于覆盖存储的申请人。创建时用实际提交者，刷新/决定时用申请记录原申请人。沿用固定创始人判断与严格阻断规则；原因文案改为全操作通用，预览增加/统一 `reviewerBasis=operator`。不单独在某个创建或负责人接口补丁式更换审核人，因为会与通知及决定分叉。

任务访问、基础修改、进展、重开、专用交接权限仍独立判断。上级代办交接时取代办人的上级，不取被交接员工的上级。接管只更改业务责任，不冒充原申请人。所有有效待审刷新同事务更新审核人、历史与通知；组织权限版本及决定前重验阻止旧页面越权。固定创始人免审必须经过与正常提交相同的全部校验。

### 2. 多标签与任务版本关联

新增下一可用编号的 Flyway 迁移，建立任务版本到共用标签的有序关联，带组织隔离、同版本去重及名称/颜色快照。回填旧 `tag_id` 为序号 0，保留旧列作为首项兼容投影；不修改 V17/V27。新请求用 `tagIds` 数组，新响应带 `tagIds/tags` 完整集合；标签顺序稳定，取消后重选追加到末尾。

未提供字段的旧写请求沿用完整原集合；同时传入冲突的新旧字段拒绝。仅传 `tagId` 时，旧对象零/单项允许兼容，既有多项对象返回明确冲突避免静默截断。审核 diff、历史、通知摘要和重提必须使用完整集合；日志仍单选，私人标签独立。

日程保持现有单背景色表达：私人覆盖优先，否则第一个共用标签，否则默认粉色；详情显示全部标签。多色拼接会影响任务文字可读性，本次不采用。已删除标签仅能在已有版本关联中保留，不允许借新数组重新关联。

### 3. 通知筛选由服务端统一裁决

增加 `readStatus=all|unread|read` 与 `category=all|review|result|reminder|comment|other`，保留旧 `unread=true` 映射；非法值或冲突参数明确拒绝。分类使用结构化事件类型和当前申请权限，不能从中文摘要推断。`review` 只纳入当前可办理消息；原提交已办结不伪造结果事件，实际结果事件仍归 `result`。

扩展批量元数据以取得分类所需的请求状态/审核人/截止；先生命周期及权限裁剪，再组合筛选、计数、分页，最后生成安全投影，不做逐条数据库查询。不在已加载第一页上过滤。全局未读数仍按全部可见消息计算。

界面默认精简四字段，提供精简/完整切换；条件存会话内、详情返回恢复、切换账号清除。完整模式仍提供原摘要。非任务通知显示安全对象或无关联占位，撤回/失权处理继续使用服务端安全响应。

### 4. 真实组织树与分离选择

候选最小增加 `managerId` 及构树需要的团队名称/位置类型；复用公司固定组织树来源，不按职位名称或数字层级猜父子关系。仅当前合法候选可选择，必要结构祖先不得携带联系方式或获得额外业务权。

树按公司—部门负责人—团队负责人—员工逐层展开，名称/职位/部门用于辨识；展开按钮与选择框分离，均可键盘操作，并表达展开/选中状态。搜索覆盖全部合法候选，自动展示命中路径；折叠、搜索、跨分支不丢选中，取消丢弃工作副本，确认回写有序 ID。组织变化导致候选失效时重新校验并明确提示。

### 5. 表单布局延用现有主题

色块按钮用弹性自动换行容器，名称在按钮下方；选中描边+勾号及 `aria-pressed`。单独保留日志单选 helper，避免共用 helper 改动扩大日志语义。

排期用开始/截止两个分组和响应式网格，移除造成手机拥挤的内联等分宽度；日期与时分控件分别可收缩或换行，复用现有时分选择，不触发大表盘。创建、编辑、重提和重开统一显式日期与时刻，移除全天开关。快捷按钮将开始时刻设 00:00、当前截止日推进一天并设 00:00；同一未修改的结果重复点击不继续推进。旧全天记录编辑时按其实际 startAt/dueAt 转成时刻，不改旧数据读取/API 兼容。320px/390px/桌面浏览器实测焦点、滚动、键盘与返回行为。用户于实施阶段明确取消手机真机测试，本轮不以模拟尺寸宣称真机通过。

### 6. 横向拖动排期

月历实际起止端点提供独立手柄，横向按天移动并保持时刻；跨周/月的续接端不伪装成真实端点。日模式增加默认横向 00:00—24:00 轴，每任务独立一行，包括整日覆盖，保留纵向轴及清单切换。横向轴按 15 分钟相对增量调整实际端点，部分覆盖续接端不可拖。零时长保留真实点位与独立命中区。

只对 canEditTask 允许的任务显示手柄；拖动仅预览，松开进入已有编辑表单复核日期时刻、原因与审核路线。提交复用 change、ETag 和幂等规则；旧版本变化不覆盖新排期。Esc、pointercancel、失去捕获及无位移取消，逆序拒绝，不误开当天清单。键盘左右箭头提供同粒度调整，表单提供任意精确时刻。

## Risks / Trade-offs

- [旧客户端丢失多标签] → 保留读投影、缺省写保留集合、冲突明确拒绝，测试实际旧载荷。
- [旧待审仍被创建者批准] → 上线显式刷新有效申请，决定入口同规则重验；旧审核按钮、通知、并发决定均验证。
- [混淆申请人与当前查看者] → 测试原申请人、旧审核人、新上级及接管人四者不同的案例。
- [标签迁移丢历史] → 独立升级库比对旧版本/标签快照、重复启动及回读，不运行生产清理。
- [通知全量筛选性能] → 使用批量元数据与稳定排序，延续现有批量读取预算测试，不通过逐条详情查询分类。
- [树目录泄露个人资料] → 候选最小字段白名单测试、跨公司及管理员排除、不能复用带电话的资料详情。

## Migration Plan

1. 在隔离数据库运行新增迁移并校验单标签、空值、已删除标签及历史版本无损；验证全新库及已有库结果一致。
2. 完成后端与前端测试、实际浏览器检查（用户已取消手机真机测试）；生成实施说明和独立验证交接。
3. 后续发布时先备份数据库与部署配置，整体切换兼容后端及网页；对有效待审执行可重入刷新并核对原申请人/新审核人/通知，不重写终态。
4. 已产生多标签数据后不可直接回退到只支持单标签的旧服务。回退使用兼容集合的修复版本；若恢复备份须先核对发布后新增数据，不能丢弃新业务记录。

## Confirmed Choices

用户已确认：固定创始人继续免审，其余员工缺少有效直属上级时阻断；沿用现有公司标签，修改网页和在线安卓套壳。上述选择已从规划假设转为确认要求。多标签首项作为日程底色仍是本方案的显示选择，不改变标签业务内容。

## 追加决定：本人表单、标签维护和日志入口

任务表单在统一结果管线先按creatorId或assigneeIds过滤，再执行搜索/筛选/分页；全局授权集和其他入口不改。移除仅可见筛选。标签维护API（含私人标签）强制创始人，返回canEdit同规则；非创始人不显示管理入口，日程图例和详情私人颜色选择入口移除，已有私人覆盖与共用首项颜色保留。写日志查询公司近三天已有记录，仅提供缺失日期；无缺失提示从详情编辑。编辑仅显式日志ID打开，创建竞态保持草稿和错误不切换编辑。
