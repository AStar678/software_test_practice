## Why

员工 App 在任务创建、任务生命周期、每日事项时间语义、首页呈现和数据新鲜度上仍有验收缺口：创始人必须离开任务表单才能建标签，任务无法删除，每日事项只有日期精度，导航切页后经常保留旧数据，部分长名称末字出现重影。本 change 集中修复员工端与共享后端的这些问题，管理端员工生命周期另立 change，周视图双指手势本批不做。

## What Changes

- 任务表单允许固定创始人在当前表单内直接创建公司标签并自动选中；不离开表单、不丢失已填内容，普通员工仍只能选择或清除标签。
- 为任务增加软删除：当前业务责任方或原创建者可删除，存在未结申请时须先撤销或办结；通知、申请、评论、日志关联和管理端操作历史不级联删除。
- 已删除任务从日历、看板、任务表单、搜索、统计和父任务候选中排除；从通知、申请或日志关联点击时显示“任务已删除”，不再进入正常详情。
- 每日事项保留全天/定时两种模式；定时事项保存精确开始/截止时刻并按实际时刻判断逾期，日历仍按天展示，旧数据无损迁移为全天。
- 事件纪和任务看板的预览及完整清单在每条左端显示当前顺序序号。
- 负责人候选在同一部门/团队内按负责人优先，顺序为创始人、部门负责人、团队负责人、普通员工，再按姓名及稳定标识排序；已选手动顺序不重排。
- 底部导航每次点击都刷新目标主页数据，但保留滚动位置、筛选、分页、日期与草稿；通知、我的下属等无底栏关键页面提供可靠的下拉或显式刷新。
- 修复受限名称末字渐隐时重复绘制造成的重影，继续不使用省略号且不额外留字符位。
- 统一 App 可见错误为中文、可操作提示；增加后端安全兜底，避免原始异常、技术信息和英文字段名直接展示。
- 本 change 不包含周视图双指进入/退出、非创始人内联标签创建、管理端员工入职/离职/筛选及管理端文案清理。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `pandora-requirements-aligned-prototype`: 修改标签表单入口、每日事项时间语义、首页序号、负责人排序、刷新与错误安全要求，并增加任务软删除及已删除对象呈现要求；周视图双指手势保持现状。

## Impact

- `flutter/`：任务表单、任务详情/动作、日历与当天清单、工作日志关联、每日事项、首页、通知/下属刷新、负责人选择、渐隐文字及统一错误展示。
- `backend/`：任务软删除与历史、每日事项时间字段及迁移、负责人候选排序、全局错误兜底与用户可见文案；可能涉及新增数据库迁移。
- 共享接口保持员工 Web 兼容：不新增 Web 员工端删除入口；受任务软删除影响的既有通知、申请和日志链接须返回可识别的已删除状态。
- 测试覆盖 Flutter 组件/交互、后端单元与接口、数据库迁移、窄屏与刷新保持、任务删除后的跨入口表现及每日事项逾期边界。
- 管理端员工生命周期、身份证号、员工筛选、已删除任务管理历史和管理端文案清理属于独立的后续 admin change。
