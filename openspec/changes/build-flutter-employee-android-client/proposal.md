## Why

员工客户端需要从 Web/套壳迁移到可继续跨平台发展的 Flutter，同时完整保留现有协作业务并落实 2026-11-08 的新交互。现有 Flutter 工程已部分实现，但员工 Web 随后更新，须按当前 Web 最终有效行为补齐新增功能及原有细节差异。

这是完整迁移的 B，依据[迁移盘点](../../../docs/reviews/潘多拉-Flutter完整迁移盘点与Change边界-2026-11-08.md)的全部 90 项、54 条主规格及 J01–J32，而非只实施 12 项新指导。共享契约 change [A](../archive/2026-11-09-prepare-employee-client-contracts-and-business-upgrade/proposal.md) 已归档。2026-11-17 对齐基线为 `8625617` 的员工 Web、现行主规格与共享后端；原 90/54/12/32 项映射是历史覆盖索引，新增 Web 要求须补充映射，不能因原任务已勾选而跳过。

## What Changes

- 继续完成真正使用 Flutter 控件的完整员工客户端，覆盖创始人、部门负责人、团队负责人、普通员工；保留“首页、公司、日志、统计、我的”及所有二级流程，不把业务界面包装成 WebView。
- 完整迁移认证/强制改密、会话与账号隔离、任务创建/有序负责人/父子关系/字段编辑/进展/完成/重开、申请审核/diff/撤销/失效、专用交接与预设；服务端仍裁决权限、版本和幂等；重开承接负责人和排期原子替换，认证明确有效token轮换、过期重登及刷新中断处理。
- 完整迁移本人月/日历、全局个人任务表单及两种独立置顶、日志全生命周期、共用多标签与创始人维护、平铺评论、本人资料/头像、真实下属只读工作区、站内通知全生命周期及真实统计/本地规则建议。
- 落实新指导：纵向连续范围事项月历与实际命中日清单；首页少量预览且先清单，事件纪逐条展开、任务再进详情；独立表单置顶；官方节假日标识；按日志所属日主动追加名称；约 500ms 长按/单次轻震、月历二维跨月拖动、日轴最终日边界；真实入职时长、组织职务路径及授权下属邮箱；日志所属日排序与填充超限的无损处理；保持横纵日轴各自的全天布局；连续人员日程；六类×三已读状态通知布局；真实四角色动画演示。
- 对齐当前 Web：事件纪仅正文、两行折叠及清单逐条展开；看板截止/紧急度/ID排序和仅清单逾期红底；事项两周密度、较高三轨、准确溢出及整条长按改期；表单置顶整行蓝底；评论只保留发表/本人编辑入口；入职字段去重及去截至日期；通知稳定布局、下属密集月历和新版真实演示。
- apply 每项开始前必须查阅对应 Web 最终生效脚本、样式、接口及相关浏览器检查，实施记录列明来源与行为对照；不能仅凭旧任务描述或个人偏好设计。原生控件适配不得改变业务、交互顺序与信息层级，明确的 Flutter 特有要求继续保留。
- 使用 A 最终输出的范围事项、`/tasks/table`、`/table-pin`、日志填充、资料投影及节假日接口；其余现有服务复用。续做前核对 A 的归档证据及后续 Web 更新后的实际契约，发现新的漂移先协调规划。
- 新 Flutter Android 包采用独立 applicationId，与 `cn.pandora.mobile.debug` 旧套壳共存；提供可复现 APK 构建、签名说明、真实后端联调及安卓模拟器证据。会话安全存储、系统返回、前后台/进程重建、选图、键盘、安全区、字体放大和网络失败属于交付范围。
- 以现行主规格重建共享 delta，保留已落地 Web 场景并扩展至 Flutter，清除旧过渡外观豁免；业务授权和数据语义继续共用。员工 Web 保持参考/过渡，独立管理员继续 PC，不在本 change 停用旧入口。

系统推送按用户决定继续延期，完整站内通知在范围内；不新增移动管理员、全公司通讯录、私人标签、周视图、日志月历、离线写入或外部 LLM。按2026-11-17用户决定，真机验证移出本change完成/归档条件，交由其他组员后续独立验证，发现问题另提change；交接明确触觉实感、真实选图及设备兼容性未覆盖，不以模拟器冒充真机通过。本轮仅修订规划，不修改工程代码、数据、APK或主规格。

## Capabilities

### New Capabilities

- `flutter-employee-client`：完整员工业务在 Flutter 的交互、契约接入、上下文权限、会话/恢复、跨模块状态、Android 共存安装与真实交付证据。

### Modified Capabilities

- `pandora-requirements-aligned-prototype`：将五页载体、首页预览、事项连续月历与状态展示、资料职务路径、下属连续日程、通知布局、触摸拖动及交付范围明确为 Flutter 最终行为，同时保留当前 Web 已落地的全部有效规则，承接正文事件纪、事项整条拖动、置顶和评论呈现。已退役的横向事项和数量标记要求不再作为 MODIFIED 目标。

## Impact

- 现有工程位于 `flutter/`，包含 Dart 业务/数据/界面分层、Android 宿主、资产、测试和构建说明；根目录旧 `android/`、`android_shell/`、`android-shell/` 不读取、不参考、不修改，不替换其包或迁移其本地登录态。
- 接口继续使用现有 `/api/v1` 和 A 的增量，无独立移动后端、重复审批引擎或数据库迁移。A 的最终交接文档 `backend/docs/employee-client-contracts.md` 及后续更新的服务接口文档是实际实施输入；不以 A 时的旧样例覆盖当前契约。
- 依赖包括 Flutter/Dart、状态/路由/HTTP、安全存储、时区和图片处理；具体选型及锁定方式见 design。领域日期与权限模型不依赖 Android，实现可为未来平台复用；首轮只交付安卓。
- 验证覆盖全部迁移项和 32 条路径，按 Flutter 逻辑/组件、真实 API 集成和安卓模拟器分层取证；服务或旧 Web 的 PASS 不能替代 Flutter 交付。PC 管理操作及 A 迁移作为跨端联动依赖验证，不迁入员工客户端。
