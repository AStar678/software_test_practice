## Goals / Non-Goals

**Goals:** 原有员工业务与新交互在同一 Flutter 客户端闭环；服务端唯一裁决，客户端保留有效版/提议/历史区别；日期与上下文模型可跨平台复用；Android 产物及触摸、生命周期有独立证据。盘点、规格、任务和验收有具体映射，防止迁移漏项。

**Non-Goals:** 不移植 Java、不包装业务 WebView、不另建移动后端或审批状态机、不复制 PC 管理界面、不承诺离线写入/持久化业务草稿/iOS 交付。不自动下线员工 Web，不发布到商店或改生产部署。本 change 不承担 A 的数据迁移实现或用 B 偷补未完成的 A。

## Decisions

### D1. A 先实施，B 可提前规划；共享 delta 顺序应用

B 当前按 A 的已提出方案规划，实施前第一项任务确认 A 当前独立 e13 PASS、归档、实际代码/契约与交接文档，记录归档路径、提交、接口示例及差异结论。A 当前 0/46，不能将它视为可用环境。用户“再创建 B”只提前规划时间，不撤销 A → B 实施顺序。

B 的现有能力 delta 共 11 个完整 MODIFIED block。`Horizontal continuous daily-item calendar`、`Daily-item status count markers`、`Minimal profile page`、`Strict prototype scope` 的起点复制 A 的预期修改，其余复制当前主规格；所有原场景保留，仅明确过渡 Web 与 Flutter 的区别。B 必须在 A 归档后重核这四块，先让 A 同步，再同步/归档 B；不能在 A 未完成时提前同步 B 覆盖共享规格。历史 Requirement 标题保留以便精确匹配，正文才定义最终行为；包括旧 `Shared single-select...` 的实际有序多选规则仍完整承接。

主规格是共享业务，`flutter-employee-client` 是载体、完整流程接入、生命周期与交付要求。新能力中对业务的复述用于明确 Flutter 必须落地的流程，不另建第二套服务规则。遇到真正的新业务缺口，先定位是否 A 未兑现、现有服务缺陷或新需求，再修正对应 change 规划；不能用客户端伪造/扩权/永久 mock 处理。

备选：等 A 归档才提 B 会阻碍现在审阅全量迁移；并行实现两套未对齐契约容易返工。采用提前可审阅、实施有明确前置的方式。

### D2. 独立 Flutter 工程和可替换平台边界

工程放 `flutter/`，包含 `lib/core`（会话/HTTP/日期/路由/主题）、按业务分组的 `features/*/{data,domain,presentation}`、`test/`、`integration_test/`、`assets/` 和 `android/` 宿主。根目录旧 Android 工程保持独立；仅新工程宿主承担必要平台配置。

选 Flutter stable/Dart，实施时记录并锁定可用具体版本（`.fvmrc` 或等效机器可读 SDK pin、提交应用 `pubspec.lock` 和 Gradle wrapper），不在未实际探测环境时虚构版本。状态采用 Riverpod，路由 go_router，HTTP Dio，凭证 flutter_secure_storage，IANA 时区 timezone，图片选择 image_picker + image 处理；优先不用代码生成框架完成类型和状态，减少首轮工具链负担。每个依赖在加入时核对最低 Android 支持、维护/许可并锁文件；版本不能兼容最低系统时先选兼容版本，不静默提高交付下限。

纯 Dart 业务日期、授权上下文、范围覆盖/条布局及写入状态与 Flutter/Android 插件隔离；数据仓库返回实际 DTO/能力/错误。HTTP 实现、时钟、图片选择和触觉为可替换适配边界。运行时无“演示模式假后端”；固定响应只用于隔离自动检查。

备选：原生 Java 修复、WebView 或巨型单页面会丢失本次原生/未来跨平台目标；引入完整新后端/BFF 会扩大审批与权限维护。采用 Flutter 控件和现有 API。

### D3. 独立包、签名和网络环境

确定 release applicationId 为 `cn.pandora.employee.flutter`，debug 加 `.debug`，首个版本 `1.0.0+1`；显示名“潘多拉”，debug 加“开发版”。两者均与旧 shell、早期 Java 包不同，共存安装，无旧签名/SharedPreferences/localStorage 数据迁移。首次需重新登录共享后端；不需要为兼容旧 shell 签名而寻找旧私钥。

首轮支持 Android 8.0/API 26 起，目标/compile SDK 采用实施时 Flutter stable 支持的当前稳定 SDK、至少 API 36；实际记录版本，Android 8 边界用模拟器或设备验证，现代 Android 真机完成核心触摸/生命周期测试。产物至少为设备可装的签名 release APK；debug 仅开发检查，不能冒称正式交付包。可首次生成新的项目发布签名，通过忽略的本机 keystore/环境配置使用，持续保管便于同包后续升级；记录证书指纹而非密钥。不得提交 keystore、密码、token 或内置账号密码。

API base URL 通过明确构建配置提供且包含 `/api/v1`，不在界面默认暴露技术设置。release 使用有效 HTTPS 和系统证书链，禁止接受任意证书；确需局域网 HTTP 联调只放 debug 的明确主机例外，不扩大 release 明文策略。请求日志脱敏且发布包禁用敏感正文日志；无自定义外源节假日访问。输出构建/安装命令、SDK/JDK/ABI、版本、签名指纹、APK SHA256、后端地址类型和环境；不把本轮规划当实际构建记录。

备选：覆盖旧包需要旧签名及本地数据迁移。用户已选择共存，独立包便于过渡和对照；同一后端数据仍是真实共享，不复制业务库。

### D4. 显式会话状态、请求代次及安全恢复

会话状态为未登录/校验中/受限改密/正常/失效。凭证仅安全存储；启动先查 session，受限时不发 `/me`、home、通知或 refresh，改密成功清全部本地凭证并重新登录。正常会话按实际 expiresAt 串行刷新，多个请求合并刷新，避免刷新风暴；401/撤销/停用导致失效，普通 403/404 对象失权清对象而非一律退出。离线无法核验时显示联网重试，不展示旧敏感正文冒充已授权。

所有异步结果携带 accountEpoch，列表再带 person/context/queryGeneration。换账号清账号 Riverpod scope、Dio cancel token、内存 DTO/草稿、路由和未决提交；相同账号切条件也隔离代次。每次前台恢复重验会话、相关详情/能力/申请，可能已冻结或改派；进程重建只恢复账号命名空间的非敏感偏好/日期锚点，业务正文、联系方式、token 不进入普通 restoration bucket。浏览位置重取授权数据后恢复；草稿只在同一有效会话内存保留，不提供跨进程持久化承诺。活动编辑丢失的系统重建需明确恢复提示，不暗中重放写请求。

写入状态独立于页面 loading：草稿→提交中→成功/确定失败/结果待确认。幂等键使用安全随机值、满足 8–80 位字符限制；同体同版本未知结果保留同键重试，改变体/目标/版本新建操作。428/412/409 显示明确冲突并保草稿，回读后由用户重新确认，禁止自动 merge 覆盖。端点分别配置版本来源：任务、申请、日志、评论各自 ETag；个人 pin 不机械带任务 If-Match。失权后不可展示旧缓存成功或重放。

备选：仅 UI mounted 检查挡不住跨账号缓存污染；普通偏好存 token 和持久化完整页面会泄漏敏感数据。采用身份代次+安全凭证+授权后恢复。

### D5. 类型化日期、分页及 A 契约适配

date-only 用明确年月日值对象，不执行“UTC 午夜→设备日期”转换。Instant 与 OrganizationZone 分开，用 `/me.organizationTimeZone`、服务响应 businessDate；后台停留跨公司零点后重取业务日。旧 allDay、普通 timed 和 pendingSchedule 分开处理。共用纯函数计算绘制占用/日轴最终边界，但个人表单日期筛选不复用半开日历算法，交给 A 服务管线；tenure 直接渲染服务投影。

| 用途 | 实际读取/写入与客户端责任 |
| --- | --- |
| 范围事项 | `/daily-items?from=&to=` 每窗口 ≤93 日，`nextOffset` 逐页至结束，ID 去重保完整原范围；详情/编辑只发 startDate/endDate 成对或省略，正文/完成不压缩范围。摘要用于准确数量，不从首屏推断全量。响应后刷新旧/新覆盖窗口及 home。 |
| 个人表单 | `/tasks/table` 独立查询仓库，relation/completion/q/from/to/sort/direction/limit/offset 按 A；服务全局分组排序计数，客户端不再本地重排当前页。`tablePinned/canTablePin` 和 `/table-pin` 与 `pinned/canPin`、`/pin` 独立。 |
| 日志填充 | `/work-logs/fill-source?businessDate=` 只在用户主动时读；要求 `complete:true` 和两组完整名称，按各组 ID 去重；不按近三日阻止仍未满 24h 的编辑。 |
| 资料 | 本人/有权详情的 hireDate、tenure/email 白名单；树摘要和候选 DTO 不接受详情私密字段的扩散。 |
| 节假日 | `/calendar/holidays/{year}` 按可见年份缓存 ready/stale/missing，仅从自有 API 取；missing 不画官方休班，stale 保留旧数据并可读地提示。无移动 admin refresh。 |
| 其余分页 | 通用 tasks 的 nextCursor 是偏移字符串，comments 是真实 ID 游标，日志/通知/事项 nextOffset、申请 offset。各适配器独立，ID 去重/查询代次通用；不强造一个统一数字 cursor。 |

日志填充仅一次主动响应追加到等待结束时的最新正文，避免覆盖期间输入；目标/日期/会话变更则丢弃。格式为两个有内容的分组标题“每日事项”“任务”与逐项名称换行，空组不生成空标题，原正文有内容时加空行。只去源结果的组内重复 ID，重复点击属于新主动追加，不按文本删用户内容；提交中禁重复按钮、不得失败后自动重复追加。名称可能同名但 ID 不同，均保留。无结果简短提示，无半组成功。

### D6. 路由与授权上下文贯穿嵌套路径

使用五分支导航栈，任务表单/通知/申请/资料/清单为二级。详情接受不可升级的 `normal`、`subordinate(personId, chainOrigin)`、`notificationHistory(notificationId)`；下属嵌套父子/关联/申请/评论仍继承只读业务上下文，即使用户在正常入口有创建或负责身份，也不在该路径提供业务动作。历史专用读取的 DTO 不写正常任务缓存，没有评论及写能力。正常入口按服务端 editableFields/can* 决定，不以组织身份文本/职位名猜权限。

返回优先由当前局部层处理：输入法/活动输入、可取消交互或浮层、日清单、详情、二级页、当前主栈；保存/删除后只弹当前目标并刷新来源，取消不写。含未保存草稿的离开提供必要确认；手势取消/系统中断不自动开详情。恢复 key 至少含账号、日历类型、personId、模式、筛选；本人事项/本人任务/每个下属独立。需要复核权利时重读，不从旧 route extra 恢复正文。

备选：给详情一个可变 readOnly 布尔值容易在嵌套跳转/评论保存后丢失来源。显式不可升级上下文与分离 DTO 防止这类误写。

### D7. 两种月历、日轴及长按的统一几何基础

本人任务与下属任务共用无业务写入的日期布局/占用计算器；下属不创建拖动识别器，事项只复用月份网格基础，不复用任务审批/拖动。按月分块的虚拟列表双向补载，以真实日期+格内偏移为锚点；跨月条按周切段且记录真实起止/续接边缘及每个命中日矩形。并发补载以查询代次丢旧响应，日期窗口缓存有界但当前锚点/活动拖动所需范围不可回收；月份裁剪不意味着数据截断，日清单始终完整分页。条、文本、溢出、空格的命中都映射实际触点日，不能统一回条 startDate。

首页用协调的 sliver/scroll controller：上方卡片属于整页滚动，事项月份接续纵向展开/按锚点延伸，不做两个抢同方向手势的固定高度内滚容器。公司/人员月历为独立全页视口。任务标题/时间在任务条框内；事项短条可外置名称；不将两套新指导混用。密度/更多展示不隐藏真实溢出总数，屏幕阅读器能到完整清单。

日轴默认横向每任务一行、可切纵向；对碰撞簇分栏，超过五项不截断，用横滚/布局与完整清单保证可访问；旧全天及覆盖整日单独区域，点任务用最小触摸宽度而不修改真实工期。时间轴与文字同用有效/提议投影源。

交互为 idle→pressCandidate→activeDrag→confirmation→submitting。约 500ms 未滚动才激活、发一次 `HapticFeedback.lightImpact`；不能每帧/越格重复震动，无能力时视觉反馈降级。激活前 Flutter 滚动手势优先；激活后独占该次指针，记录原完整排期/版本/抓取日。月历由二维日期 hit map 计算差量，靠边按节流速度自动滚动并补载，更新映射而不重置抓取日；缩放仅真端点。日轴按相对小时差保留分钟，原始资格与最终 [dayStart,nextDayStart]、有序性在预览/键盘/确认三处统一校验；不把日轴限制施加 API 或详情跨日输入。松开只开轻量原因确认，保存仍走原 reschedule/版本/幂等/实际申请人审核。取消、离开、后台、无位移、无效点均回 idle，不触发普通点击。

备选：现成日历组件若不能保证跨月二维命中、真实端点/提议以及密集重叠会逼迫业务妥协；只用纵向像素估日期也会跨行错误。采用可独立检查的布局/命中算法与 Flutter 手势，不自画无法访问的纯画布。键盘与可访问动作复用同一调整器，免拖动完成等效操作。

### D8. 视觉、移动输入和跨模块刷新

沿用手账主题的信息层级、圆角、颜色与标记：ink `#51495e`、brand `#a34470`、paper `#fff9fc`、mint `#dcf2e6`、petal `#fbe5ef`、muted `#7d6e80`，大圆角约20、按钮约13，保持已有业务布局及新指导明确的变化；不用默认 Material 配色悄悄重设计。可复用根 SVG 品牌资产（按 Flutter 合法资产格式处理），系统中文字体为主，不拷贝无授权桌面字体。窄屏 320/390 逻辑宽度、短屏、现代真机及放大字体下验证；头像、行文、状态文本不可只靠颜色。正式文案短、保留原因/错误/冻结/只读/实际审核人等决策信息。

资料图片源先校验类型/10MB，中心裁切到256 JPEG，再检查 ≤300000 bytes/≤512 px/data URI≤400000；需要权限只由选择行为触发，优先系统相册，不申请无关存储权限。取消、处理错误、服务拒绝不覆盖原资料，发布包不保留临时照片。

写后按对象及业务依赖失效：任务/申请影响详情、日历有效/提议、表单、home、统计/通知；事项影响全部旧新窗口及 home；日志影响本人/授权人员列表、详情；评论只刷新当前对象评论和相关未读；pin 只更新对应偏好查询，不改任务 rowVersion。失效后重取而非拼造最终状态，尤其不能审批生效前改普通 DTO。前台恢复/下拉刷新走相同路径，表单无额外顶栏刷新按钮。

### D9. 分层验收，全部盘点有落点

## Risks / Trade-offs

- [A 尚未实现导致契约漂移] → 第一任务强制按最终 A 重核四个重叠 block、真实样例和错误，不提前同步 B，不用客户端补假接口。
- [长流程迁移漏掉旧业务] → 90 项/54 条/32 路径映射至具体任务，四角色闭环，交接/重开/历史例外等不留到“以后”。
- [同一任务多入口导致误写或缓存泄露] → 不可升级上下文、分离历史 DTO、账号代次和每次权利重读，覆盖身份重叠及迟到响应。
- [虚拟连续月份和跨月拖动复杂] → 先验证日期/命中/锚点纯算法，再组件与真机测自动滚动和手势中断；先构建静态正确性再添加写入口。
- [offset 并发下跨请求不冻结] → 沿 A 一致单响应语义，查询代次/ID 去重、写后重载，不将已读首屏当完整集合。
- [系统重建丢内存草稿] → 明确首轮不承诺持久草稿，不重放未知写；同会话普通失败/返回保草稿，系统重建给明确反馈。
- [依赖/SDK/设备当前不可用] → 先定位实际环境再锁版本，缺项记录具体阻塞；没有真机或签名 APK 不宣布安卓交付通过。
- [共存应用对同一后端并发修改] → 用现有版本/幂等/权限冲突处理，跨端回读验证；不复制数据、不自动退出或停用旧端。

## Migration Plan

1. A 先独立验证并归档；将最终契约/主规格/真实样例与 B 核对，有变化先修订 B 规划和映射。
2. 定位 Flutter/Dart/JDK/Android SDK/设备，创建独立 `flutter/` 和包标识，锁依赖、完成正常/受限登录及隔离骨架，不动常用业务库。
3. 在隔离真实 A 后端逐个模块实现和验证，从只读加载/日期/权限开始，再开启版本化写入、审批与跨入口失效；按表中全部业务闭环，不以页面骨架代替交付。
4. 使用显式隔离演示库加载四角色主线和独立极限夹具，跑真实集成和安卓设备验收；记录 A/PC 依赖证据与 B 新证据的边界。
5. 产出签名 release APK、构建/安装/环境/证书指纹/哈希和交接文档，设备共存安装后重新登录，PC/Web 回读共享数据。此 change 不自动部署后端或停止旧 Web，不推送商店。
6. 回退客户端时卸载/停用新独立包即可继续既有过渡 Web/套壳，后端保留 A 兼容版本及新业务数据；不得回退旧数据库或压缩跨日事项。需要恢复同包旧 APK 时使用保管的同签名及版本策略，回退前后均不能清理后端业务数据。
