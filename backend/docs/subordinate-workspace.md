# 下属资料与工作查看

我的 → 下属资料按真实直属关系逐层排列。左侧加减按钮展开或收起，点击姓名先进入该人员的资料卡；资料卡分别提供“查看日程”和“查看日志”。创始人和管理者能看到授权的下属及其下属，普通员工显示暂无下属。

每个节点在姓名下方显示组织行：身份（创始人/部门负责人/团队负责人/员工）、职位、真实部门和团队分别呈现。有职位时不会省略部门或团队；无部门者显示“公司层”，不伪造组织、不显示原始空值。展开状态不跨账号保留。

工作页为独立全屏小屏设计，顶部姓名、职位和组织，下方日程/日志切换。日程参考本人日历提供月视图和日视图，默认月历，按公司日期查看当前负责的授权任务。月历按周一至周日排列，按任务占用的公司日期绘制日级连续条，不按小时缩窄或偏移；午夜截止不多占次日，零时长保留零工期并显示时点标记；超过容量时点+N进入完整当天。日视图提供00:00至24:00时间轴、重叠任务分栏、全天区和任务清单切换。箭头在月历按月翻页、日视图按天翻页；日期选择可跳转，今天回当前日。跨日延续、整日、午夜截止、零时长和完成状态保持真实：已完成任务在月历、日轴、全天区和清单都有“已完成”文字与样式。点任务进入详情，返回仍是该人员、该日期和月/日模式。

下属工作页、任务详情、关联任务及日志详情均保持“仅浏览和评论”模式，即使查看者同时是该任务的创建者或负责人，也不从该导航链出现编辑、排期、置顶、审核等写入口；服务端继续独立鉴权。鼠标、触摸和键盘不能在下属日程触发调时。关闭子详情只返回上一层下属页面，不改变本人的日历和日志状态。

已发布任务进入修改、进展、完成、重开或交接审核时显示虚线框和“审核中”；有排期变化时只在提议位置显示，刷新保持；通过后按新排期显示实线，驳回/撤回/失效恢复有效排期，普通详情和提醒仍使用有效版本。

日志按日期卡片展示摘要，点击全文进入详情及评论，每页十条、可加载更早日志。本人日志页仍只显示本人，个人日历和任务表单范围不变。人员详情返回会重新校验权限并读取内容；没有权限、加载失败会清空工作列表并提示重试。

资料按当前返回权限显示手机号；资料卡与工作页均不因进入下属导航而扩大业务操作权。界面没有代替下属编辑日志、设置交接预设或拖动日程的入口。

本地验证：`CHROME_BIN=… python3 backend/scripts/check_subordinate_workspace.py`（组织行、完成状态、月/日几何、无拖动、详情权限、日志与失权/旧响应）以及 `CHROME_BIN=… python3 backend/scripts/check_schedule_drag.py`（下属月/日待审提议位置与审核终态）。随机测试库自动创建清理，截图和报告位于 output/subordinate-workspace/。需要先构建 backend/target/pandora-backend-0.1.0.jar。本轮不做手机真机测试，仅真实浏览器尺寸模拟；云端发布另行处理。
