# 本地后端实施状态

本次代码以用户最新修改的 **MySQL** 为数据库方向，采用 Java 21、Spring Boot 3.5.16、Spring JDBC 和 Flyway。V1.1 文档中的 PostgreSQL 建表附件没有直接执行；本地 V1 迁移包含 17 张表，V2 迁移明确幂等键的大小写敏感比较，V3 为首页信息加入编辑版本号，V4 加入个人联系电话、邮箱和资料版本号，均位于 `src/main/resources/db/migration/`。本文件描述当前代码范围，不代表详细设计全部交付。

## 已落地的代码

| 范围 | 当前行为 |
| --- | --- |
| 登录与会话 | 账号密码登录，BCrypt 密码哈希，随机 Bearer 凭据仅保存摘要，数据库会话有效期和撤销检查；刷新轮换当前凭据，退出撤销会话。 |
| 身份与可见范围 | 组织隔离，上层公司范围、中层本部门范围、下层本人关系；管理员通过独立后台只读接口查看人员、团队和审计。每次请求读取当前账号状态。 |
| 任务 | 列表、详情、创建、修改、进展、完成、重开；多负责人、紧急程度、定时/全天排期及父子任务；有效版本与提议版本分开。 |
| 审批 | 根据负责人层级计算审核人；创建者等于审核人且亲自操作时免审；同一任务唯一待审并冻结；通过、退回、申请人撤销、拒绝后重提。待创建任务不进入普通任务集合和统计。 |
| 状态与并发 | 进展生效进入进行中；完成退回进入进行中、撤销恢复原状态；重开增加执行轮次。写事务锁组织行，再锁任务/申请，并校验版本；父子关系防环。 |
| 日志 | 默认本人及授权范围查询，作者本人新增、修改和删除，关联任务独立过滤；带版本校验、幂等和审计。日志删除属于本轮本地 CRUD 接口，不是旧 V1.0 文档中的既定页面入口。 |
| 首页 | 查询公司信息、个人信息、本人被派发未完成任务和近 10 个自然日的日志；各块最多 10 条。公司信息在业务端只读，维护入口留待管理员后台；个人信息由本人新增、编辑、删除，带版本校验和幂等，每类最多10条。 |
| 个人资料 | 本人可修改姓名、联系电话和邮箱；账号、部门、身份和直属上级只读。联系电话和邮箱不进入人员目录，保存带版本校验和幂等。 |
| 通知 | 业务事务同时保存事件和审计；定时工作器分发站内消息，同一事件同一接收人去重；本人查看、已读和隐藏，消息动作不办理审批。 |
| 提醒 | 扫描有效且未完成、无待审的任务；临期 72 小时内按公司自然日去重，逾期按到期版本去重，两者均区分执行轮次；账本与提醒事件在同一事务保存。 |
| 统计与规则建议 | 统计当前有效、可见任务；同步生成明确标注 `rule_based` 的临期/逾期建议。没有调用外部模型。读取分析结果再次检查来源任务可见性。 |
| 本地数据 | 首次开启种子时初始化演示组织、7 个账号及任务、日志、首页信息；重启保留现有业务数据，不自动重置。 |

任务、审批、日志和通知等业务写入要求 `Idempotency-Key`。同一操作范围内相同键和相同正文/前置版本重放原命令结果，不同请求返回 409。PATCH 使用最新 GET 返回的 `ETag` 作为 `If-Match`；缺少返回 428，过期返回 412。业务错误统一返回 `code` 与 `message`。登录、会话刷新和退出不使用这套业务幂等协议。

## 当前实施边界

- 当前是本地可运行后端，不是生产上线版本。API 与定时工作器运行在同一个应用进程；未拆为独立 Worker 服务。
- 为保证本地演示事务顺序，同一组织的写命令串行执行，尚未作高并发性能调优或容量测试。
- 未提供组织、账号、职位与授权范围的完整后台维护、人员交接授权及审核改派工作流。中层当前按所属部门查询，没有实现详细设计中的多团队 `management_scopes`。
- 未提供任务私人草稿、个人置顶、消息撤回/保留期清理、推送设备管理、完整提醒参数后台。
- 没有接入操作系统推送、短信、邮件、Redis 或真实模型；通知只保存并展示站内消息。规则分析不是深度 AI，也不自动修改任务。
- 统计当前支持 `scope=self|visible`，不支持日期范围统计；传入 `from/to` 会明确拒绝。规则分析结果会检查来源访问权限；未实现完整的内容版本缓存失效、词云、历史组织范围报表和所有 V1.0 指标。
- 提醒采用当前扫描时点及每日去重，尚未实现详细设计中的 72/48/24 小时与当日 09:00 可配置调度组合、独立租约队列及外部渠道重试。
- 没有完成生产级 TLS、登录限流、设备会话策略、备份恢复演练、部署监控和负载测试。数据库外部直写也不等于经过应用命令校验。

## 原项目页面接入

本地服务根地址加载项目原 `index.html`，继续跳转原 `潘多拉-交互原型.html`。保留五个页面、导图四象限和原任务弹层；视图页按最新需求改为月历、周历和纵向日程。视图页与导图页共用相同的外框宽高、圆角和导航，内部增加相同风格的卡片边框。月历全部周、周历七列及周/日完整时间范围按可用高度适配，在一屏内展示。任务创建入口位于视图页；日志页用“工作日志、待我审核、我的申请”切换内容，移除日志查找。

- `潘多拉-api.js`：真实登录、当前账号、授权数据加载、请求错误、幂等重试及会话清理。
- `潘多拉-任务接入.js`：任务创建/修改/进展/完成/重开；审批快照、通过/退回/撤销/重提。待创建申请单独展示，不混入已生效日历。
- `潘多拉-工作区接入.js`：首页信息、日志、通知、真实统计及规则分析；保留从已授权任务提取的关键词词云。
- `潘多拉-日程视图.js` 与 `潘多拉-界面调整.css`：连续色条月历、日期切换、全天任务、纵向时间轴和密集任务展开。月历跨日连条、跨周分段，任务行数按实际周高度计算（最多四行），按当天实际隐藏集合计算“+N 项”；点击日期打开完整清单。周/日时间轴按可用高度缩放，最小可点击高度同步参与分组。支持原生农历日期显示。
- `潘多拉-个人资料.js`：本人资料查看与编辑，保存后同步首页和人员名称。

顶部身份按钮进入对应账号登录，实际权限仍由后端决定。任务参与人以最小的姓名摘要展示，派发候选仍限制为 `/users` 授权结果。打开表单时记录版本，冲突会要求重新打开，不静默覆盖。

构建只打包明确列出的前端文件，不暴露项目目录或数据库配置。旧独立调试页位于 `/debug.html`。

## 验证方法与结果

`scripts/smoke_test.py` 仅依赖 Python 标准库，通过运行中的 HTTP API 验证真实 MySQL 环境。它从登录和 `/me` 获取用户标识，不硬编码用户 ID；每次创建 `Smoke <UUID>` 前缀的数据，不删库、不重置种子、不清理其他业务记录。

在 `backend` 目录、服务启动后运行：

```sh
python3 scripts/smoke_test.py --base-url http://127.0.0.1:8080 --report .runtime/smoke-report.json
```

自定义服务地址可用 `PANDORA_BASE_URL`，演示密码可用 `PANDORA_DEMO_PASSWORD`。报告包含通过项目、创建记录 ID 与失败原因，不包含密码或登录凭据。测试覆盖幂等、待创建隔离、审核权、旧有效版本和冻结、完成退回/撤销/重开、负责人变更路由、日志权限、通知与待办分离、统计、审批撤销竞争和父子独立。

**2026-10-12 接入前的后端基线验证：真实 MySQL HTTP 检查 50 项全部通过，耗时 4.13 秒。** 运行地址为 `http://127.0.0.1:8080`，应用连接本地 MySQL 9.3，Flyway 已迁移至 V2。报告为 `.runtime/smoke-report.json`，本轮测试数据前缀 `Smoke 8bdb27f4-bf90-40c6-ab32-0061d241f447`；本轮只新增 9 个任务和 1 条日志及其派生审批/事件，没有重置原种子。

检查结果覆盖待创建对上层隔离、幂等重放与异正文 409、旧有效版与待审冻结、旧 ETag 412、完成退回和撤销的不同结果、重开轮次、负责人转移沿用旧审核路线及新旧访问权切换、拒绝创建后重提、日志独立权限、通知已读/隐藏不审批、有效任务统计、并发审批与撤销单赢家、父子状态独立及自引用拒绝。规则分析和管理端权限也通过 HTTP 检查。V2 新增检查证实：同一用户、同一正文、仅大小写不同的幂等键生成不同任务及申请，且各键分别重放自己的原结果。

接入前的 Java 单元测试共 **12 项通过**：`TaskServiceTest` 9 项、`AccessTest` 3 项，失败、错误和跳过均为 0。真实 MySQL 的 **18 项只读完整性检查全部通过**，报告为 `.runtime/database-check.json`。脚本语法和手工 HTTP 示例中的 13 段 JSON 均通过解析检查。以上不覆盖负载、跨数据库版本兼容、操作系统推送或生产恢复演练。

手工请求示例见 [api-examples.http](api-examples.http)。示例中的 ID、令牌和 ETag 需要用真实响应替换，按当前待审状态顺序执行，不能一次性把所有动作发送给同一未办结任务。
