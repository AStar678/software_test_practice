# 通知、创建任务与操作者审核（V28）

## 使用变化

通知默认显示所属任务/对象、类型、已读状态、通知时间。可切换完整摘要，组合筛选已读状态与通知类型；打开才标已读，返回保留条件，切换账号恢复默认筛选。没有关联任务时显示安全对象名或占位信息。

创建、重提和编辑任务使用共用标签多选按钮，点一次选中，再点取消；选择顺序保留，取消后重新选中会排在末尾。名称位于色块下方，长名称自动换行。日志仍单选。任务日程颜色依次取本人私人标签、首个共用标签、默认粉色；详情展示全部共用标签。

负责人按真实直属关系展开：创始人、部门负责人、团队负责人、员工。展开与勾选独立，支持跨分支多选、姓名搜索及前后调整顺序；取消丢弃选人工作副本，确认才写回表单。日期和时分按开始、截止分组；窄屏换行。创建、编辑、重提和重开均须填写日期与时刻，不再选择全天类型。“设为全天”将开始日设为00:00、截止日推进至次日00:00，可继续修改；对同一结果重复点击不会再次延长。旧全天数据编辑时按其实际保存的起止时刻回显。

月历任务条两端的箭头可横向拖动，以一天为步长并保留时刻；日视图默认“横向排期”，以15分钟为步长，仍可切换纵向时间轴或任务清单。拖动时显示预览，松开进入编辑表单，填写原因、确认后提交；方向键也可调整。取消或Esc不保存，截止早于开始会提示。任务条跨周/月/日的续接端没有虚假的端点手柄；已完成、审核中及无基础编辑权的任务不显示手柄。只有负责人身份而无编辑权不能拖动。审核前日历保持原有效排期，拖动期间版本变化会提示重新调整。

## 审核和权限

创建、重提、资料修改、进展、完成、重开和专用交接统一按**本次实际操作者的直属上级**审核。上级代办交接时，使用代办人自己的上级。固定创始人继续免审，但仍须通过操作权、版本、负责人、排期等校验。缺少有效上级、上级不可审核或组织不合法时阻断。

业务接管只改变后续办理权，不改变原创建人、原申请人或审核依据。组织调整、停用、接管刷新有效待审，过期先处理、终态不复活；旧审核人失去决定权，记录改派并通知新审核人。已办结历史不重写。

## 接口兼容

- `GET /api/v1/notifications`：`readStatus=all|unread|read`，`category=all|review|result|reminder|comment|other`，可与 `limit/offset` 组合。先筛选再分页，`total` 为匹配总数，`unreadCount` 为所有可见通知未读数。旧 `unread=true` 等价于 `readStatus=unread`，`unread=false` 为全部；新旧冲突或非法值返回 400。
- 每条通知带结构化 `category`。只有当前可办理且未截止、未撤回的申请才归 `review`；已办结的旧提交消息归 `other`，不能当作新结果消息。实际通过、拒绝、撤销、失效、直接生效事件归 `result`。详情与列表延续正文裁剪和历史只读规则。
- 任务写入 `tagIds: [id1,id2]`，空数组清除。响应 `tags/tagIds` 是完整有序集合，旧 `tag/tagId` 投影第一项。未传标签字段沿用完整集合；多标签任务显式只传旧 `tagId` 返回 409 `MULTI_TAG_CLIENT_REQUIRED`，同时传冲突的新旧字段返回 400。重复、跨公司、私人冒充共用、已删除标签新引用均拒绝。
- `assignee-candidates` 增加 `managerId/teamName/placementType`，仅提供合法员工最小目录字段，不提供电话或邮箱。候选可选不赋予任务、日志或交接操作权。
- 审核预览 `reviewerBasis=operator`。刷新和决定使用申请记录里的 `applicantId`，不使用当前查看者替代申请人。

## 升级和回退

Flyway `V28__task_version_multiple_tags.sql` 新建有序 `task_version_tags`。旧非空 `tag_id` 按序号 0 回填，保留稳定 ID、原名称/颜色快照及历史版本；旧空值映射空集合。V17/V27 与旧投影列保留。

正常启动的 `LegacyCreationRoutes` 仅刷新带旧原因码的有效待审，使用组织锁、版本校验、截止处理与原申请人重新计算；可重复启动，已迁移记录不重复改派。若禁用启动维护，发布时须显式开启 `pandora.startup-maintenance-enabled=true` 执行这一步。无法修复的组织问题写入 V28 `migration_findings`，修复组织后按正常组织调整流程刷新；不得手工改写申请人或批准记录。

发布应整体升级后端和在线网页并先备份数据库。出现多标签数据后，不可直接回退到单标签旧服务；使用兼容集合的修复版本。此变更未发布云端，不操作正式数据。

## 本人任务表单、标签维护和写日志入口

任务表单仅列出本人原始创建或当前负责的任务，先按本人关系过滤，再搜索、排序、计数和分页；仅因上下级关系可见的任务不进入表单。日历仍仅显示本人负责的任务。

所有标签（含私人标签）的创建、改名、改色、删除仅由公司固定创始人执行，非创始人仅可在任务/日志编辑中选择和清除。创始人从“我的 → 标签管理”维护；日程页的标签管理/图例行已移除。已有私人颜色覆盖、共用标签首项颜色与默认粉色均保留，旧数据不清空。

“写日志”统一创建公司今天、昨天、前天缺失的日志，只提供未创建日期，三天都已写时提示从日志详情编辑。编辑通过日志详情/列表的编辑按钮进入。创建期间若其他会话先创建同日记录，保留当前草稿并提示，不能自动改成编辑覆盖已有记录。

验证：`CHROME_BIN=… python3 backend/scripts/check_log_backfill_entry.py`，使用独立一次性测试库，覆盖管理层任务表单、共用/私人标签API越权、标签颜色、三天日志创建、显式编辑及并发重复创建；截图在 `output/entry-refinement/`。


## 日志页与日志表单

日志页固定只展示本人日志，删除人员/部门/团队筛选；计数、旧状态和刷新都不能混入他人记录。人员资料中的有权日志阅读改为独立弹层，正常权限保留。

日志卡片去掉“查看与评论”按钮，点击正文或空白直接打开详情评论；聚焦卡片按Enter或空格也可进入。卡片上的编辑和关联任务按钮各自操作，不额外打开详情。日期和标签统一为相同字段结构、标题间距及控件高度，在320/390/1440宽度验证创建和编辑布局。
