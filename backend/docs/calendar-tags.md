# 日程标签

日程的月视图和日视图都提供“编辑标签”。员工可新增私人标签并在任务详情中选择“我的标签”；创始人还可维护公司共用标签。新增表单省去范围选择，员工默认创建私人标签，创始人默认创建共用标签。颜色沿用产品的八色柔和色板，日程同时显示名称与颜色图例。

V27 为已有公司补充六个共用分类：项目工作、会议沟通、专注处理、交付验收、学习成长、日常事务。同名共用标签已有的颜色与删除状态保持不变。迁移不自动重写任务内容或历史记录。

## 权限与接口

- `GET /api/v1/tags` 只返回公司共用标签和当前员工的私人标签。每项提供 `scope` 和 `canEdit`。
- `POST /api/v1/tags` 支持 `name`、`color`、`scope`。`scope=personal` 创建私人标签；省略或设为 `shared` 保持创始人专属的旧接口行为。
- `PATCH/DELETE /api/v1/tags/{id}` 保留版本检查。私人标签只允许本人维护，创始人也不能读取或修改别人的私人标签；管理员不进入业务接口。
- `PUT /api/v1/tasks/{id}/personal-tag` 使用 `Idempotency-Key` 和 `{"tagId":"私人标签 ID"}`。传入 `null` 清除个人标记。任务必须已发布且当前员工有查看权限。
- 任务列表和详情分别返回 `tag`（共用）和 `personalTag`（当前员工）。私人标签优先决定该员工看到的日程颜色，不改变共用标签。

私人标记单独存储于 `personal_task_tags`，不创建任务版本、审批、通知或共享历史。标签所属人与关联表的使用人通过组合外键绑定。任务和日志的共用标签字段拒绝私人标签。删除私人标签时移除个人关联并恢复共用颜色；删除共用标签仍保留原引用及“已删除”标识。

标签名称在公司共用范围或各自私人范围内唯一。私人标签改名、改色立即影响本人视图；既有已删除名称仍被保留，避免历史身份混淆。

## 验证

先构建当前 JAR，再运行 `python3 backend/scripts/check_calendar_tags.py`。脚本创建随机临时数据库并独占本机 18199 端口，验证跨员工、跨公司权限、共用快照隔离、重命名、删除、刷新持久化及 320/390/844/1440 像素浏览器布局，结束后移除数据库。沿用 `check_fixed_communication_web.py` 验证原共用标签、评论和通知流程。
