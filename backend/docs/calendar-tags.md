# 当前标签接口（2026-11-04）

本页记录 `refine-notifications-task-editing-and-staff-browsing` 的当前实现契约。V27 曾引入私人标签；V30 会检查共用引用没有私人标签后，删除私人目录、个人任务覆盖表和 owner 字段。历史迁移及当时的报告保留原文。

## 共用目录

- `GET /api/v1/tags` 返回本公司共用标签与八色调色板；逻辑删除的标签仅在 `includeDeleted=true` 时列出。普通员工可读，创始人可维护，独立管理员没有业务目录权限。
- `POST /api/v1/tags` 仅接受 `name` 和 `color`，仅创始人可创建。`PATCH/DELETE /api/v1/tags/{id}` 仍需版本检查。`scope`、私人标签和 `PUT /api/v1/tasks/{id}/personal-tag` 已移除，旧写入不再可用。
- 共用名称在公司内唯一。改名改色更新当前引用；逻辑删除保留原引用和已删除标记，禁止新增该标签引用。无标签任务使用 `#FFE1EA` 默认粉色。

## 任务与日志关联

- 任务以有序 `tagIds` 写入，以 `tagIds` 和 `tags` 读取；日程颜色取首个共用标签，其余标签仍在详情展示。省略字段保留原集合，显式空数组清空。
- 日志创建和编辑同样使用有序 `tagIds`，列表、详情、首页近期日志和授权下属日志返回 `tagIds/tags`。编辑时省略字段保留集合，空数组清空。重复、跨公司和新增已删除引用被拒，正文与集合一次事务提交。
- 任务与日志共用同一套多选色块控件：按钮带 `aria-pressed`，支持键盘切换；选中顺序按加入顺序保存，取消后再选按新位置追加，不按目录排序重排。日志创建与编辑各自保留日期、正文和关联任务草稿，嵌套选择关联任务返回后草稿不丢失。已删除但保留引用的标签在编辑态可见、可移除，移除后不能重新挂回。
- 日志详情不显示“编辑权限”资料行；可编辑作者看到编辑按钮，冻结时显示简短状态，越权者没有正文或标签写入口。
- V29 把旧 `work_logs.tag_id` 回填到 `work_log_tags` 的 ordinal 0，保存名称和颜色快照；校验后删除旧列。日志 ID、业务日期和首次创建时间不随迁移变化，24 小时冻结仍以首次创建时间计算。
- 本轮不提供旧日志单标签字段双写，也不把已删除私人内容转为共用。原生端须单独适配这些当前接口。

## 检查入口

构建当前 JAR 并配置本机数据库后，运行 `python3 backend/scripts/check_apply_log_tags.py`。它独占临时数据库，验证顺序、授权、删除、重复、跨公司、旧字段拒绝和事务完整性，并启动真实 Chrome 验证日志创建/编辑的共享多选顺序、键盘状态、已删除保留项、嵌套返回、失败草稿和 320/390/1440 无横溢。`check_apply_private_migration_guard.py` 验证异常私人引用阻断；`check_task_creation_refinement.py` 继续覆盖任务表单中的同一控件。完整浏览器及迁移证据见该 change 的 `implementation-notes.md`；检查脚本本身不代表独立验收通过。
