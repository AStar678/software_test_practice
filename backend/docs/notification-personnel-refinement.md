# 通知、人员与下属详情修复

本次范围对应 `fix-notification-personnel-and-detail-navigation`，2026-11-03。

## 行为

- `task.reminder_20`、`task.reminder_10`、`task.reminder_5`、`task.overdue` 与兼容的旧提醒前缀均归入提醒；列表筛选、分页总数和详情使用一致分类。
- 通知返回 `canOpenRequest`，仅对当前有权访问通知绑定原申请者为真。原申请办结后仍打开原记录，不转向同任务后续申请。无权者保留允许的结果摘要、状态及处理意见，不显示无效申请按钮；申请接口及比较数据权限保持不变。撤回、屏蔽、已删除评论和权限撤销继续执行原隔离规则。普通任务通知只留一个任务入口，评论保留定位入口。
- 人员缓存收到完整资料会更新原条目；姓名摘要不覆盖身份、职位或部门。工作台重新读取后候选缓存重新加载，候选引用当前人员对象。负责人摘要展示组织身份、职位、真实部门和团队，重复名称去重。
- 下属工作弹层及子层使用逐层返回；头部、页脚关闭、遮罩及 Esc 返回原人员日程。保存月/日、选中日期、月历/日轴及外层滚动；返回重读人员权限和任务，不用旧数据绕过鉴权。
- 置顶按钮仅显示在本人当前有效负责且已发布的任务，创建但不负责或仅组织可见任务没有入口。置顶只改变本人日历排序。
- 人员资料删除公司行，日志删除编辑权限行；编辑按钮、冻结状态和时间继续依后端权限显示。
