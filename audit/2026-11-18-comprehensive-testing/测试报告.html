5. 确认缺陷

P2：会导致支持输入被拒、错误输入被接受、功能返回错误或用户操作无效。P3：受控测试辅助或当前 HTTP 入口已有保护的内部问题。本轮没有将这些证据升级为未经验证的安全突破。

F01 · P2 · 管理员小组列表仍查询已移除字段，接口返回 500

  • 位置：backend/src/main/java/cn/pandora/workspace/WorkspaceService.java:1173。
  • 输入 / 步骤：独立管理员 GET /api/v1/admin/teams?limit=1（100、0、101、-1、x 同样失败）
  • 预期：合法分页返回 200；非法分页返回 400。
  • 实际：六组请求均返回 500。服务日志明确记录 Unknown column parent_id；V25 迁移已删除该列。
  • 影响：当前管理台主要使用完整组织结构接口；此兼容读取接口仍可达，不能按正常小组列表使用。未发现因此获得额外权限。
  • 证据：pytest-complete/pytest-api.log；pytest-complete/pytest-service.log:73；test_00_uncovered_contracts.py::test_admin_directory_and_audit_pagination（6 个失败用例 / 断言）。
  • 修复建议：按现行团队与部门关系读取或明确退役该接口，保留正常 / 边界 / 非法参数回归。

F02 · P2 · 评论新增和编辑接受非字符串 JSON 正文

  • 位置：backend/src/main/java/cn/pandora/workspace/CommentService.java:103、134。
  • 输入 / 步骤：body 分别传入 42、true、["text"]、{"text":"comment"}；各测试新增和编辑。
  • 预期：按文本接口契约返回 400，保持原数据。
  • 实际：8 条真实接口测试均返回 200；实现使用 Objects.toString 强制转换后进入写入逻辑。正常文本、空白、10000/10001 UTF-16 和 emoji 长度边界通过。
  • 影响：错误类型被当作正文接受，输入契约与其他文本接口不一致；没有测试证据表明能执行代码或 SQL。
  • 证据：pytest-complete/pytest-api.log；test_acceptance_extremes.py::test_comment_rejects_non_text_json / test_comment_change_rejects_non_text_json（8 个失败用例 / 断言）。
  • 修复建议：在新增与编辑入口统一要求字符串，再做 trim、空值和长度校验。

F03 · P2 · Flutter 拒绝服务端允许的区号和分隔格式手机号

  • 位置：flutter/lib/features/auth/presentation/login_page.dart:111。
  • 输入 / 步骤：+123、+86 (138) 0000.0004
  • 预期：与后端 Phone.normalize 一致，规范化后进入认证。
  • 实际：两个组件测试被前端格式校验拦截；当前正则只接受 3–20 位纯数字。后端对应格式校验测试通过。
  • 影响：用户使用服务端支持的手机号写法时，Flutter 无法提交登录；纯数字真机账号不受影响。
  • 证据：flutter-expanded.jsonl；flutter/test/features/login_page_test.dart；PhoneBoundaryMatrixTest（2 个失败用例 / 断言）。
  • 修复建议：复用与服务端一致的规范化规则，并保留 3 / 20 位、格式化和异常输入回归。

F04 · P2 · Flutter 新密码的字母定义与后端不同

  • 位置：flutter/lib/features/auth/domain/password_policy.dart:15。
  • 输入 / 步骤：汉 重复 9 次，再加 1，共 10 个码点、28 个 UTF-8 字节。
  • 预期：前后端对同一密码作相同策略判断。
  • 实际：服务端 Character.isLetter 接受 Unicode 字母，Flutter [A-Za-z] 拒绝该输入。
  • 影响：部分服务端允许的密码无法在 Flutter 密码表单中使用。字母的产品定义应统一后两端共同遵循。
  • 证据：flutter-expanded.jsonl；flutter/test/core/acceptance_boundary_test.dart；CredentialBoundaryMatrixTest（1 个失败用例 / 断言）。
  • 修复建议：确定统一的字母范围，消除两端策略差异。

F05 · P2 · Flutter 密码最小长度按 UTF-16 而后端按码点计算

  • 位置：flutter/lib/features/auth/domain/password_policy.dart:11。
  • 输入 / 步骤：a1 加 7 个 😀，共 9 个码点、16 个 UTF-16 单元、30 个 UTF-8 字节。
  • 预期：因少于 10 个 Unicode 码点而拒绝。
  • 实际：Flutter 前置策略通过；服务端最小码点规则拒绝。
  • 影响：前端提示符合要求，提交仍会失败。尚未构成服务端密码策略绕过。
  • 证据：flutter-expanded.jsonl；flutter/test/core/acceptance_boundary_test.dart（1 个失败用例 / 断言）。
  • 修复建议：最小长度使用 runes.length，UTF-8 上限仍单独检查。

F06 · P2 · 网页每日事项从远月份回今天时定位到月初

  • 位置：潘多拉-每日事项.js:591。
  • 输入 / 步骤：浏览至 2040-01，离开每日事项页再返回，点击“今天”；公司业务日为 2026-11-19。
  • 预期：今天所在日期进入可见区域，延迟布局后仍保持。
  • 实际：390 / 1440 像素、返回后 0 / 10ms 四种组合均保留 2026-11-01 锚点；当时仅 1–15 日可见。goToDate 跨远月调用 jumpToMonth 后直接 return，丢掉具体日期。
  • 影响：网页“今天”按钮可能仍让今天位于屏幕外；这是网页每日事项问题，不是 Flutter 日视图真机失败。
  • 证据：browser-recheck/check_daily_items.log:93；browser-recheck/suite-artifacts/refine-home-daily-items-layout-and-scrolling/daily-items-browser.json；page-return-navigation.json（4 个失败用例 / 断言）。
  • 修复建议：补载目标月份后继续定位目标日，保留不同宽度、页面往返与布局延迟回归。

F07 · P3 · 受控测试时钟的管理接口接受分数及溢出整数
