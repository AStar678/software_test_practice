## 逐方法追踪的诚实边界

`core-method-inventory.json` 从源代码收集 249 个 public 候选，包含服务方法、退役兼容入口、record 构造器和辅助方法，不等于 249 个现行业务功能。`core-method-coverage-review.json` 将这些候选与真实 JaCoCo 方法命中关联；`coverage/java-method-coverage.csv` 列出所有可执行方法的覆盖率。

按《中期验收要求》严格逐方法检查时，仍需要小组给每个**现行核心方法**选定至少三条正常 / 边界 / 异常用例并逐条复核签字。当前矩阵是业务 / 方法组级追踪，不能把同一模块的三条测试自动算到每个方法，也不能用覆盖率替代这个要求。退役入口与 record 构造器需要人工标注是否属于核心方法，不能靠名称机械认定。

## 特殊边界口径

- 密码：服务端按 Unicode 码点检查最少 10 字符，按 UTF-8 检查最多 72 字节；日志 / 评论按 Java UTF-16 计上限。这三种长度不同，已分别测试。
- 日期：闰年包含 2000 / 2024，非闰年包含 1900 / 2026；时间戳必须带时区，并按数据库微秒精度向下截断。
- 并发：8 路同键创建与 2 路旧版本更新检查的是数据一致性，不据此宣称达到生产吞吐指标。
- 角色：独立管理员与创始人分开；实际上下级与角色名称分开；另一公司角色作为隔离对照。
- 分页：检查完整性、稳定接续、无重复、删除并发和刷新失败保留有效行，而非只检查 HTTP 200。
