# 潘多拉：原始 16 条反馈与增补需求确认稿

整理日期：2026-11-01。

原始反馈基于提交 `0826463`。本文保留原 16 条编号，结合 `f29f9fd` 起提出的 OpenSpec changes、后续增补及本轮明确选择，整理当前设计口径；新增要求从第 17 条起单列。

本文是需求确认稿，不是实现或验收报告。规划、任务勾选及历史验证结论不能代替当前实现的独立验证。本文仅归纳本轮反馈及其增补，不替代完整产品需求文档。

## 一、更新后的原始 16 条

### 1. 通知系统精简、筛选与状态同步

- 通知列表默认只显示所属任务、通知类型、已读状态、通知时间。正文和具体变化在详情中查看，可保留完整摘要显示模式。
- 非任务通知显示所属对象；没有关联任务或对象不可读时，使用合适占位，不泄露受限名称或正文。
- 支持全部／未读／已读筛选，以及需我审核／结果告知／提醒／评论／其他类型筛选，两类条件可以组合。
- “需我审核”仅包含当前用户仍有权办理、尚未到期的待审事项，不能仅凭历史事件类型判断。
- 筛选先于计数和分页；全局未读数不因当前列表筛选条件改变。
- 合并指向同一任务详情的重复入口，不同时提供用途相同的“查看相关任务”和“查看相关对象”。评论通知保留定位评论区的用途；查看申请或审核申请仍是独立业务操作。
- 通知展示信息由系统根据任务、对象、事件、申请、变化内容及时间自动生成，不新增需要人工填写的通知标题、摘要等字段。对象缺失、撤回或失权时有安全兜底。
- 打开通知即标为已读。返回列表后，已读状态、未读数和筛选结果立即同步；在未读筛选下，该通知不应继续作为未读项保留。

### 2. 创建任务时的标签多选

- 共用标签以圆形或胶囊色块排列，先横向排列，空间不足自动换行。
- 每个色块下方显示标签名称。
- 点击选中，再次点击取消；允许选择多个，也允许不选。
- 选中状态清楚可辨，鼠标、触摸和键盘均可操作。
- 创建、编辑、重提、详情和审核差异应正确处理完整标签集合，不能保存或回读时只剩一个。
- 多标签保持稳定顺序；任务日历颜色沿用第 8 条规则。日志标签仍为单选或不选。

### 3. 创建任务的日期与时间布局

- 开始日期与开始时刻作为一组，截止日期与截止时刻作为一组，桌面布局清楚，窄屏可合理换行。
- 创建、编辑、重提和重开均明确显示日期与时刻，不使用拥挤的内联排布。
- 移除表单中的全天开关，保留“设为全天”快捷填入：开始日 00:00 至当前截止日次日 00:00；对同一未修改结果重复点击不继续推进日期。
- 历史全天任务继续可读；编辑时按实际起止时间呈现，不因表单调整改写旧记录的有效排期。
- 日期计算与校验使用公司时区，开始、截止及跨日边界含义一致。

### 4. 创建任务的负责人选择

- 采用真实直属关系构成的可展开多选树，体现公司层、部门负责人、团队负责人和员工的层级。
- 展开／收起与勾选人员分开操作，支持跨分支多选、查看已选、调整顺序、确认和取消。
- 保留姓名搜索与部门筛选；树状层级承担团队浏览，不强制另加团队下拉框。
- 人员姓名、身份／职位、真实部门与团队分别清楚展示，不能以团队冒充部门，也不能有职位后就省略组织信息。
- 公司层无部门人员显示公司层级，不伪造部门，不出现原始空值、异常文字或重复身份。
- 搜索、折叠及切换分支不丢失已选项；取消不改写原草稿。选人范围沿用原授权。

### 5. 审核人统一为实际操作者的直属上级

- 创建、修改资料／负责人、进展、完成、重开、交接等需要审核的操作，均由本次实际操作者，即申请人的当前直属上级审核。
- 不再根据任务创建者、业务接管人或所选负责人决定本次审核人。操作者恰好是创建者或业务责任方，也不因此免审。
- 固定创始人沿用已确认的免审规则，但仍须通过权限、版本、排期及其他业务校验，并保留原因与记录。
- 非创始人没有有效直属上级时阻断，不跨级、不由创建者兜底，也不解释为自动免审。
- 预览、提交、详情、通知和实际审核使用同一规则。有效待审在组织变化后按保存的原申请人重新确定审核人，旧审核人失权。
- 正式接管不改写原申请人；历史已办结审核不追溯重写。

### 6. 月视图按天显示与拖动，日视图按小时调整

**月视图显示：**

- 按任务实际占用的公司日期绘制日级任务条，不再根据日内小时缩窄或偏移。
- 例如 09:00—12:00 的任务占当天一个日期格，不画成当天的 3/24 宽。
- 跨日任务连续覆盖占用日期；截止恰为次日 00:00 时，不多占次日。零时长任务在所属日期明确标识，不改变真实工期。
- 具体起止时刻可从日视图或详情查看。按日绘制只是显示方式，不把任务改成全天任务，也不改写业务排期或提醒。

**月视图操作：**

- 整条拖动按天平移，保留原日内起止时刻及工期。
- 拖动真实开始或截止端点时，按天调整该端日期，保留该端日内时刻和另一端不变，允许改变工期；截止不得早于开始。
- 支持跨周、跨月和跨年。抓取跨周续接片段进行平移时，移动的是完整任务，不能把片段日期误当成任务原始开始。
- 被裁剪的续接端不能冒充任务真实起止端点。

**日视图与共同行为：**

- 横向、纵向日视图按一小时相对增量调整，保留原分钟；整条移动保留工期，端点调整保留另一端不变。
- 纵向全天区也应为合法任务提供整条和真实端点操作，不能因为归入全天区而丢失能力；不在时间轴重复绘制。
- 仅本人月／日视图提供拖动。任务表单、下属日程没有拖动或画布上的独立调时按钮；详情操作见第 15、19 条。
- 仅对已发布、未完成、非待审且有现有仅排期权限的任务提供操作。本人视图仍只显示本人当前负责的任务。
- 拖动实时预览完整排期，松开后确认、填写原因并按第 5 条审核。取消、无位移、逆序及版本冲突不能隐式保存或误触其他入口。
- 待审位置、虚线和冻结按第 17 条处理。

### 7. 任务表单只显示本人创建或负责的任务

- 任务表单仅显示本人原始创建，或本人当前有效负责的授权任务，两类取并集并去重。
- 仅因上下级关系或其他查看授权而可见的任务，不进入本人任务表单。
- 不再提供“仅可见”关系筛选，搜索、计数和分页也不能把被排除任务重新带回。
- 正式接管不把任务算成接管人原始创建。
- 本条限制任务表单范围，不缩小下属工作区等其他合法查看入口的范围。本人日历仍只显示本人负责的任务，不能与表单范围混为一谈。

### 8. 创始人维护标签，日程保留任务颜色

- 只有固定公司创始人可以创建、改名、改色和删除标签，包括私人标签；其他员工及独立管理员不因身份取得该维护权。
- 其他员工在拥有相应任务／日志编辑权时，可以选择或清除标签；任务共用标签多选，日志单选或不选。
- 标签维护入口放在创始人的“我的”页面。
- 日程页移除“编辑标签”和标签图例／展示行，保留任务条颜色。
- 任务颜色沿用：已有私人颜色覆盖优先，其次为共用标签集合第一项颜色，无标签时为默认粉色。
- 标签删除不级联删除任务、日志或历史；已有引用按规则保留删除时信息，新关联不得再选已删除标签。

### 9. 补写统一归入“写日志”，编辑走独立入口

- “写日志”统一创建公司今天、昨天、前天尚未创建且可创建的日志，不再单独提供补写按钮。
- 日期候选只包含缺失日期，不允许未来或更早日期；三天均已有记录时，提示从已有日志进入编辑。
- 编辑必须从明确的已有日志入口进入，并绑定真实日志标识，不能以选择已有日期的方式自动切入编辑。
- 重复创建或并发冲突不自动转编辑、不覆盖已有日志，保留当前草稿并反馈。

### 10. 日志创建与编辑使用独立界面

- 创建与编辑分别组织界面、草稿模式和提交目标，不能仅给同一个创建模板改标题、禁用控件就充当编辑页。
- 创建界面提供近三天缺失日期选择、标签、正文、可选关联任务及保存／返回。
- 编辑界面展示目标日志的不可修改业务日期，提供标签、正文、可选关联任务及保存／返回；不出现创建日期候选、补写或新建控件。
- 日期使用只读展示字段，不保留冗余的禁用日期下拉框。底层标签、正文等基础组件可以共享。
- 选择关联任务后返回、网络失败、版本冲突或冻结时，不串用创建与编辑的草稿或提交目标。
- 仍按原作者权限、同日唯一、首次创建后 24 小时冻结及版本规则执行；编辑不改业务日期，也不重置冻结时刻，删除重建不绕过原冻结约束。

### 11. 日志日期与标签字段对齐

- 创建与编辑分别做好日期与标签的标题、间距、字段高度及视觉对齐。
- 桌面同排对齐，窄屏同列边缘对齐，无截断或横向溢出。
- 编辑页的只读日期展示与标签选择控件也要对齐，不能因控件类型不同而错位。
- 在 320、390 及桌面宽度检查布局，正文、保存和返回入口保持可达。

### 12. 直接点击日志进入详情与评论

- 去掉日志卡片上的“查看与评论”按钮。
- 点击日志正文或空白区域即可进入该日志详情与评论，键盘聚焦后支持 Enter／Space。
- 卡片内已有编辑、关联任务等独立按钮只执行自身动作，不重复触发日志详情。

### 13. 日志页只展示本人日志

- 移除部门、团队、人员和范围内全部等筛选，日志页只列当前登录者本人的日志。
- 不混入他人日志、任务或审核事项；审核从通知等原有入口办理。
- 列表、计数、刷新、回顶及账号切换都使用本人范围，旧筛选状态不能恢复他人内容。
- 合法的下属日志阅读从人员工作区独立进入，不改变本人日志页范围。本人无日志时显示个人空态。

### 14. 下属资料按真实管理树展示

- “我的”下属资料按真实直属关系分层展示全部合法的直接及间接下属，不能只按职位名称或职级猜层级。
- 支持逐层展开／收起，展开节点与点击人员分别操作。
- 节点展示姓名、职级／职位及真实部门／团队，有职位时仍保留组织信息，公司层无部门者明确显示公司层。
- 展开状态不跨账号保留，组织变化后重新校验范围。

### 15. 下属工作区提供日志与日程；页面不拖动，任务详情沿用原权限

- 从下属人员入口打开独立工作页，明确当前人员，提供日志与日程切换及人员资料。
- 展示内容以该人员自己的日志、负责的日程为参照，同时必须处于查看者当前授权范围，不以代入下属身份绕过权限。
- 下属日程默认月视图，可切日视图；月历按第 6 条日级方式绘制，日视图提供真实时间轴、独立全天区和任务清单。
- 支持日期选择、前后导航、回今天和完整分页；跨日、午夜、零时长及重叠任务正确，月历、日轴、全天区和清单均能辨识完成状态。
- 下属日程页面不提供整条拖动、端点拖动、画布上的独立调时按钮或任务表单入口。
- **不能将整个下属工作区及其任务详情笼统定义成严格只读。** 点击任务进入正常鉴权详情后，按当前用户原有权限显示基础编辑、精确排期或其他操作，不因来自下属入口额外禁用，也不因能看见就增加基础编辑权。
- 下属日志正文仍不可由上级编辑，评论按独立权限办理。
- 待审虚线和提议位置按第 17 条展示。进入详情后返回，应保留人员、日期、模式及页签，不改写本人日历或日志状态。
- 快速切人、换账号或失权时，旧响应不能串入新人员／账号，失权正文及时清除。

### 16. 清理正式界面的 AI／原型遗留说明文案

- 清理员工 Web 主页面、二级页／弹层、登录与账号流程，以及 PC 管理端当前可达界面中的冗余规则长说明、原型／开发者解释和原始内部技术标识。
- 删除或精简“标签由创始人统一维护，日志最多选择一个，任务支持多选；删除的标签不能再用于新的关联。”及同类说明，也不在日志表单重复堆放归属、上级只读、仅作者可编辑等规则段落。
- 保留必要字段名称、空态、校验、失败重试、危险操作确认和用户判断所需的待审、冻结、只读、失权及结果提示。
- 分析页保留真实统计范围、生成时间及可理解的方法／来源，不直接显示内部方法代码，不删除 AI 地图功能，也不夸大为外部模型生成。
- 只清理产品静态文案，不按关键词过滤任务、日志、评论、审核原因或历史等真实业务内容；规划、审计、代码注释和历史文档不属于产品界面文案清理范围。

## 二、后续增补要求

### 17. 已发布任务待审时统一虚线，并在提议排期位置显示

- 已发布任务进入任意后续审核时，一律显示虚线外包围线、淡底及可辨识的审核中状态，保留标签颜色。
- 有排期变化时，本人及授权下属日程只在提议的新位置显示一次，框体、跨度、日期范围和文字均取提议排期，原位置不留副本。
- 没有排期变化的审核，在原有效位置显示虚线。
- 月历按提议占用日期绘制日级任务条，日轴按提议真实时段绘制。刷新、重新登录或切换视图后保持一致。
- 待审期间继续冻结原有业务修改和拖动；评论按独立权限保留。
- 虚线投影不是提前生效：实际有效排期、普通任务详情、任务表单、提醒及其他业务权限仍按原有效版本处理。
- 审核通过后按新有效排期恢复实线；驳回、撤回或失效后按仍有效排期恢复实线。
- 未发布的创建申请不进入正常日程。创始人合法免审的修改直接生效，不制造虚线待审或本人待审事项。
- 本人及下属日程画布不放独立的“调时、起、止”按钮；本人视图以框体和透明边缘操作，下属页面不提供拖动。

### 18. 本人与下属日志的阅读样式一致

- 本人日志列表、日志详情正文与下属日志正文统一为 15px 字号、1.55 行高。
- 长内容正常换行，无横向溢出；详情可阅读全文并进入评论。
- 编辑输入、评论和元信息保留各自用途，不机械统一所有文字样式。

### 19. 区分查看范围、拖动入口、仅排期权限与基础编辑权限

| 入口／操作 | 当前确定规则 |
| --- | --- |
| 本人月／日视图 | 仅列本人当前有效负责的任务；合法未完成、非待审任务可拖动 |
| 本人任务表单 | 本人原始创建或当前负责的任务；不拖动，可进入详情 |
| 下属日程 | 所选下属当前负责且查看者有权的任务；页面不拖动，可进入详情 |
| 正常任务详情的仅排期操作 | 沿用现有权限：正常可见、已发布、未完成、非待审任务可申请仅排期修改，不限创建人、业务责任方或负责人 |
| 基础资料／标签／负责人修改 | 暂维持当前业务责任方可申请；正常在任时为原创建者，正式接管后为接管人 |
| 进展、完成、重开、交接 | 沿用各自原有操作权限；审核路线按第 5 条统一 |
| 历史通知的受限只读任务详情 | 不属于正常查看权，不因此取得编辑或仅排期操作权 |
| 下属日志正文 | 上级可按授权阅读，不得编辑；评论单独鉴权 |

- 拖动是本人视图提供的交互入口，不能据此把后端仅排期权限收紧成“只有负责人可调时”。
- 仅排期操作不得夹带资料、标签、负责人、进展或执行状态修改；提交和审核生效前均重新检查权限、版本及状态。
- **待确定事项：是否将基础字段编辑权扩大为“正常可见即可编辑”。本轮暂不实施，继续维持现有基础编辑权限。** 此待定事项不撤销已经保留的仅排期权限，也不要求把下属入口的普通任务详情强制改成只读。

### 20. 普通 HTTP 页面也能可靠提交与重试

- 经普通 HTTP 地址访问时，写入操作仍能正常提交，不能因浏览器缺少某项随机标识 API 而报错。
- 首次提交已成功但响应丢失时，相同操作重试不得产生重复申请或重复写入；新操作仍正确区分。
- 失败后保留当前表单草稿，不改权限、审核、版本及幂等规则，不向用户暴露内部实现说明。
