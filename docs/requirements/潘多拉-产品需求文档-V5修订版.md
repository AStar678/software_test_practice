## 1. 产品目标与范围

### 1.1 背景与目标

公司当前用共享文档维护任务，存在任务通知缺失、权限边界不清、任务之间无法关联、缺少历史记录，以及查看、误操作、维护归档不便等问题。V1 建立按组织权限运行的任务协作和个人工作日志系统，使人员能创建或接收任务、跟进进展、完成审核、查看权限内的工作信息，并通过标签和评论补充协作上下文。

### 1.2 V1 组成

- **员工业务前端**：工作台、日程、日志、统计、我的五个主栏目；任务表单为日程下的二级页面；通知中心承接消息及审核，不新增主导航。员工 Web、Android 套壳和 Android 原生端承载相应业务时，遵循相同业务规则；平台控件可采用适合各端的实现，不能改变权限、审核或数据语义。
- **PC Web 管理端**：独立管理员维护员工、固定组织、展示职位、停用及业务接管、公司信息、通知和完整任务操作历史；不嵌入员工前端。管理员不占员工组织位置。
- **共用后端**：统一认证、权限、任务与审核、日志、标签与评论、通知、统计及持久化；前端入口隐藏不能替代后端鉴权。
- **仍暂缓**：上级请示及回复、一人多团队、任务私人草稿、任务取消、公司信息草稿/定时发布、个人信息由日志自动生成、外部模型及 MBTI。10.23 第 6 条历史日期进展与已结束/超时任务新增操作规则仍待确认。
- **员工停用与交接**：V1 包含员工停用、岗位继任、负责人交接及正式业务接管；完整复职/重新启用流程不在本版范围。

### 1.3 术语约定

- **日志**：员工按公司业务日期填写的个人工作内容；任务的技术流水称“任务操作历史”。
- **组织位置**：创始人、部门负责人、团队负责人、普通员工之一；每人唯一位置，权限和直属上级据此推导。
- **展示职位**：必填的“销售经理”“设计师”等资料，不决定权限或审核人。
- **创始人**：公司明确指定且固定的唯一业务创始人，不以任意无上级员工或管理员身份推断。
- **独立管理员**：管理端账号，与员工身份分开，不参与员工组织、任务负责人或业务审核。
- **当前业务责任方**：任务原创建者正常在任时为原创建者，正式接管后为唯一接管人；原创建者及创建时间始终作为原始来源保留。
- **公司标签**：固定创始人创建、改名、改色和删除的公司级任务/日志粗分类；任务可多选，日志单选或不选，员工只选择或清除。
- **个人颜色覆盖（兼容）**：历史数据中仅影响本人日历显示的颜色偏好；不创建公司标签、不进入标签目录、不改变任务分类或他人颜色。本版不再提供员工新建、改名、改色或删除标签的入口。
- **待审投影**：已发布任务待审时在日程中按提议排期绘制的虚线位置；只是审核中的展示，不是已生效排期。
- **实际操作者/申请人**：本次发起需审核操作的人；其当前唯一直属上级是本次审核人。

## 2. 用户、组织与权限

### 2.1 固定组织模型

- 四层关系固定为：**创始人 → 部门负责人 → 团队负责人 → 普通员工**。全公司一位固定创始人，每部门一位部门负责人，每团队一位团队负责人。
- 每人只有一个位置，不兼任多个部门或团队，不设副职、联合负责人或多管理链。普通员工必须归团队，团队必须归部门。
- 部门负责人直属创始人，团队负责人直属本部门负责人，普通员工直属本团队负责人。组织身份、层级和直属上级由位置推导，不再分别手工设置。
- 创始人属于公司层，不要求部门和团队；部门负责人属于部门层，不要求团队；团队负责人及普通员工须有部门和团队。所有员工均须填写展示职位和唯一有效登录手机号。
- 只有独立管理员可维护组织和展示职位。取消“角色与授权”、自定义业务范围及员工团队管理入口；职位、旧角色名称或前端身份按钮不能授予业务权。
- 新增、调岗、负责人更换、单位删除及停用须按完整合法结果保存，不能出现无负责人单位、管理环、悬空上级或双重位置；细则见 3.2。
- 新建和后续修改任务负责人均可选择全公司有效业务员工，包括本人、直属上级、跨部门员工及创始人；提交至少一位。该候选范围不扩大任务/日志查看权，不适用于专用交接。独立管理员不进入候选。

### 2.2 业务权限基线

以下为正常业务范围；未发布任务隔离、正式接管和历史通知专用只读例外另行裁决。

| 能力 | 独立管理员 | 创始人 | 部门负责人 | 团队负责人 | 普通员工 |
| --- | --- | --- | --- | --- | --- |
| 员工、组织、展示职位、公司信息维护 | 管理端维护 | 无员工端组织维护权 | 同左 | 同左 | 同左 |
| 查看正常任务 | 管理端按后台查询职责 | 全公司 | 本部门涉及，以及本人创建或负责 | 本团队涉及，以及本人创建或负责 | 本人创建或负责 |
| 新建及修改负责人候选 | 不参与员工业务 | 全公司有效员工 | 同左 | 同左 | 同左 |
| 查看日志（人员工作区） | 不因管理员身份取得 | 全公司 | 本人及本部门全部直接/间接下属 | 本人及本团队员工 | 本人 |
| 查看下属资料 | 不因管理员身份取得业务资料权 | 全公司员工 | 本部门全部下级 | 本团队员工 | 本人 |
| 手机号读取 | 录入/覆盖不赋予读取他人号码权 | 本人及实际管理链下属的授权详情 | 同左 | 同左 | 本人 |
| 统计、词云范围 | 无员工分析权 | 全公司 | 本部门 | 本团队 | 本人 |
| 规则建议范围 | 无员工分析权 | 全公司任务 | 本人任务 | 本人任务 | 本人任务 |
| 公司标签定义维护 | 无 | 创建/改名/改色/删除全部公司标签 | 仅选择/清除 | 仅选择/清除 | 仅选择/清除 |
| 任务/日志标签选择 | 无 | 有相应编辑权时选择/清除 | 同左 | 同左 | 同左 |
| 任务/日志评论 | 无员工评论权 | 当前正常可查看对象即可评论 | 同左 | 同左 | 同左 |
| 写/编辑/删除日志 | 无员工写入权 | 仅本人，受日期与冻结窗口限制 | 同左 | 同左 | 同左 |
| 完整任务操作历史 | 管理端查询 | 员工端不提供完整入口 | 同左 | 同左 | 同左 |

- “本部门/团队涉及”指至少一位当前有效负责人处在该组织范围，不按创建者部门判断。多人跨部门任务可同时落入相应管理范围。
- 部门、团队负责人保留本人创建或负责的正常任务查看权；普通员工不因同团队或同任务而取得同事独立任务、日志或联系方式。
- 正式接管人按接管关系取得必要任务查看和办理权，但接管任务不计入其“我创建”。创建、修改、审核等操作权按 4.2、4.3 单独判断，管理范围不等于任意修改权。
- 月/日、全天区和当天清单仅显示本人当前有效负责的正常任务，含已完成；任务表单仅展示本人原始创建或当前有效负责的任务；统计、日志、人员详情执行各自范围。
- 手机号仅本人及实际管理链上级在授权人员详情中可读；同级、下属、其他管理链及仅有管理员身份者不可读。邮箱仅本人可见。目录、负责人候选、日志、通知、分析和普通业务摘要不返回号码。
- 下属资料包含当前管理链的直接及间接下级；资料权、日志权和任务权分别判断，看到日志不自动取得其关联任务访问权。
- 列表、详情、搜索、关联、人员候选、计数、统计、旧页面提交、审核预览及实际决定均按当前关系鉴权；组织调整后旧页面、缓存及请求重放不保留旧权限。
- 标签定义在公司范围内统一由创始人维护；员工不能创建、修改或删除标签。标签和评论不增加对象访问权，个人颜色覆盖不进入共享任务、日志、通知或共享历史。

### 2.3 查看、拖动、仅排期与基础编辑边界

| 入口／操作 | 当前确定规则 |
| --- | --- |
| 本人月／日视图 | 仅列本人当前有效负责的任务；合法未完成、非待审任务可拖动 |
| 本人任务表单 | 本人原始创建或当前负责的任务；不拖动，可进入详情 |
| 下属日程 | 所选下属当前负责且查看者有权的任务；页面不拖动，可进入详情 |
| 正常任务详情的仅排期操作 | 沿用现有权限：正常可见、已发布、未完成、非待审任务可申请仅排期修改，不限创建人、业务责任方或负责人 |
| 基础资料／标签／负责人修改 | 暂维持当前业务责任方可申请；正常在任时为原创建者，正式接管后为接管人 |
| 进展、完成、重开、交接 | 沿用各自原有操作权限；审核路线按 4.3 统一 |
| 历史通知的受限只读任务详情 | 不属于正常查看权，不因此取得编辑或仅排期操作权 |
| 下属日志正文 | 上级可按授权阅读，不得编辑；评论单独鉴权 |

- 拖动是本人视图提供的交互入口，不能据此把后端仅排期权限收紧成“只有负责人可调时”。
- 仅排期操作不得夹带资料、标签、负责人、进展或执行状态修改；提交和审核生效前均重新检查权限、版本及状态。
- 待确定事项：是否将基础字段编辑权扩大为“正常可见即可编辑”。本轮暂不实施，继续维持现有基础编辑权限；该待定不撤销已经保留的仅排期权限，也不要求把下属入口的普通任务详情强制改成只读。

## 3. 账户与管理端

### 3.1 账户与身份

- 员工由管理员手动新增，不开放注册。员工以手机号和密码登录，以姓名展示，以稳定内部 ID 关联业务，不设置独立员工用户名。
- 手机号规范化、必填、不可清空，在当前不选择租户的员工认证范围内唯一；跨公司重复导致身份歧义时同样拒绝员工登录，由独立管理员修复。
- 每公司一个独立管理员，使用管理员账号名和密码，在单独“管理员账号”区域维护；不进入员工名单、组织树、任务候选、日志目录或业务审核，不要求员工部门、团队及职位。
- 员工和管理员登录明确区分身份，不跨类型回退。不接受未指定身份类型或旧员工用户名载荷，不能因标识/密码碰巧相同而静默选择另一身份。各客户端均须使用明确的身份类型与登录标识。
- 建号生成初始密码，首次登录及管理员重置后必须改密；受限会话仅能改本人密码或退出，不得先载入业务数据。日常改密校验旧密码；新密码至少 10 个字符、含字母与数字、UTF-8 长度不超过 72 字节。
- 改密成功撤销包括当前会话在内的全部会话，要求重新登录；重置密码、停用员工和管理员凭据变更同步撤销相应旧会话。
- **员工姓名与登录手机号仅管理员可改**。员工本人可维护头像、邮箱和密码，不能通过混合请求修改姓名、号码、组织或权限。
- 管理员合法改号后，新号码用于登录、旧号码失效，员工 ID 和业务来源不变，原会话撤销；管理员可录入/覆盖号码，但管理响应和审计不回显他人号码。
- 员工业务页与管理端按真实会话进入，不通过演示按钮切换权限。演示准备按第 10 章执行。

### 3.2 员工与组织维护

- 管理端维护姓名、登录手机号、必填展示职位及合法位置。职位仅展示，改名不改变任务、审核、日志及统计权限。
- **首位创始人**：公司尚未设置创始人时，管理员可在组织计划中将新创始人加入草稿，填写姓名、手机号并选择展示职位，再保存完整结果。加入草稿不创建正式账号；可在保存前取消。已固定创始人的公司不提供重复新增、转交、调任或普通停用。
- 创建部门或团队须同时安排一位有效负责人，负责人可以是首位且唯一成员。新员工、调岗、负责人更换、删除单位须同时安排所有受影响人员去向。
- 跨多人、跨单位调整校验完整最终结果后原子提交；校验失败保留原组织。并发保存检查版本及唯一性，防止双负责人、无负责人、跨部门团队、环或悬空链。
- 保存组织时同步更新权限及仍有效待审的审核关系，业务读取和写入只观察合法旧状态或新状态。旧审核人不得凭旧通知继续决定。
- **专用交接**：被交接人本人或其当前直属上级可发起/设置预选接收人；间接上级不自动代办。接收人限同部门、直属上级、直属下属，创始人可选全公司有效业务员工；正式提交重验资格。只变更规定的负责人关系，不借此修改任意基础资料。
- **停用前完整安排**：未完成任务负责人交接、岗位继任与下属位置、未发布创建申请办结/撤销、待办审核承接、已发布任务创建者业务责任的正式接管，须一并处理。需要他人审核的交接先办结，不能靠管理员停用跳过任务审核。
- 管理员指定有效业务员工为正式接管人，自己不成为业务接管人。每项任务只有一个当前业务责任方；接管独立记录对象、前后责任人、办理人、时间及原因，不覆盖原创建者、创建时间或来源。
- 未发布创建申请不转造为接管人创建；停用前无法办结者，由原申请人撤销，或由专用停用操作中的管理员撤销并留因。此管理例外仅限未发布创建申请，不赋予管理员一般业务撤销权。
- 停用、组织及业务安排校验待审状态、截止、版本和有效接收/接管人后原子提交，失败保留原状态。成功后撤销停用人员会话、重算有效待审及通知，不留停用审核人、双重责任或复活终态申请。

### 3.3 公司统一信息与后台查询

- 管理端为独立 PC Web 页面，承接员工、组织计划、展示职位、管理员账号、停用接管、公司信息、任务历史及通知管理；不要求管理员 App，窄屏可打开不等于移动管理端交付。
- 公司统一信息最多十条，管理员录入、修改、删除和调序；默认按创建时间排序，不提供草稿或定时发布。员工工作台只读，创始人也无员工端编辑入口。
- 管理端可查完整任务操作历史及通知接收、已读、撤回等信息。删除/撤回业务通知不删除历史、不撤销任务或申请结果。
- PC 管理端不设标签管理栏目；公司标签的员工端入口、创始人维护权和员工选择权见 4.7。

## 4. 任务、审核、标签与评论

### 4.1 任务资料与关联

任务至少包含：标题、说明、创建者、创建时间、一个或多个有序负责人、开始与截止时间、全天标记、紧急程度、执行状态、文字进展、可选上级任务、审核人、审核意见、标签。

- 创建任务不再设置“完成标准”字段；创建/编辑任务表单不要求完成标准输入区，也不保留其最小高度限制。说明仍是可选长文本字段，窄屏下其他字段和提交操作须可滚动访问。历史任务已有的完成标准数据保留，展示、编辑和审计须兼容，不因本版移除创建字段而删除历史内容。
- **创建者可以不在负责人列表中**。初始负责人按固定位置确定：普通员工默认本人；创始人、部门负责人、团队负责人默认空。创建者可在提交前把自己移除或选为负责人，也可以只创建并指派给他人；创始人不默认成为负责人。创建者身份、创建时间和来源信息独立保留，不因不在负责人中而消失。
- 负责人可多选，创建任务时范围是全体在职员工，可选择自己、直属上级、下级、其他部门员工或创始人。新建和后续基础修改均可选全公司有效业务员工；专用交接另按 3.2 的关系圈执行。列表顺序须保存并在创建/编辑任务表单中明确呈现，用于展示和通知；**不再用于审核人计算**。
- 紧急程度为“紧急/高/中/低”四档，是独立属性，不拼入标题。不使用百分比进度或进度条；提醒中的剩余时间比例不是完成进度。
- 非全天任务填写起止日期与时刻；全天任务填写起止日期，首尾日期均计入日历展示。截止不得早于开始，至少有一位负责人。
- 进展保留现有文字备注与当前进展展示；首次有效进展生效后，任务从待开始进入进行中。10.23 反馈第 6 条关于“选择之前日期、已结束/超时任务展示与操作”的含义尚未确认，V1 暂不新增对应规则，待确认后再纳入；当前已完成、逾期状态仍须在详情、任务表单和日历中保持可识别。
- 父任务和子任务均为独立可执行任务，各自有负责人、排期、状态和审核人。父任务不因子任务完成而自动完成，也不按子任务计算百分比进展。
- 子任务列表表达拆解关系及状态；不得形成关系环，不得向无权查看的任务新建关联，不能通过关联打开权限外的任务。
- 任务可选择零个或多个公司标签，顺序稳定；日志单选或不选。所有标签定义均由固定创始人维护，员工只能在拥有相应编辑权时选择或清除；不提供员工新建私人标签。标签规则见 4.7，任务评论见 4.8。

#### 4.1.1 日期与时刻布局

- 创建、编辑、重提和重开的表单中，开始日期与开始时刻为一组，截止日期与截止时刻为一组；桌面清楚分组，窄屏按组换行，不使用拥挤的内联排布。
- 移除表单全天开关，保留“设为全天”快捷填入：开始日 `00:00` 至当前截止日次日 `00:00`。对同一未修改结果重复点击不能继续推进日期。
- 历史全天任务继续可读；编辑时按实际起止时间呈现，不因表单调整改写旧记录的有效排期、提醒或统计口径。
- 日期、时刻、跨日边界和校验统一使用公司时区。

#### 4.1.2 负责人选择树

- 使用真实直属关系构成的可展开多选树，至少体现公司层、部门负责人、团队负责人和员工层级；不以团队名冒充部门。
- 展开/收起与勾选人员分开操作，支持跨分支多选、查看已选、调整顺序、确认和取消；取消不改写原草稿。
- 提供姓名搜索与部门筛选；树状层级承担团队浏览，不强制另加团队下拉框。
- 节点分别展示姓名、展示职位/身份、真实部门和团队；公司层无部门人员明确显示公司层，不出现空值、异常文字或重复身份。
- 搜索、折叠及切换分支不得丢失已选项；选人范围沿用现有授权，树形展示不扩大也不缩小候选。

### 4.2 操作权限

审核人只按申请人的当前直属上级确定，详见 4.3；负责人层级和保存顺序不参与审核人计算。下表区分“谁可以发起”与“谁审核”，不把二者混同。

| 操作 | 可发起者 | 审核人 |
| --- | --- | --- |
| 创建、未发布创建申请重提 | 创建者/本次申请人 | 申请人当前直属上级；固定创始人免审 |
| 基础资料、公司标签及负责人修改 | 当前业务责任方 | 申请人当前直属上级；固定创始人免审 |
| 仅排期修改 | 正常可见、已发布、未完成、非待审任务的申请人 | 申请人当前直属上级；固定创始人免审 |
| 更新进展、提交完成 | 当前有效负责人 | 申请人当前直属上级；固定创始人免审 |
| 重开 | 当前业务责任方 | 申请人当前直属上级；固定创始人免审 |
| 专用负责人交接 | 被交接人本人或其当前直属上级 | 申请人当前直属上级；固定创始人免审 |
| 标签选择/清除 | 拥有相应任务/日志编辑权者 | 随对象编辑审核；仅选择/清除不单独产生通知 |
| 评论 | 有当前正常查看权的员工 | 不进入审核；作者管理本人评论 |

- 创建/派发共用日程右下加号入口，不按“自建/派发”区分审核。工作台不再提供重复创建按钮。
- 当前业务责任方可改标题、说明、排期、全天、紧急程度、父任务、公司标签和负责人；原创建者不在负责人中不影响其在任业务责任。正式接管后由接管人承担，独立管理员不代行业务。
- 当前负责人可更新进展、提交完成；负责人身份本身不授予基础编辑或重开权。
- 已完成任务由业务责任方重开，生效后回到**进行中**并进入新轮次；可同时调整未来排期及有效负责人，以处理原负责人已停用的任务，不自动加回创建者或接管人。
- 公司标签是基础信息，随任务编辑审核；员工只能选择或清除。评论与个人颜色覆盖不参与业务待审冻结。
- 仅排期操作沿用现有权限，不因“拖动只对本人视图开放”而收紧为只有负责人可调时；不得夹带资料、标签、负责人、进展或执行状态修改。
- 下属工作区中的普通任务详情按当前用户原有权限显示操作，不因来自下属入口而强制只读，也不因可见而增加基础编辑权。
- 固定创始人的免审范围见 4.3；非创始人不能以“业务责任方”“创建者”或“负责人”身份绕过直属上级审核。

### 4.3 审核人确定规则

所有需要审核的操作使用同一条规则：**由本次实际操作者，即申请人的当前唯一直属上级审核**。预览、提交、详情、通知、待审刷新和实际决定必须一致；任务创建者、当前业务责任方、负责人层级、负责人保存顺序和所选负责人都不能替代该规则。

#### 4.3.1 申请人直属上级

1. 创建、未发布创建申请重提、基础修改、负责人修改、仅排期、进展、完成、重开和交接，均由申请人当前唯一直属上级审核。
2. 申请人恰好是创建者、当前业务责任方或负责人，也不因此免审；固定创始人是唯一免审例外。
3. 固定创始人的需审核操作直接生效并记录原因，但仍须通过权限、版本、排期、截止、关联和冻结等完整校验。
4. 非创始人没有有效直属上级，或上级停用、失效、跨公司、关系损坏时阻断并提示修复；不跨级、不向创建者或业务责任方兜底，不解释为自动免审。
5. 不手动选择或转交审核人。负责人可包含本人、上级、创始人或其他部门员工；选择、换序和更换负责人不改变本次审核人。
6. 审核预览和提交在同一事务中重新读取当前关系，预览结果不是授权凭证。

#### 4.3.2 组织变化与旧审核人

1. 有效待审在组织变化后，按申请时保存的原申请人重新计算其当前直属上级；原审核人失权，旧通知和旧页面不能继续决定。
2. 重新计算只作用于仍有效的待审申请，记录前后审核人、原因和时间，并同步更新通知和可见入口。
3. 历史已办结审核不追溯重写；正式接管不改写原申请人、原创建者或历史决定。
4. 失效、拒绝、撤销、超期和已终结申请不能因组织变化或重试复活。

### 4.4 审核范围、冻结与可见性

- **创建/创建重提及所有需审核操作**统一按 4.3 的申请人直属上级规则。需他人审核者提审；固定创始人免审并留因，其他申请人不能因创建者、业务责任方或负责人身份免审。
- 只有明确固定创始人可免审；其他员工缺有效直属上级时阻断。非创建操作的审核人不可用时，同样阻断并提示修复组织关系，不作免审。
- 一个任务同一时间仅允许一个待处理申请；待审期间冻结其他业务操作，包括其他负责人的进展和完成提交。重复提交提示已有申请，不产生第二条待审。**评论区与个人颜色覆盖不参与冻结**，具有当前正常查看权时仍可操作，但均不改变任务有效内容。
- **一般只有申请人可撤销自己的待审申请**。业务责任方或审核人不能凭身份撤销他人申请；审核人可拒绝或退回。修改提议须先撤销再重提。3.2 的专用停用操作对未发布创建申请有受限管理撤销例外。
- 待创建审核任务不进入月/日视图、任务表单列表及其搜索/计数、工作台任务列表和统计。只有审核人从通知中心查看、创建者从日程页的**独立申请入口**跟踪；其他负责人即使被指派也不可见，除非其同时是审核人。
- 创建申请被拒绝、撤销或到期失效后仍不进入正常任务区；创建者可调整后重提。拒绝结果通过通知呈现，不新增专门的已拒绝申请档案页面。删除结果通知不删除管理端记录。
- 已生效任务提交修改、进展、完成或重开申请时，任务详情和任务表单继续展示**原有效内容**并标记审核中、冻结操作；日程按 5.2.7 在提议排期位置显示待审投影，不得提前改写有效排期、提醒或其他业务权限。
- 待审投影只展示提议排期一次：有排期变化时，本人及授权下属日程只在提议的新位置显示，原位置不留副本；无排期变化时在原有效位置显示虚线。审核通过后按新排期恢复实线；驳回、撤回或失效恢复原有效排期。
- 未发布创建申请不进入正常日程；固定创始人合法免审的修改直接生效，不制造虚线待审或本人待审事项。
- 审核人可查看原有效内容与提议内容的逐项差异，类似 diff；**该差异对比仅对本次审核人开放**。申请人可以查看自己提交的内容、状态和结果，但不因申请人身份开放专用差异对比；其他普通查看者只见原有效版本和冻结标记。
- 待审跨过截止时间时，按 5.6.2 使原申请失效、解除冻结并提醒重提；审核操作须检查适用截止时间，不能因定时扫描尚未执行而在截止后批准旧申请。

### 4.5 状态与审核结果

执行状态与申请状态分别表达。执行状态为待开始、进行中、已完成；申请状态包括待审核、已通过、已拒绝/退回、已撤销和已失效。“待创建审核”“待完成审核”为用户可见的流程状态，不能混同为已生效执行结果。

| 当前情况 | 触发事件 | 后续处理 |
| --- | --- | --- |
| 新任务提交 | 创建人有直属上级且审核人可用 | 待创建审核，与普通任务隔离；审核人为申请人直属上级 |
| 新任务提交 | 创建人没有有效直属上级或审核人不可用 | 暂不生成可绕过审核的生效；提示修复组织关系，不跨级、不由创建者兜底、不免审 |
| 新任务提交 | 明确固定创始人创建 | 记录免审原因，进入待开始并正常展示；其他员工缺上级须阻断 |
| 待创建审核 | 通过 | 待开始，进入正常展示并通知任务人员 |
| 待创建审核 | 拒绝、撤销或失效 | 保留申请内容及结果，可调整后重提，不进入正常展示 |
| 待开始 | 首次进展备注生效 | 进行中 |
| 待开始、进行中 | 有效负责人提交完成 | 由申请人直属上级审核；固定创始人免审；无有效直属上级时阻断 |
| 待完成审核 | 通过 | 已完成 |
| 待完成审核 | 退回 | 进行中，记录退回意见 |
| 待完成审核 | 申请人撤销 | 恢复提交前执行状态，解除冻结 |
| 已生效任务申请修改或更新进展 | 通过 | 提议内容生效；最新有效进展成为当前进展 |
| 已生效任务申请修改或更新进展 | 拒绝或撤销 | 保留原有效版本及执行状态，解除冻结 |
| 已完成 | 当前业务责任方提交重开并按规则生效 | 进行中，进入新的执行轮次；必要的排期调整同时生效 |
| 重开申请 | 拒绝或撤销 | 保留已完成状态 |
| 任一待审申请 | 在待审期间跨过适用截止时间 | 申请失效，解除冻结，提议内容不生效；未发布任务仍不发布，已发布任务保留原有效版本及提交前状态 |

审核入口在通知中心，审核人可查看申请并通过、拒绝或退回，拒绝/退回须填写意见。多人并发提交、审核、撤销及截止失效只能产生一个最终结果，旧页面重复操作不能再次生效。

已结束任务在任务详情、任务表单和日历中保持可识别；逾期未完成与已完成是不同展示，逾期标记不应被“已结束”文案覆盖。评论不改变上述状态。

### 4.6 任务操作历史

所有共享任务创建和更改均须记录，包括基础资料、负责人及其顺序、完整公司标签集合及其顺序、文字进展、申请提交/撤销/失效、审核决定与改派、完成、重开、交接、评论发布/编辑/删除及无需审核的原因。记录至少能说明谁在何时进行了什么操作，以及对应变更、审核人和处理结果。

个人颜色覆盖（兼容）不写入共享任务历史，也不生成共享版本、审批或通知；共享历史不得泄露个人显示偏好。

完整历史仅在管理端查询。员工前端展示当前资料、有效进展、审核人、与本人相关的申请及审核意见、标签和评论，不开放完整操作历史入口。任务交接、个人消息删除、通知撤回或三个月后的消息清理均不抹掉任务操作历史。

### 4.7 公司标签与任务颜色

#### 4.7.1 公司标签

- 所有标签都是公司级任务/日志粗分类，由固定创始人创建、改名、改色和删除；其他员工及独立管理员不因身份取得标签定义维护权。
- 员工只能在拥有相应任务/日志编辑权时选择或清除标签；任务可多选，日志单选或不选。
- 任务标签以圆形或胶囊色块展示，先横向排列，空间不足自动换行；每个色块下方显示标签名称。点击选中、再次点击取消，选中状态对鼠标、触摸和键盘均清楚可辨。
- 创建、编辑、重提、详情和审核差异必须保存、回读和展示完整标签集合，不能只剩一个；多标签保持稳定顺序。
- 标签名称 1—40 字，在公司范围内唯一；颜色从八色柔和预设色板选择，不输入任意色值，不包含白色及无标签专用默认粉色。
- 标签改名、改色即时影响当前引用展示，历史任务版本及操作快照保留原值。
- 删除标签为逻辑删除：新内容不能再选，原引用保留名称、颜色和“已删除”信息；不级联删除任务、日志、评论或历史；有业务编辑权者可清除或替换。
- 升级已有公司时，已存在的同名标签颜色及删除状态不得被覆盖，不自动重写历史任务。新增六类默认公司标签的名称按现行部署脚本执行，不与用户手工标签冲突。

#### 4.7.2 个人颜色覆盖（兼容）

- 本版不再提供员工创建、改名、改色或删除私人标签的入口；所有标签定义统一由创始人维护。
- 历史数据中已有的个人颜色覆盖可继续作为本人日历显示优先项；它不创建公司标签、不进入标签目录、不改变共享任务内容或他人颜色。
- 个人颜色覆盖只影响本人显示，不产生共享任务版本、审核、通知或共享历史；失去任务正常查看权后不能借该覆盖访问对象。
- 不再新增员工私人标签维护入口；如后续决定恢复，须单独形成需求变更，不沿用 V4 的私人标签维护规则。

#### 4.7.3 入口与展示

- 标签维护入口仅放在固定创始人的“我的”页面；员工端其他位置不提供标签创建、改名、改色或删除入口。
- 日程页移除“编辑标签”和标签图例/展示行，不常驻标签目录；任务/日志详情以彩色药丸展示标签，任务详情展示完整多标签集合。
- 任务日历颜色优先使用本人已有的个人颜色覆盖，其次使用公司标签集合第一项颜色，均无时使用默认粉色 `#FFE1EA`；日志默认粉色，不使用白底。
- 任务标签多选，日志单选或不选；标签背景不得影响任务点击、时间位置或重叠分栏，文字与背景对比不足时自动切换文字颜色。
- 标签不改变任务、日志、评论、审核及统计权限；公司标签目录不因员工选择而扩大。

### 4.8 评论（任务与日志通用）

- 任务详情和日志详情底部增加平铺评论区，交互参考飞书文档底部评论：上方为按时间正序排列的评论列表，下方为输入框和发送操作；评论列表支持分页加载。
- **所有能查看该任务/日志的人都可以查看评论并发表评论**，包括创建者、负责人、审核人、有查看权限的管理层及日志可见范围内的上级。不能查看该任务/日志的人不能看到评论入口或评论内容。
- 评论展示作者、时间和内容；不支持楼中楼、子评论或回复层级，所有评论直接属于该任务/日志。评论不进入审核流程，不改变任务/日志状态、有效内容、审核人、标签或权限。
- 评论不参与 4.4 的待审冻结；待审期间仍可评论。评论不因任务完成、日志冻结而删除，但日志冻结后仍按日志查看权限展示。
- **本人控制**：评论作者可随时编辑、删除自己的评论，不受日志创建后 24 小时编辑窗口限制，也不需要任务审核。编辑后标注“已编辑”；删除后不再展示正文。其他人包括任务负责人、日志作者不能编辑或删除他人评论。
- **通知规则**：仅新评论发表时通知任务当前有效负责人（多人时全部）或日志作者；接收人去重并排除评论者本人。不额外通知任务创建人、审核人、全体可见人员或其他评论者。通知包含对象名称和评论用途，跳转至对应详情评论区；编辑、删除评论不另发通知，已删除评论的通知不再展示正文摘要。
- 新评论和编辑评论均使用适合长文本的多行输入区，默认高度约 160px、字号 16px，可竖向扩展；手机键盘出现后输入、发送、保存及取消仍可达。
- 评论操作仍须具备对象当前正常访问权限；查看权限被收回后，评论随任务/日志一起不可见，历史通知的只读例外不额外恢复评论区访问权，也不开放评论写入。

## 5. 员工业务页面

### 5.1 工作台（原导图/首页）

保留四象限，整个界面固定，各板块内容超出可视范围时在板块内下滑浏览，尽量展示完整信息。

| 位置 | 内容与数量 | 操作与排序 |
| --- | --- | --- |
| 左上 | 公司统一信息，最多十条 | 按后台设置顺序展示，员工端只读 |
| 右上 | 本人被他人派发且未完成的正常任务，最多十项 | 按派发时间倒序；条目仅标题和右对齐紧急程度，点击进入详情 |
| 左下 | 本人手动维护的个人信息，最多十条 | 点击详情后编辑、删除，列表不外显编辑/删除操作；不从日志自动生成 |
| 右下 | 本人最近十个自然日的日志，最多十条 | 包含今天及此前九个自然日，按日志日期倒序，点击查看原文 |

工作台日期区不显示“新建任务”按钮及空白占位。待办长标题不得挤出右侧紧急程度，为滚动条预留空间，窄屏滚动时仍完整可读。个人事项详情的编辑/删除只作用于当前事项。

每人每天一篇日志，不用任务派发时间给日志排序。待创建审核、未获准发布及仅因历史通知仍可访问的任务不进入首页正常任务列表。

### 5.2 日程（原视图）

日程以本人负责的正常任务为数据源，提供**月、日两种**日历模式，并提供创建任务、进入任务表单页和本人申请跟踪入口。本人只是创建者或仅有查看权限、但不是负责人的任务不进入日历及其当日列表；本人同时是创建者和负责人时正常显示。已完成的本人负责任务仍按排期展示。

#### 5.2.1 通用框架与入口

- 顶部第一行：左侧展开按钮，中央年月（如 `2026.10`，点击打开日期选择器），提供“任务表单”入口。年月随连续滚动的可视主月份更新。
- **跨月连续滚动**：月视图/任务瀑布流支持上下连续滑动，滚动到当前月末自动接续下一个月，向上可接续上一个月，不要求用户先通过月份选择器切换。月份选择器保留为快速跳转；连续滚动、月份选择和“回到今天/本月”须保持结果一致。
- 连续滚动边界不得出现空白页、重复任务或丢失任务；跨月任务在相邻月份自然衔接；顶部年月、月份选择器与当前可视主月份同步。从任务详情返回时保留原滚动位置和可视月份。
- 左侧展开为覆盖式抽屉，从左进入、约占日程区域 40%—45%，不挤压底层日历；窄屏右侧仍留明显日历。提供月/日切换、“我的申请”和关闭入口，不常驻旧范围说明。内容换行/纵滚，不自动全屏；打开时阻止底层误点误滚，关闭按钮、遮罩、返回及 Esc 可收起，并恢复日历位置与入口焦点。
- 日视图不在今天时，提供回到今天的快捷按钮；月视图提供回到本月入口。
- 右下悬浮加号打开创建任务表单，避免遮挡底部导航和关键任务内容。
- 日历页面不提供任务名称搜索框、搜索按钮或搜索结果，也不保留原任务数量统计区；名称搜索在任务表单页提供；分类统计取消，仅保留分页总数。日期选择器及其必要日期导航保留。
- 点击“任务表单”进入 5.2.6 的二级页面，可返回此前日历模式、日期和滚动位置；待创建审核申请仍通过独立“我的申请”入口跟踪，不混入普通任务表格。
- 选择日期并确认后，月视图定位到所在月，日视图定位到该日。日视图前后按天切换；**不提供独立周视图，不要求整周左右滑动**。
- **时间选择器**：创建、编辑、重开使用适合手机的时/分选择控件，规避安卓套壳中的大表盘时钟，精确保持跨日时刻，全天不伪造时刻。取消时间选择不关闭整张表单或清空草稿；日期采用日历式选择。各端控件均须满足相同的时间精度、校验和草稿保留要求。
- 日程页不提供“编辑标签”、标签图例或常驻标签展示行；任务条颜色按 4.7 的公司标签和既有个人颜色覆盖规则处理。

左上展开按钮用于视图功能面板，月格任务未显示完的提示用于打开当天完整列表，两者用途不同。月格 `+N` 等用于访问隐藏任务的数量提示保留，不属于已取消的分类统计栏。

#### 5.2.2 月视图

- 按自然月展示，星期从周一至周日排列。任务条按任务实际占用的公司日期绘制成日级条，不根据日内小时缩窄或偏移；例如 09:00—12:00 占当天一个日期格，不画成当天的 `3/24` 宽。
- 跨日任务连续覆盖占用日期；截止恰为次日 00:00 时不多占次日；零时长任务在所属日期明确标识，不改变真实工期。具体起止时刻从日视图或详情查看，按日绘制不把任务改成全天，也不改写业务排期或提醒。
- 月视图纵向连续滚动跨月，滚动过程中自动加载相邻月份；不因跨月滚动改变任务所属日期或重复计算任务。连续滚动与月格高度调整手势须共同设计，避免误触或冲突。
- 跨日任务应能辨认完整跨度，跨周在对应周继续展示；跨月任务在相邻月份连续衔接。
- 单日直接展示数量随月格高度调整，默认最多五条；空间不足时可少于五条，超出部分用 `+N` 提示并可打开当天完整任务列表。标题最多展示两行，再按当前样式截断。
- 日期数字、空白、任务条及 `+N` 的点击均从底部打开**实际点击日期**的完整当天清单，不直接开详情或切日视图。跨日条按命中日期定位，滚动、调高及双指手势不触发点击。
- 清单含当天全部本人有效负责的正常任务（含已完成）、按任务 ID 去重；按本人置顶优先、同组开始时间及稳定 ID 排序。顶部显示日期、“查看日视图”和关闭入口；空态可按该日创建任务。
- 清单点任务才进入原详情，关闭详情回到原清单及位置；关闭清单恢复月历日期、密度及滚动位置。手柄下拖或正文在顶部继续下拉可关闭，正文正常滚动不误关；同时支持关闭按钮、遮罩、返回/Esc 及焦点恢复。
- 默认按时间顺序，支持本人将重要任务置顶；置顶仅影响本人排列，不改写任务紧急程度。
- 任务块颜色按 4.7：本人已有个人颜色覆盖优先，其次公司标签集合第一项，均无时默认粉色；不使用白底。标签、颜色和拖动不改变任务权限或有效排期。
- 月视图拖动按天平移或调整开始/截止端点，具体见 5.2.7；待审任务在提议排期位置按虚线投影显示。

#### 5.2.3 日视图

- 顶部保留周一至周日日期行，标明选中日，点击日期行切换当天任务；日视图前后**按天切换**，不采用整周左右滑动。
- 日期行下、00:00 上为全天任务区，全天任务按完整日期范围展示，不伪造时刻。
- 下方为单日 00:00 至 24:00 纵向时间轴。定时任务完整覆盖公司某日 `00:00—次日00:00` 时，只在该日上方全天区紧凑展示；首尾不足整天仍按真实时段入时间轴。例：周二 20:00 至周四 10:00，周二显示 20:00—24:00、周三全天区、周四 00:00—10:00。
- 该归类仅影响展示，不改原始全天标记、起止、工期、截止或提醒；详情保留原排期。午夜截止不生成次日副本，零时长不误判全天，全天区全量可访问且当日不重复。
- 时间轴纵向滚动，任务全量展示、可访问，不以收起/折叠或溢出聚合代替任务；不要求全部 24 小时挤进首屏。可保留任务清单辅助模式。
- 日视图拖动按一小时相对增量移动或调整端点，保留原分钟、工期或另一端，具体见 5.2.7；全天区合法任务也提供整条和真实端点操作，不在时间轴重复绘制。
- 点击任务进入详情，颜色按 4.7。顶部提供明确“返回月视图”，回到当前选中日期所在月份，清理日视图临时面板并恢复相应焦点；无需依赖抽屉寻找返回入口。

#### 5.2.4 日历排序、重叠任务与分页总数

- 默认按时间组织任务。置顶影响月格及当日列表顺序，时间轴仅用标识强调，不改变真实起止位置。
- **同一时段重叠任务在所属日期内横向并列**，按并发列数减小单项宽度；日视图在当天时间轴宽度内分栏。各任务均可见、可点，不采用只显示一项再用“+N”聚合其余任务的方式。
- 任务标题可裁切，完整内容在详情查看，但不能让任务块互相覆盖导致无法点击。大量并发场景仍须逐项可访问，需要替代交互时记录设计变更，不以聚合隐藏代替任务。
- 标签背景不得影响任务块点击、时间位置或重叠分栏；文字与背景对比不足时由系统自动切换文字颜色。
- 日历和任务表单均不展示关系/待完成/逾期等分类统计栏；任务表单只保留完整筛选结果的分页总项数、页码及翻页。月格真实溢出数量 `+N` 仍保留。
- 任务表单页的关系筛选与计数按 5.2.6 执行；日历的个人置顶不决定任务表格的列排序。

#### 5.2.6 任务表单页（Excel 式任务列表）

**入口和数据**：从日程进入二级页面，顶部“返回日历”恢复原模式、日期及位置，不显示顶部刷新按钮。列表仅含本人原始创建或本人当前有效负责的已发布任务，两类并集去重；仅因上下级关系或其他查看授权而可见、但本人既不创建也不负责的任务不进入任务表单。待审显示原有效版及待审/冻结标记，不泄露提议或专用 diff；待创建、未发布、仅历史通知可读任务不进入列表、搜索或分页总数。点击名称打开原详情，业务操作沿用原权限。

- 本范围只限制本人任务表单，不缩小下属工作区、正常任务详情、统计、日志或人员资料等各自合法入口；本人日历仍只列本人当前有效负责的任务，不与任务表单范围混同。

**查看列**：默认“概览”，可切换以下四组。切列不改变数据范围、筛选或排序，横向位置回到该组起始，尽量保持当前任务的纵向位置。

| 列组 | 显示内容 |
| --- | --- |
| 概览 | 任务名称及本人关系/紧急程度、状态汇总（执行/待审/冻结/逾期）、起止排期、负责人、说明 |
| 排期 | 任务名称、开始、截止、紧急程度、执行状态、排期类型、逾期 |
| 资料 | 任务名称、负责人、原创建者、创建时间、说明、历史完成标准、进展、上级任务 |
| 全部列 | 任务名称、本人关系、执行状态、待审/冻结、截止、紧急程度、负责人、开始、原创建者、创建时间、说明、历史完成标准、排期类型、是否完成、进展、逾期、上级任务 |

- 不恢复新建任务“完成标准”输入；历史值在资料/全部列及详情兼容展示，不是新增必填字段。公司标签在详情查看和设置，不另设表格标签列；任务展示完整多标签集合。
- 名称列固定左侧、表头可定位，宽表横向滑动；提供左右翻列按钮和位置提示，边界按钮不可继续。概览合并状态与起止，日期时间分行、文本可预览，全文在详情可读，不以缩小字号容纳所有列。
- 不再要求所有列组固定“任务名+状态”两列或遵守一条全局列序；上述分组替代原 V4 的单一宽表设计。低优先级字段仍可通过相应列组、横滑及详情访问。

**筛选与搜索**：

- 搜索任务名称，范围为完整任务表单数据集；搜索常驻，其他关系、完成、起止日期条件可展开/收起。收起时显示生效条件摘要及数量；支持清空，Esc 可收起并恢复筛选按钮焦点。
- 关系为“全部/我负责/我创建”。“我创建”按原创建者判断，可与“我负责”重叠；正式接管不把任务算成接管人原始创建。“全部”即本表单的创建或负责并集，不再提供“仅可见”选项。
- 完成为“全部/未完成/已完成”，按有效执行状态判断，完成待审仍未完成。逾期未完成不算已完成。
- 日期按公司日期与任务排期相交筛选，默认全部日期，不暗中继承日历月份。条件组合生效，无结果可清空，不用无权任务补充结果。

**排序与分页**：至少支持任务名称、创建时间、开始、截止、紧急程度、执行状态升降序。默认开始升序，新列先升序，同列再次切降序，同值按任务 ID 稳定排序；紧急程度按紧急/高/中/低，状态按待开始/进行中/已完成。所有筛选、排序作用于完整结果后再分页，每页默认 50 条；不能只处理 API 当前一页或将部分加载误报完整。

只显示完整组合筛选结果的总项数、当前页和翻页，不展示负责/创建/待完成/已完成/逾期分类统计，也不保留两句旧范围/排序说明。排序和翻页不改变总项数。

**返回与更新**：详情普通关闭保留筛选、页码和纵横滚动位置；换列尽量保持阅读任务；搜索、筛选、排序及翻页按新结果从页首浏览。写入成功或权限变化后按当前数据重算，过期搜索防抖响应不能覆盖新操作或重置刚恢复的位置。被移出负责人但仍有查看权者可在表单保留，不能继续进入本人日历。

#### 5.2.7 拖动、仅排期与待审投影

**拖动入口与权限**

- 仅本人月/日视图提供拖动；任务表单、下属日程和画布外的独立调时按钮不提供拖动。
- 本人视图仍只列本人当前有效负责的任务。仅已发布、未完成、非待审且当前用户具有现有仅排期权限的任务可拖动。
- 拖动是本人视图的交互入口，不等于收紧后端仅排期权限；仅排期操作仍按 2.3 适用于正常可见、已发布、未完成、非待审任务，不限创建人、业务责任方或负责人。
- 仅排期操作不得夹带基础资料、标签、负责人、进展或执行状态修改；提交和审核生效前重新检查权限、版本、状态和截止。

**月视图拖动**

- 整条拖动按天平移，保留原日内起止时刻及工期。
- 拖动真实开始或截止端点时，按天调整该端日期，保留该端日内时刻和另一端不变，允许改变工期；截止不得早于开始。
- 支持跨周、跨月和跨年。续接片段被拖动时移动完整任务，不把片段日期当作任务原始开始；被裁剪的续接端不能冒充真实端点。

**日视图拖动**

- 横向或纵向拖动按一小时相对增量调整，保留原分钟；整条移动保留工期，端点调整保留另一端不变。
- 纵向全天区的合法任务也提供整条和真实端点操作，不因归入全天区而丢失能力；不在时间轴重复绘制。

**确认与审核**

- 拖动实时预览完整排期，松开后确认、填写原因并按 4.3 的申请人直属上级规则审核。
- 取消、无位移、逆序、版本冲突和权限/状态变化不能隐式保存，也不能误触其他入口。
- 待审期间冻结拖动；评论按独立权限保留。

**待审投影**

- 已发布任务进入任意后续审核时，一律显示虚线外包围线、淡底和可辨识的审核中状态，保留标签颜色。
- 有排期变化时，本人及授权下属日程只在提议的新位置显示一次，框体、跨度、日期和文字均取提议排期，原位置不留副本。
- 无排期变化时，在原有效位置显示虚线。月历按提议占用日期绘制日级条，日轴按提议真实时段绘制；刷新、重新登录、切换视图后保持一致。
- 虚线投影不是提前生效：实际有效排期、普通任务详情、任务表单、提醒及其他业务权限仍按原有效版本处理。
- 审核通过后按新有效排期恢复实线；驳回、撤回或失效后按仍有效排期恢复实线。
- 未发布的创建申请不进入正常日程；固定创始人合法免审的修改直接生效，不制造虚线待审或本人待审事项。
- 本人及下属日程画布不放置独立“调时、起、止”按钮；本人视图通过框体和透明边缘操作，下属页面不提供拖动。

### 5.3 日志

- 产品界面统一使用“日志”，不再使用“记录”作为模块名或入口名；任务的技术流水称“任务操作历史”。日志页只承担写日志和查看本人历史。
- **日志页只展示当前登录者本人的日志**：移除部门、团队、人员及范围内全部等筛选，不混入他人日志、任务或审核事项。列表、计数、刷新、回顶及账号切换都使用本人范围；旧筛选状态不能恢复他人内容。本人无日志时显示个人空态。
- 合法的下属日志阅读从 5.7 人员工作区独立进入，不改变本人日志页范围；日志页不提供下属筛选入口。

**写日志与编辑日志**

- “写日志”统一创建公司今天、昨天、前天中尚未创建且可创建的日志，不再单独提供补写按钮。日期候选只包含缺失日期，不允许未来或更早日期；三天均已有记录时提示从已有日志进入编辑。
- 每人每天仅一篇日志；目标日期已有记录时只能按明确编辑入口进入，不能新建第二篇。
- 创建与编辑使用独立界面、草稿模式和提交目标，不能仅改同一创建模板的标题或禁用控件来充当编辑页。
- 创建界面提供近三天缺失日期选择、公司标签（单选或不选）、正文、可选关联任务及保存/返回。
- 编辑界面展示目标日志的不可修改业务日期，提供公司标签、正文、可选关联任务及保存/返回；不出现创建日期候选、补写或新建控件。日期使用只读展示字段，不保留冗余的禁用日期下拉框。
- 点击已有日志的明确编辑入口进入编辑并绑定真实日志 ID；不能以选择已有日期的方式自动切入编辑。编辑不改业务日期，不重置冻结时刻。
- 重复创建或并发冲突不自动转编辑、不覆盖已有日志，保留当前草稿并反馈。选择关联任务后返回、网络失败、版本冲突或冻结时，不串用创建与编辑的草稿或提交目标。
- **创建后 24 小时编辑窗口**：日志创建时记录创建时间，作者可在创建后 24 小时内编辑或删除；超过 24 小时自动冻结，转为只读。冻结时限与**创建时间**绑定，不按日志日期或当日 24:00 计算。
  - 例：10 月 27 日 23:50 补写 10 月 26 日的日志，可编辑至 10 月 28 日 23:50，不会在 10 月 27 日 24:00 冻结。
  - 目标日期已有一篇且已冻结时，只能查看，不能编辑或删除；目标日期没有日志且仍在近三天内时，可以新建。
  - 删除不重置原创建时间，也不能通过删除重建绕过同人同日唯一性和冻结约束；冻结后不能删除。
- **不能编辑别人日志**：即使上级可查看下属日志，也只能只读查看，不能编辑、删除或代写。不可编辑时直接隐藏编辑和删除按钮，不显示为可点击但报错的状态。

**查看、详情与评论**

- 日志可关联一项本人有权查看的任务，也可不关联。日志属于作者，可见性不随任务参与者变化；参与同一任务不获得同事日志权限。日志中关联的任务按任务权限独立检查。
- 去掉日志卡片上的“查看与评论”按钮。点击日志正文或空白区域即可进入该日志详情与评论，键盘聚焦后支持 Enter/Space；卡片内编辑、关联任务等独立按钮只执行自身动作，不重复触发详情。
- 日志详情底部提供评论区，所有能查看该日志的人可评论；评论规则见 4.8。
- 本人日志列表、日志详情正文与下属日志正文统一为 15px 字号、1.55 行高；长内容正常换行，无横向溢出；详情可阅读全文并进入评论。编辑输入、评论和元信息保留各自用途，不机械统一所有文字样式。

**标签、日期与布局**

- 日志标签为单选或不选；所有标签定义由固定创始人维护，员工只能在日志编辑权内选择或清除。未选标签使用默认粉色，不使用白底。
- 创建与编辑分别做好日期与标签的标题、间距、字段高度及视觉对齐；桌面同排对齐，窄屏同列边缘对齐，无截断或横向溢出。编辑页只读日期与标签选择控件也要对齐。
- 在 320、390 及桌面宽度检查布局，正文、保存和返回入口保持可达。
- 日志页不提供任务创建、任务审核、本人任务申请、请示或回复入口，不设置日志与审核/申请混合标签。日志导航项处于当前页时可进入“写日志”，但已有目标日期记录时只能按上述编辑入口进入，不自动新建。

### 5.4 统计（原 AI 地图）

保留任务统计、关键词词云和建议三部分。V1 采用基于实际任务数据的规则分析，不以外部模型或 MBTI 为前置条件。

- 统计当前权限范围的任务数、执行状态、逾期数及紧急程度分布；待完成审核与已完成分开统计，待创建审核不计入执行任务。
- 创始人看全公司统计、词云及公司建议；部门负责人看本部门统计/词云，团队负责人看本团队统计/词云，两类负责人的建议均仅针对本人任务；普通员工看本人统计、词云及建议。
- 词云从对应范围的任务标题、说明提取，不默认分析完整私人日志，也不默认分析评论内容。
- 建议围绕临期/逾期、排期冲突及高紧急程度任务生成；临期口径与 5.6.2 一致。进入页面或主动刷新时更新，标明分析范围、生成方式和更新时间。
- 明细跳转、词云和建议均不得泄露权限外信息，也不因历史通知可访问某任务而把它纳入当前统计。不能用固定词表或预写文案冒充真实数据分析。
- 标签和评论不改变统计口径；标签不作为权限或完成状态参与统计。
- 分析页只展示真实统计范围、生成时间和用户可理解的方法/来源，不显示内部方法代码、原型/开发者解释或“外部模型已生成”等不实文案；不删除 AI 地图功能。

### 5.5 我的

- 展示本人公司、姓名、展示职位、由位置推导的四层身份及实际部门、团队、直属上级和登录手机号；创始人不伪造部门/团队，部门负责人不强制团队。不展示员工用户名。
- 本人可改头像、邮箱、密码及退出；姓名和手机号为只读，由管理员维护。不再提供员工团队管理入口。
- 手机号按授权详情读取，邮箱仅本人。
- **标签维护入口只属于固定创始人**：创始人可在“我的”创建、改名、改色、删除全部公司标签，包括历史上称为私人标签的定义；其他员工和独立管理员没有标签定义维护入口，只能在拥有相应编辑权时选择或清除。PC 管理端不设标签栏目。
- **下属资料按真实管理树展示**：按当前实际管理链展示全部合法直接及间接下属，不能只按职位名称或职级猜层级。支持逐层展开/收起，展开节点与点击人员分别操作；节点展示姓名、职级/职位及真实部门/团队，有职位时仍保留组织信息，公司层无部门者明确显示公司层。展开状态不跨账号保留，组织变化后重新校验范围。
- 资料卡不设派发任务按钮。从下属资料进入 5.7 独立工作区，提供日志与日程入口；不得把“进入工作区”理解为获得编辑权。
- 下属工作区中的普通任务详情按当前用户原有权限显示操作，不因来自下属入口额外禁用，也不因能看见而增加基础编辑权；下属日志正文上级不可编辑，评论按独立权限办理。

### 5.6 通知中心

#### 5.6.1 通知事件与接收人

通知以真实业务事件产生站内消息与系统推送，覆盖审核请求与结果、任务创建、基础信息及紧急程度变化、进展/状态变化、完成、重开、临期、逾期和申请失效。请示/回复不纳入 V1。

| 事件 | 接收人 | 查看入口与限制 |
| --- | --- | --- |
| 创建申请提交及未通过前的拒绝、撤销、失效结果 | 申请人和对应审核人 | 本人申请/审核详情；不提前通知其他负责人或公司管理者 |
| 已生效任务的修改、进展、完成、重开、交接申请提交 | 本次审核人，申请人可跟踪 | 申请详情；其他任务人员不提前查看提议内容 |
| 已生效任务的审核通过、拒绝/退回、撤销、失效 | 申请人、审核人及相关任务人员 | 结果或有效任务详情；差异对比仅审核人可见 |
| 创建生效、基础信息/紧急程度/标签/进展/状态变更生效 | 当前业务责任方与当前全部负责人 | 正常任务详情 |
| 负责人变更生效 | 当前业务责任方、当前全部负责人、本次新增及被移除负责人 | 变更消息；被移除人员按 5.6.4 保留历史查看 |
| 临期、逾期提醒 | 当前业务责任方与当前全部负责人 | 正常任务详情；待审失效时另告知申请人和审核人 |
| 新评论 | 任务当前有效负责人，或日志作者 | 对应任务/日志详情评论区；去重并排除评论者本人；编辑、删除不另发通知 |

- 通知列表默认只显示所属任务或对象、通知类型、已读状态和通知时间；正文、具体变化和完整摘要进入详情查看，可保留完整摘要显示模式。
- 非任务通知显示所属对象；没有关联任务或对象不可读时，使用安全占位，不泄露受限名称或正文。
- **通知展示信息由系统自动生成**：根据任务、对象、事件、申请、变化内容和时间生成，不新增人工填写的通知标题、摘要等字段。对象缺失、撤回或失权时使用安全兜底。
- 任何任务状态更新均触发通知；申请提交与变更生效是不同事件，同次操作修改多个字段用一条消息汇总变化。
- 同一事件中，一个人兼任多个接收身份仅接收一条业务消息，自通知不主动排除；站内消息与系统推送是同一事件的不同渠道。
- 创建审核通过后再通知全体负责人，待创建隔离优先于一般“相关人员均通知”的规则。
- 所有审核事件的审核人提示均按 4.3 的申请人当前直属上级规则生成；组织或接管后的待审改派同步通知，旧审核人不得继续决定。
- 合并指向同一任务详情的重复入口，不同时提供用途相同的“查看相关任务”和“查看相关对象”；评论通知保留定位评论区的用途，查看申请或审核申请仍是独立业务操作。

#### 5.6.2 临期、逾期与待审到期

**临期采用剩余工期比例，取代旧稿“提前三天重复提醒”。**

- 按公司时区确定计划开始时刻 `S` 和截止时刻 `D`，总工期 `T = D - S`，以自然经过时间计算，不扣除夜间、周末或节假日。
- 剩余总工期的 **20%、10%、5%** 时各提醒一次，即 `D - 0.20T`、`D - 0.10T`、`D - 0.05T`。例如 09:00 至 19:00 的十小时任务，分别在 17:00、18:00、18:30 提醒。
- 全天任务以开始日 00:00 为 `S`，截止日公司配置的下班时刻为 `D`；下班时刻默认 **18:00**，管理员可设置。日历仍覆盖完整首尾日期，不因提醒截止时刻缩短全天条带。
- 已完成任务不提醒；待审核期间不发送常规临期/逾期提醒。**待审期间跨过适用截止时间时，原申请到期失效并解除冻结，告知申请人及审核人须调整后重提**，不能继续批准原申请。
- 已生效且未完成的任务解除待审时如已逾期，向当前业务责任方及当前负责人补一次逾期提醒；可与失效结果合并说明，但需保留两种事件的记录。尚未发布的创建申请只发送失效及重提通知，不进入普通任务提醒集合。
- 逾期任务提醒一次。申请失效不等于任务取消或自动完成，任务保持原有效内容；无基础资料修改权限的申请人由当前业务责任方调整排期后再发起自己的操作。

以下为使上述规则可执行的时间处理约定：

- 创建、含排期变更的修改/重开申请，待审失效以**本次提议截止时间**为准；其他申请以当前有效截止时间为准。已过期的排期须调整后重提，不能提交后等待旧申请继续通过。
- 仅在总工期大于零时计算比例提醒；起止相同时不发比例提醒，未完成且超过截止时发送一次逾期提醒。
- 调度延迟、任务生效较晚或解除冻结时跨过多个临期节点，只补当前最近一个已到节点，之后节点正常发送，避免连续补发多条过时提醒；已逾期时只按逾期规则处理。
- 同一任务、同一执行轮次、同一生效排期下，各比例节点和逾期提醒分别去重；重开或排期变更生效后按新轮次/排期重新计算。截止失效与人工审核/撤销并发时，只能有一个最终处理结果。

#### 5.6.3 消息生命周期

- 通知列表不显示底部刷新/关闭操作栏，保留头部关闭入口；空列表及键盘操作也可关闭，不影响消息详情中的业务操作。
- 打开消息即标记已读，通知入口显示未读数量。
- 已通过、拒绝/退回、撤销或失效的审核通知置灰并显示处理结果，不再提供有效审核按钮。消息已读、删除或撤回本身不办理审核。
- 通知列表项按 5.6.1 显示所属任务/对象、通知类型、已读状态和时间；正文、变化摘要和处理结果在详情首屏可见，不把完整正文堆到默认列表。
- 通知保存三个月，用户可删除自己的消息，管理端支持通知管理；个人删除不影响其他接收人的消息或管理端操作历史。
- 通知发送后 **3 分钟内**可撤回，超过时限不提供撤回操作。为区分发起人撤回与个人删除，本版约定：业务操作发起人可撤回该操作触发的通知，管理员在后台通知管理权限内处理；自动提醒由管理员管理，普通接收人只能删除自己的消息。
- 撤回后，普通接收人只看到“通知已撤回”提示，不再展示被撤回的通知正文或原跳转内容；若本人本来具有任务权限，仍可从正常任务入口查看。撤回不撤销任务结果、已生效变更或审核申请。
- **受限例外**：原消息接收人若是业务发起人当前实际管理链上的上级，且其通知副本送达时没有屏蔽内容，可在消息仍可访问时只读查看原通知标题、摘要和变更摘要，并显示“通知已撤回，当前上级可只读查看原内容”的原因提示。该例外不向所有上层、同级、其他管理链或仅有管理员身份者开放；被送达屏蔽的内容不能补回；个人已删除或超过保存期的通知不因上级身份重新开放；仍不开放任务/申请跳转、审核或其他业务操作。该例外与 5.6.4 的失权历史通知只读不同，不能互相扩大。

#### 5.6.4 权限变化后的历史通知

对于普通任务事件通知，负责人被移除或组织权限收回后，**本人已收到且尚在保存期内的历史通知保留标题与变更摘要，仍允许通过原通知查看该任务详情**，显示“负责人身份/访问授权已撤销”等提示；这里撤销的是工作关系或授权，不表示任务或申请已被取消。

- 该例外只向原消息接收人开放，查看为只读，不恢复修改、进展、完成、审核、评论或重新关联权限。
- 详情展示该任务已生效内容，不开放待审提议、审核人专用差异、其他受限关联任务、人员手机号或他人日志；也不恢复普通列表、搜索、首页、任务计数或 AI 分析范围。
- **评论通知不适用普通任务的失权历史例外**：评论已删除、缺失或对象正常权限丧失时，隐藏评论正文、任务/对象/审核跳转，并拒绝该通知的历史任务入口；撤回后的上级只读资格也不恢复受限评论内容。当前有正常对象权且评论仍有效者按正常入口读取。
- 通知尚未送达时不能因曾在接收人列表就获得查看权；待创建审核仍只向申请人和审核人开放。消息被删除、撤回或超过保存期后，该消息不再提供历史查看入口。

#### 5.6.5 通知列表、筛选与状态同步

- **列表默认紧凑显示**：所属任务/对象、通知类型、已读状态、通知时间；正文、具体变化和完整摘要进入详情查看，可保留完整摘要显示模式。
- 支持“全部/未读/已读”与“需我审核/结果告知/提醒/评论/其他”两组筛选，两组可组合。
- “需我审核”仅包含当前用户仍有权办理、尚未到期的待审事项，不能仅凭历史事件类型判断；已失权、已办结、已到期或不可访问的记录不得进入该筛选。
- 筛选先于计数和分页；分页总数按筛选后的结果计算。全局未读数不因当前列表筛选条件改变，始终按用户全部未读消息统计。
- 打开通知即标记已读。返回列表后，已读状态、未读数量和当前筛选结果立即同步；在“未读”筛选下，该通知不得继续作为未读项保留。
- 筛选、分页和打开详情期间，旧请求响应不得覆盖新筛选或新账号数据；空结果、对象缺失、撤回和失权均显示各自安全状态。
- 完整摘要模式可显示事件类型、任务名、实际变化摘要和时间；默认紧凑模式不要求列表承担完整正文，但必须能区分通知用途并进入详情。
- 通知详情的审核结果置灰、撤回、三个月保存、个人删除、历史只读和评论裁剪规则继续适用。

### 5.7 下属工作区

- 从“我的”下属资料进入独立工作页，明确当前查看的人员，提供日志与日程切换及人员资料，不清空为无身份页面。
- 展示内容以该人员自己的日志、该人员当前负责的日程为参照，同时必须处于查看者当前授权范围；不以代入下属身份绕过权限。
- 下属日程默认月视图，可切日视图；月历按 5.2.2 的日级方式绘制，日视图提供真实时间轴、独立全天区和任务清单。
- 支持日期选择、前后导航、回今天和完整分页；跨日、午夜、零时长及重叠任务正确，月历、日轴、全天区和清单均能辨识完成状态。
- 下属日程页面不提供整条拖动、端点拖动、画布上的独立调时按钮或任务表单入口；画布不放置独立“调时/起/止”按钮。
- **不能把下属工作区及任务详情笼统定义成严格只读**：点击任务进入正常鉴权详情后，按当前用户原有权限显示基础编辑、精确排期或其他操作，不因来自下属入口额外禁用，也不因能看见而增加基础编辑权。仅排期操作按 2.3 和 5.2.7 执行。
- 下属日志正文仍不可由上级编辑；评论按独立权限办理。日志正文和本人日志使用一致的 15px/1.55 阅读样式。
- 待审虚线和提议位置按 5.2.7 展示；进入详情后返回应保留人员、日期、模式及页签，不改写本人日历或日志状态。
- 快速切人、换账号或失权时，旧响应不能串入新人员/账号，失权正文及时清除；旧筛选、旧滚动位置和旧人员数据不得跨账号保留。

## 7. 视觉与交互原则

整体简洁，信息可扫描、操作易触达。五个栏目保持稳定，不为新标签、表单或通知增加主导航。

- **表单**：默认概览突出任务、状态、起止及负责人；其他内容通过列组和横滑访问，固定名称列，不以缩小字号塞满整表。开始/截止各自成组，移除全天开关并保留设为全天快捷；负责人使用真实管理树，展开与勾选分离。任务详情按标题、状态/截止、负责人、紧急程度、排期、说明、公司标签完整集合、评论组织。
- **日历**：覆盖式抽屉不挤日历；月视图按日绘制并按天拖动，日视图按小时调整；月格统一开当天清单，清单及详情返回保留位置。月格调高、跨月滚动、横滑、拖动和关闭手势分别识别，正文滚动不误关。日轴完整、重叠全量可点；待审按提议位置显示虚线投影。
- **日志**：日志页仅本人，不提供他人/部门/团队筛选；点击正文或空白进入详情与评论，独立按钮不冒泡；创建/编辑独立界面，日期与标签对齐；本人及下属日志正文 15px/1.55，长文换行。
- **时间选择**：采用适合手机的时分控件，支持各端输入方式，取消不丢草稿；安卓套壳规避大表盘。
- **标签**：所有标签由创始人维护，任务使用多选胶囊色块并在色块下显示名称，日志单选/不选；日程不提供编辑标签或图例。颜色按既有个人覆盖→公司标签首项→默认粉色，八色预设；颜色、药丸、文字和时间轴背景保持可读，分类不只靠颜色表达。
- **评论**：列表平铺，新增/编辑均为大多行输入区，Web 默认高度约 160px、16px 字号，原生控件提供等效可读和输入空间；保存、发送、取消在手机及键盘占位后可达。评论与共享任务审核及日志冻结解耦，但跟随对象正常访问权。
- **通知**：默认紧凑列表只显示任务/对象、类型、已读和时间；正文和变化在详情，完整摘要为可选模式；类型与已读筛选组合，筛选先于计数分页，打开即读并同步列表。
- **文案**：正式界面不显示原型/开发者/AI 提示、内部方法名或重复规则长段；保留字段名、空态、校验、失败重试、危险确认和业务状态提示，不清理真实业务内容。
- **网络反馈**：登录、工作台/任务加载及保存展示对应状态；请求进行中防重复触发，成功/失败消息与加载状态分开。并发请求各自结束，最后一个当前会话请求结束才清理加载；接收响应正文期间仍属于等待。
- **慢请求及失败**：请求约 8 秒后提示仍在等待、保存勿重复提交；约 20 秒超时后明确提示可重试。断网、超时与主动取消区分，写入重试复用幂等语义，不重复保存；按钮和焦点状态最终恢复。时间阈值为交互设计参数，可调整但不得取消明确反馈。
- **会话隔离**：退出/失效/换账号清理旧请求和加载状态，旧响应不得覆盖新会话；刷新、搜索和并发加载也不能让旧结果盖过新结果。
- **跨端适配**：窄屏、系统键盘、滚动、弹层焦点及返回行为须适合目标运行环境；安卓套壳与原生端均须保持输入、提交及关闭入口可达，浏览器和系统返回不丢失需保留的上下文。

## 8. 跨端一致性与质量要求

### 8.1 员工端与管理端分工

- 员工 Web、Android 套壳及 Android 原生端遵循统一的组织、身份、任务、审核、日志、标签、评论和通知规则。页面及控件可按平台特点适配，不能改变业务权限、数据范围或审核结果。
- 管理能力由独立 PC Web 管理端承载，员工端不嵌入完整管理模块；管理员身份不能代替员工业务身份。
- 各端使用一致的员工手机号/管理员账号名与身份类型契约，保留同一员工内部 ID，不通过旧请求格式、缓存或页面按钮绕过认证及首次改密要求。
- 站内通知与系统推送对应同一业务事件，接收、摘要、跳转及办理权限一致；消息查看和办理时按最新关系鉴权。

### 8.2 移动端使用与升级

- 在目标浏览器及安卓设备中验证板块独立滚动、跨月浏览、月格调高、完整日轴、重叠任务点击、返回位置、标签对比及评论输入。首轮可使用开发人员现有真机，记录机型及结果。
- 系统键盘、时间选择和系统返回不能遮住必要操作、误关其他弹层或清空需保留的草稿。安卓套壳规避系统大表盘；原生端提供等效易用的时分选择。
- 安卓应用安装、启动、覆盖升级后须能正常认证及使用业务功能，升级保留应持久保存的设置和数据；客户端与共用后端的身份及业务契约保持一致。
- 每个平台按目标运行环境验收，结果另记；跨端一致性不要求各端使用相同代码或相同视觉控件。

### 8.3 性能、启动与数据完整性

- 大数据量下工作台及任务、审批、日志、通知、统计查询须保持可用，结果完整、不漏页、不将部分数据标为全部；总数和排序覆盖全部符合条件的任务。
- 优化读取不能改变正常范围、有效版隔离、通知裁剪、历史只读例外或实时鉴权。组织/接管变化后，新请求须按最新关系裁决，缓存不延长旧权限。
- 应用初始化和必要维护完成、数据库可用后才报告健康；未就绪须明确响应，不提前接入正常业务流量。普通启动不应因无关公司的审批维护阻塞业务，不清空或重建演示数据。
- 新建库及升级库须得到一致业务结构与约束，升级保留员工内部 ID、原始创建者及业务历史，不回写已应用历史迁移。
- 旧数据缺失或无法确认创始人、负责人、位置、管理员来源，或出现重复手机号时，须明确报告并受控修复，不猜身份、不跳过审核或以非法组织取得免审。
- 普通 HTTP 地址下的写入必须与 HTTPS 使用相同业务规则；客户端不能依赖仅安全上下文可用的随机标识 API。缺少该 API 时使用兼容回退生成幂等键，首次成功但响应丢失后的重试不得重复创建申请或写入。
- 普通 HTTP 提交失败不得改变权限、审核、版本或幂等语义；保留当前表单草稿并向用户显示可重试提示，不暴露内部实现说明。

整合时采用以下边界：

- 保留原始创建者、当前业务责任方、当前负责人和申请人四种关系，各自用于来源、办理/审核、执行和申请跟踪，不混写为同一人。
- 个人颜色覆盖只是本人显示兼容，不改变公司标签多选规则，也不是任务私人草稿；日志使用公司标签单选或不选。标签定义只由创始人维护。
- “全部列”不等于在线电子表格编辑引擎；历史完成标准兼容不等于恢复新建输入，取消分类统计不等于取消分页总数或逐行状态。
- 首位创始人入草稿不等于已建账号；停用安排须先完成必要业务审核，不把管理员完整组织提交变成绕过审核的入口。
- “整屏”是占满应用可用容器，不要求触发浏览器系统全屏。各端均须保证时间选择取消、键盘输入和返回导航符合正文要求。

## 10. 演示与数据准备

### 10.1 演示账号与安全范围

- 使用后端持久化、手机号登录的有效员工账号和独立管理员账号；快捷入口不能绕过真实认证、直接切换权限或显示密码。
- 演示准备可在**明确指定且具备演示标识的目标库**受控重建符合固定组织的员工和业务样本，不要求保留旧演示关系，也不把“不得自建命名演示账号”解释为禁止重建演示员工。员工仍只有姓名、手机号和稳定 ID，无自定义登录用户名。
- 不在正常启动时清空或覆盖任意数据库；可重复准备，刷新/重启后保留持久数据，不以静态前端假数据或预写统计替代。
- 选数据丰富且有下属/跨部门任务/待审/通知/日志的部门或团队负责人连续演示；另备创始人、普通员工和管理员，以便显示四层差异。演示前完成首次改密。

### 10.2 演示数据覆盖

- **组织与账号**：固定创始人、至少两个部门、每部门多个团队和完整负责人/普通员工，职位及手机号合法；管理员不占组织位置。另在隔离空公司演示首位创始人加入草稿/取消/保存。
- **公司及个人事项**：公司信息十条，可滚动和调序；个人事项通过详情准确编辑/删除，不从日志生成。
- **任务及审核**：创建者不负责、跨部门多负责人、普通员工指派创始人、业务接管；覆盖申请人直属上级审核、固定创始人免审、非创始人无上级阻断、需他人审核、驳回/撤销/失效、完成/重开及专用交接。
- **排期**：跨月/跨年/跨日、午夜截止、零时长、整日覆盖和超过五项重叠；显示归类与提醒排期独立；月视图日级条和按天拖动、日视图小时拖动、待审提议虚线投影各有样本。
- **表单**：超过两页任务数据，四组列、横向滚动、固定名称、可折叠筛选、全结果排序及去重分页总数；无分类统计或顶部刷新。
- **日志**：日志页仅本人；统一写日志覆盖近三天缺失日期，创建/编辑独立界面；首次 24 小时冻结、删除重建约束；下属日志从人员工作区按权限进入。
- **标签与评论**：创始人维护全部公司标签，任务多选、日志单选/不选，历史引用和删除逻辑可追溯；任务/日志评论、作者编辑删除、大输入区和新评论定向通知。
- **通知与权限变化**：审核、生效、提醒、失效及接管改派；覆盖紧凑列表、全部/未读/已读与类型组合筛选、筛选后计数分页、打开即读同步；普通历史只读、撤回上级例外、失权/已删除评论裁剪。新旧账号不串数据。
- **下属工作区**：真实管理树、逐层展开、下属日志只读、下属日程月/日切换、页面不拖动、任务详情按原权限、快速切人与失权清理。
- **HTTP 兼容**：普通 HTTP 写入、首次响应丢失后的幂等重试、失败草稿保留及防重复。
- **数据质量**：使用真实业务语义，避免 Smoke、测试编号等干扰展示；保留必要来源、业务接管及历史，不能以删数据回避约束。

### 10.3 演示路径

1. 管理员展示完整固定组织与展示职位，再用员工手机号真实登录，查看工作台独立滚动及紧急程度。
2. 日程跨月浏览，点跨日条的不同日期进入对应清单；演示月视图日级条与按天拖动、日视图小时拖动和待审提议虚线投影；详情返回原清单，再明确返回月视图。
3. 任务表单切四组列、折叠筛选、组合搜索、全局排序和翻页，详情返回保持位置；说明总项数与逐行状态。
4. 普通员工创建并指派创始人，由申请人直属上级审核；演示固定创始人免审、非创始人无有效上级阻断，以及修改/进展/完成/重开/交接均按申请人直属上级审核。
5. 展示专用交接与正式业务接管，确认原创建来源及“我创建”不被改写；停用依完整方案办理，不跳必要审核。
6. 日志页演示本人范围、统一写日志覆盖近三天缺失日期、创建/编辑独立界面、24 小时窗口和冻结；从下属工作区进入其只读日志。
7. 创始人维护公司标签，员工为任务多选、日志单选/不选；历史个人颜色覆盖只影响本人显示。演示评论输入、编辑删除及新评论通知。
8. 通知紧凑列表、组合筛选、筛选后计数分页、打开即读及结果/撤回/历史只读边界；模拟普通 HTTP 提交、慢请求/断网重试和换账号隔离，确认不重复、不串数据。历史日期进展不在本版范围；系统推送及安卓设备行为按对应产品要求演示。
