# 2026-11-04 OpenSpec 变更对照

本表记录 [活动 change](../../openspec/changes/refine-notifications-task-editing-and-staff-browsing/proposal.md) 对 2026-10-30 V4 基线的替换。以该 change 的规格为当前实施依据；V4 和已归档证据保留其历史时间点，不回写为本轮已验证结论。

| 旧口径 | 当前 change 的口径 | 实现 / 检查入口 |
| --- | --- | --- |
| 私人标签、个人任务颜色覆盖 | 清理私人目录与覆盖表，仅公司共用多标签；首标签决定颜色 | V30、`Tags`、`潘多拉-标签评论.js`、`check_apply_private_migration_guard.py` |
| 日志单 `tagId` | 有序 `tagIds/tags`，V29 回填且保留日志首次创建时间 | V29、`WorkspaceService`、`check_apply_log_tags.py` |
| 基础信息仅业务责任方编辑；进展单独提交 | 当前有效负责人可编辑普通字段和进展，创建者在任或接管人控制负责人顺序；混合提议一次审核 | `TaskService`、`潘多拉-任务接入.js`、`check_apply_mixed_edit.py` |
| 普通任务详情固定责任方和审核人、员工执行时间线 | 仅显示当前有效信息与授权申请意见；当前申请回读真实审核人；完整操作历史留在管理端 | `TaskService`、任务详情与审核页 |
| 通知按旧事件名分类，原申请跳转沿用审核按钮 | 实际提醒/逾期归提醒类；`canReadRequest` 独立于 `canReview`，按原申请绑定和现权裁剪 | `WorkspaceService`、`check_fixed_notifications.py` |
| 姓名直接进入下属工作，详情可沿本人业务权限写入 | 先资料卡再日程/日志；整条下属导航只浏览和评论，独立人员与任务缓存 | `潘多拉-个人资料.js`、`潘多拉-api.js`、浏览器专项待验 |
| 日轴整日片段可拖；拖动后进入完整任务编辑 | 仅完整普通日内区间/点任务可按小时拖；拖动进入轻量排期确认 | `潘多拉-日程视图.js`、`潘多拉-任务接入.js`、拖动专项待验 |
| 管理员只知道手机号是否录入 | 同公司员工管理列表/详情读完整 `loginPhone`，普通目录继续裁剪 | `OrganizationService`、`admin.html`、`check_apply_admin_login_phone.py` |

未列出的审核冻结、三天日志补写和首次创建后 24 小时冻结、通知撤回/保留、管理员与员工身份隔离继续按现有规格办理。脚本存在与单次运行通过都不等同于独立验证；完成情况以 change 的 `tasks.md` 和后续 verification 为准。
