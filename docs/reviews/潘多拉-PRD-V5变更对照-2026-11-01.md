# 潘多拉 PRD V5 变更对照（2026-11-01）

本文支撑 [V5 修订版](../requirements/潘多拉-产品需求文档-V5修订版.md) 的本次更新。原始反馈基于提交 `0826463`；需求原稿见 [原始 16 条反馈与增补需求确认稿](../requirements/潘多拉-反馈需求确认稿-2026-11-01.md)。

本文只做需求文档的整合、追溯和一致性检查，不修改代码、数据库、OpenSpec 归档或验证记录；不表示 V5 已实现或已通过验收。

## 1. 本轮交付与优先级

- V5 是新的需求入口，V4 保留为历史版本；V4 未被本轮明确覆盖的规则继续有效。
- 本轮明确选择优先于历史冲突口径：
  - 月历按天显示和拖动，日视图按小时调整。
  - 下属页面不拖动，但普通任务详情按当前用户原有权限，不强制只读。
  - 基础字段“正常可见即可编辑”仍暂缓。
- 本轮确认：**所有标签都是公司创始人创建和编辑，标签是任务的大致分类**；员工只在拥有相应编辑权时选择/清除，任务多选、日志单选或不选。
- 本轮确认：固定创始人的需审核操作按推荐口径免审并留因；非创始人没有有效直属上级时阻断。

## 3. 主要旧规则替换

| V4/历史口径 | V5 口径 | 采用依据 |
| --- | --- | --- |
| 创建由创建者直属上级审核，非创建由当前业务责任方审核，本人即审核人直接生效 | 所有需审核操作由申请人当前直属上级审核；固定创始人免审；非创始人无有效上级阻断 | 本轮反馈第 5 条及本轮确认。 |
| 任务与日志共用标签单选 | 任务多选、日志单选/不选；所有标签由创始人维护；稳定顺序 | 本轮反馈第 2、8 条及本轮确认。 |
| 员工可维护自己的私人标签 | 取消员工新建/维护私人标签；所有标签定义由创始人维护；历史个人颜色覆盖只作本人显示兼容 | 本轮确认“所有标签都是公司创始人创建和编辑”。 |
| 任务表单展示全部当前正常授权任务，保留“仅可见”筛选 | 任务表单仅本人原始创建或当前有效负责的并集，移除“仅可见” | 本轮反馈第 7 条。 |
| 日志页按部门→团队→个人筛选，可看他人日志 | 日志页仅本人；下属日志从 5.7 工作区进入 | 本轮反馈第 13 条。 |
| 日志三天补写 + 同一创建模板编辑 | 统一写日志只列缺失日期；创建/编辑独立界面、草稿和提交目标 | 本轮反馈第 9、10 条。 |
| 月视图小时比例任务条、无拖动；日视图无拖动 | 月视图日级条、按天拖动；日视图小时拖动 | 本轮反馈第 6 条。 |
| 待审在普通任务区显示原有效版，无日程投影 | 任务详情/表单/提醒保持原有效版；日程按提议排期显示一次虚线投影 | 本轮反馈第 17 条。 |
| 通知列表强制显示完整摘要，无组合筛选/计数分页顺序 | 默认紧凑列表，详情看正文；组合筛选先于计数分页；全局未读数不受筛选影响 | 本轮反馈第 1 条。 |
| 基础字段“正常可见即可编辑”未定 | 仍暂缓；保留现有基础编辑权限和仅排期权限 | 本轮反馈第 19 条待确定事项。 |

## 4. 保留的 V4 规则

- 固定四层组织、独立管理员、员工手机号登录、姓名/手机号仅管理员维护、展示职位不授权。
- 公司信息/个人事项上限、任务有效版隔离、唯一待审、截止失效、临期比例提醒、通知撤回/保存期/历史只读、评论平铺与作者管理、统计范围等未被本轮替换的规则继续有效。
- 月/日两模式、月格统一打开当天清单、日视图完整时轴与重叠全量分栏、无独立周视图/整周滑动要求，除非本轮第 6 条已明确改变。
- 系统推送、安卓真机、安全边界和跨端质量要求继续按 V4/后续实现记录单独验收，不因 V5 文档更新自动通过。

## 5. 已确认边界与待确认事项

- 基础字段“正常可见即可编辑”仍为待确定事项，本轮不实施。
- 固定创始人“所有需审核操作免审”本轮已确认采用；若后续改为仅创建免审，必须同时处理创始人无直属上级时的操作规则并更新正文、验收和来源。
- 历史个人颜色覆盖只保留显示兼容，不新增员工私人标签维护入口；如需恢复，另立需求变更。
- “私人标签”历史数据的定义由创始人维护的表述不表示员工可创建新的私人标签。
- 本轮提到的五个 OpenSpec change 名称作为后续规格/实施线索；仓库当前没有对应活动 change，本文不创建、不修改 OpenSpec。
