## 2. 逐条源码依据与差异

### 反馈 1：Excel 式任务表单、筛选、排序和计数

**当前行为**：员工前端的 [HTML 入口](../../潘多拉-交互原型.html) 加载基础原型、API、任务接入、工作区、日程和个人资料脚本；没有任务表格列表及其进入/返回流程。[日程侧面板 `panelHTML`](../../潘多拉-日程视图.js#L135) 仍渲染“我负责 / 我分配 / 仅可见”和“待完成审核 / 已完成 / 逾期未完成”统计；[rangeSummary](../../潘多拉-日程视图.js#L65) 按当前日历月/周/日范围计算。创建任务弹层、PC 管理端员工表格、历史截图中的 `task-form-*.png` 都不能视为本次要求的任务表单列表。

**可复用基础**：

- [前端 `P.reload` 与 `P.mapTask`](../../潘多拉-api.js#L195) 已分页加载当前全部可见任务，映射负责人、创建者、说明、标准、排期、执行状态及待审标记。
- [后端 `TaskService.list`](../../backend/src/main/java/cn/pandora/task/TaskService.java#L49) 支持名称 `q`、执行状态 `state`、负责人 `assigneeId`、创建者 `creatorId`、日期范围、紧急程度与分页；先经权限过滤，且仅查询已有有效版本的任务。
- 同一列表目前按创建时间倒序及 ID 固定排列，没有按列指定升降序的实现；`state` 可查单个状态，但没有独立的“未完成”组合条件；也没有“仅可见”专用关系条件。现有 `taskKind` 采用负责人优先的互斥归类，不等于 V3 “我创建”包含自己负责的任务这一筛选语义。

**待补**：任务表单二级页面、表头/字段/滚动、关系与完成组合筛选、名称搜索、列排序、任务详情跳转与日历返回。把统计移到表单，并保证筛选、排序、计数覆盖完整授权结果集；不能只处理当前页，也不能把全局 `TASKS` 收窄为本人负责而丢掉表单数据。可选择复用前端完整数据做筛选排序，或扩展服务端查询；具体接口不是本轮产品约束。

**PRD 变更**：5.2.7 规定字段、筛选与统计；A-26/A-27 验收。自己创建且负责的任务在“我负责”“我创建”下都能找到，每个结果集只占一行；关系计数可重叠，总数单独去重。此关系语义是本轮明确列出的整合约定。

### 反馈 2：视图只显示自己负责的任务

**当前行为**：[API 接入](../../潘多拉-api.js#L252) 和 [任务接入](../../潘多拉-任务接入.js#L101) 将 `visibleTasks` 覆盖为 `TASKS.slice()`；这些任务来自后端当前授权列表。[基础 `viewTasks`](../../潘多拉-交互原型.js#L1049) 只排除 `rejected`，没有要求本人出现在负责人中。[日程 `dayTasks`](../../潘多拉-日程视图.js#L29)、月历和周历均继续使用这组任务，因此中高层会看见自己创建但不负责、或只是组织授权可见的任务。

**待补**：为日历建立本人负责的数据源，覆盖月/周/日、全天区、跨日条和当天展开清单。本人也是创建者的负责任务正常显示；自己创建给他人但本人不负责的任务不进入日历。负责人变更后按有效版更新归属。

后端 [Access.canSeeTask](../../backend/src/main/java/cn/pandora/auth/Access.java#L73) 的原授权范围供表单、详情、AI 等使用，应保留；只收窄日历展示范围即可。待创建审核仍走独立申请/审核入口，不能因为创建者或拟负责人包含本人就出现在日历。

**PRD 变更**：2.2、5.2、A-13 明确展示边界；这是一项对 V2 的需求变更，而不是旧代码未履行旧 PRD。

### 反馈 3：搜索在表单，视图没有

**当前行为**：[scheduleSearchHTML / scheduleSearch](../../潘多拉-日程视图.js#L92) 在日历中显示搜索输入框及结果，并请求 `/tasks?q=...&limit=20`；[toolbar](../../潘多拉-日程视图.js#L150) 直接插入该搜索区。任务表单列表不存在，搜索尚无新归属。

**待补**：移除日历上的任务搜索输入、结果和相关入口，将按名称搜索放入任务表单，并与关系、完成和日期筛选共同生效。日期选择、回到今天/本周、日志人员搜索及任务编辑中必要的人员/关联任务查找各有用途，不因本条一并移除。

**PRD 变更**：替换 V2 5.2.1、A-13 中的日历搜索要求，修正 5.2.6 的截图借鉴边界，新增 A-27。

### 反馈 4：日志编辑整屏

**当前行为**：[logFormView](../../潘多拉-交互原型.js#L1794) 对写日志和编辑日志统一返回 `fullscreen: true`；[实际工作区覆盖函数](../../潘多拉-工作区接入.js#L291) 保留此属性。[renderSheet](../../潘多拉-交互原型.js#L1426) 切换 `is-fullscreen`，[CSS](../../潘多拉-交互原型.css#L303) 将高度和最大高度设为 100%，正文输入区可伸展。

**结论**：已有占满应用容器的实现，无须再按“底部半屏”列为缺口。PC 原型仍有手机预览容器，不应把容器边界误认为日志没有全屏。后续回归应检查新增与编辑、关联任务选择后返回、保存与关闭均可达；真机及软键盘体验不能仅凭源码判定。

**PRD 变更**：保留 5.3，补充 A-17。

### 反馈 5：通知列表底部移除刷新/关闭

**当前行为**：[实际 `notificationsView`](../../潘多拉-工作区接入.js#L404) 只返回标题和列表正文，没有 `foot`；[renderSheet](../../潘多拉-交互原型.js#L1438) 在无 `foot` 时隐藏底部栏。HTML 的头部 `sheetClose` 仍可关闭；打开通知时会加载最新数据。消息详情的删除、撤回、审核等属于业务操作。

**结论**：已实现要求。后续检查空列表及非空列表均无底部冗余按钮，头部关闭和消息详情操作正常。

**PRD 变更**：保留 5.6.3，补充 A-19，不将本条扩大为移除所有页面的刷新/关闭按钮。

### 反馈 6：手机号仅本人及上级可见

**当前行为**：[Access.canReadPhone](../../backend/src/main/java/cn/pandora/auth/Access.java#L180) 验证同公司、有效账号和更高组织层级，并遍历实际管理链；同级、下属、其他管理链、仅有管理员身份者不能据此得到号码，循环/断链不能获得号码权限。[WorkspaceService.person](../../backend/src/main/java/cn/pandora/workspace/WorkspaceService.java#L57) 先检查资料查看权，再决定是否返回 `phone`。[个人资料前端](../../潘多拉-个人资料.js#L39) 请求鉴权详情，只有响应包含号码字段时才展示；“我的”展示本人号码。管理员员工维护只返回是否已录入号码等摘要，不回显他人手机号。

**结论**：已实现“同级不可见、仅上级可见”的后端边界，并保留本人查看/修改自己的号码。这里的“上级”是实际管理链，不是所有高职级或所有管理者；原有资料查看授权仍是前提。

**PRD 变更**：V2 已覆盖，V3 保留 2.2、5.5、A-04，不重新改成“仅本人可见”。

### 反馈 7：管理员建号，员工使用

**当前行为**：[管理端](../../admin.html#L62) 有“新增员工”，[OrganizationService.createEmployee](../../backend/src/main/java/cn/pandora/admin/OrganizationService.java#L254) 校验 `manage_accounts`、录入组织资料、生成初始密码并标记首次改密。[AuthController](../../backend/src/main/java/cn/pandora/auth/AuthController.java) 只提供会话和密码接口，没有公开自助注册接口；[AuthFilter](../../backend/src/main/java/cn/pandora/auth/AuthFilter.java) 在必须改密期间只允许读取本人会话、改密或退出，不能直接调用业务接口绕过。

**结论**：已有完整对应实现。首次演示种子账号是特殊演示路径，不能以其没有首次改密要求推断管理员新建账号也没有门禁。

**PRD 变更**：沿用 3.1、A-01。员工保留登录、改密和退出；不增加注册入口。

### 反馈 8：PC 管理端

**当前行为**：[admin.html](../../admin.html) 是独立页面，按桌面宽度组织员工、部门、职位、团队、角色、公司信息、转岗/交接、任务历史和通知等管理入口；[Maven 静态资源配置](../../backend/pom.xml) 单独打包。员工 App 维持五个主导航，没有嵌入完整管理员维护界面；管理 API 仍需相应权限。

**结论**：已有独立 PC Web 管理端，不需要另做管理员 App。页面能在窄屏打开不构成违规。PC 管理端完整流程应在电脑浏览器验收。

**现有说明遗留**：[P.reload 的管理员提示](../../潘多拉-api.js#L222) 仍指向旧 `/debug.html`，部分后端说明也保留旧 change 进行中的文字；这不改变 `/admin.html` 已存在的事实。后续实现可统一管理员提示文案，本轮未修改业务脚本。

**PRD 变更**：明确 1.2、3.3 的 PC Web 形态，增加 A-28。
